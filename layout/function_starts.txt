# Function entry points that tools/disasm.py cannot reach on its own.
#
# Columns: region  address  isa        (everything after '#' is a comment)
#
# disasm.py analyses one region at a time and seeds from entry points,
# branch targets, pool words and a prologue sweep that only recognises
# prologues saving lr.  Two kinds of function fall outside all of that:
#
#   - a leaf with no lr-saving prologue whose callers are all in another
#     region, so no branch inside this region ever names it;
#   - the same, reached only through a pointer held in another module.
#
# An address belongs here only when the evidence for it is a real
# instruction somewhere else in the image, named in the comment.  Entries
# are fed through Analyser.add_seed like any other seed, so the trace and
# validate() still have to accept the bytes as code; a wrong address here
# produces no listing change rather than plausible nonsense.
#
# Verify a line by grepping the listing it names, for example:
#   grep -n "0x020084D4" asm/overlays/ov021.s

# Argument-shuffling tail calls that reach func_0201F41C and func_02045A38.
# Both are 16 bytes of "shuffle r0..r2, load the callee from the pool,
# bx r3"; there is no push at all, so the prologue sweep cannot see them,
# and inside arm9_main nothing branches to either.
arm9_main  0x020084D4  thumb   # bl from ov021 at 0x02193BA0 and 0x021CC026, ov135 at 0x021F72DE
arm9_main  0x020084E4  thumb   # bl from ov088 at 0x021BC4AA, ov116 at 0x021D6CA8, ov120 at 0x021D4658

# A leaf that opens "push {r3, r4}": it saves registers but not lr, because
# it calls nothing, so the lr-saving prologue sweep does not fire.
arm9_main  0x0200A6F8  thumb   # bl from ov133 at 0x021B62A2

# The setter half of a getter/setter pair on the same field: "strb r1, [r0, #6];
# bx lr", four bytes, no prologue at all.  Its getter at 0x02014468 has a label
# because a bl inside arm9_main reaches it; nothing inside arm9_main branches to
# the setter, only the pool word at 0x02008948 holds its address, so the
# prologue sweep and the branch trace both miss it.
arm9_main  0x02014464  thumb   # bl from ov010 at 0x0215ED40 and 0x02164404

# An unlabelled leaf holding the second pool reference to the s8[][5] table at
# 0x0209E324; tracing it gives attest() the outside witness that unit_02019B04
# needs (wave 4B integrator note).
arm9_main  0x02019B44  thumb   # pool word referencing 0x0209E324; see src/pending/unit_02019B04.c header

# The clear half of a set/clear pair on the flag byte at +0x38 of the object
# at 0x021469BC: "ldrb r2, [r0, #0x38]; mvn/and; strb; bx lr", no prologue at
# all.  Nothing inside arm9_main branches to it; the only reference is the
# pool word at 0x02034FD0, loaded by "ldr ip, [pc, #4]" at 0x02034FC4 and
# jumped to by the "bx ip" at 0x02034FC8 in the argument-binding tail call
# that starts at 0x02034FB8.
arm9_main  0x02034FA0  arm     # ldr ip,[pc,#4] / bx ip at 0x02034FC4-0x02034FC8 via pool word 0x02034FD0

# A 16-byte leaf right after func_0201C4E4's own literal pool: "if (p->unk10
# == 0) return 1; return 0;" on the printsys.c ring object.  Nothing inside
# func_0201C4E4 branches to it (it falls through into the pool instead), so
# the prologue sweep and the branch trace both miss it; dozens of overlays
# call it directly, e.g. the bl at ov010 0x0216A0B4 and ov019 0x0217F7AE.
arm9_main  0x0201C6B4  thumb   # bl from ov010 at 0x0216A0B4, ov019 at 0x0217F7AE, and many more overlays

# An unlabelled leaf right after func_0201DA24's own literal pool: one of the
# four gf_font.c format initialisers func_0201DA00 dispatches to.  No branch
# inside func_0201DA24 reaches it and it saves no registers, so the prologue
# sweep never fires; the only witness is the format dispatch table itself,
# g_0209E73C[0] at 0x0209E73C, whose word is 0x0201DAA5 (thumb bit set).
arm9_main  0x0201DAA4  thumb   # dispatch table word 0x0209E73C ("0x0201DAA5") loaded by func_0201DA00

# A 208-byte Thumb function between two already-known labels (func_0201DC80's
# tail in unit_0201DC6C.c and func_0201DD58 in unit_0201DD58.c): the streamed-
# glyph lookup gf_font.c installs as the +0x6C hook.  It saves r4-r7 but not
# lr (it calls nothing), so the lr-saving prologue sweep does not see it; the
# only reference is the pool word at 0x0201D9C0, inside func_0201D854, which
# holds 0x0201DC89 (thumb bit set) and is stored to the object's +0x6C field.
arm9_main  0x0201DC88  thumb   # pool word 0x0201D9C0 ("0x0201DC89") inside func_0201D854, stored to +0x6C

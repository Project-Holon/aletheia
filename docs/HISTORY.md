Wave 8 added the ten naming continuations (ov210-215, ov181-199, ov203-207, ov216-222, ov223-231, ov111-118, ov115-121, ov127-134, ov132-198, ov175-195), the arm9 graphics, logic and wifi clusters, ov009 named from the SDK symbol table, and the ov137/170/172/186/119/209/217 continuations; then it split 61 aggregated files into their originals: the ov203/ov204/ov212/ov215/ov127/ov115/ov121/ov118/ov132/ov195 overlays and the arm9 bmp, menu, oam, font, g3d, tcbl, mcss, mystery_data, touchpanel, msl_c_lib (ten-way), nns_fnd_unitheap and bsubway_savedata pieces, plus the double3Ddisp and billboard merge.

Wave 9 shaped 24 lanes around removing the `Obj` view pattern: 5,052 view references across the overlays were folded into real structs and 12 regions reached zero views (7,345 `Obj` references remain across 109 files, down from 12,397 across 164), with new owner headers for ov211, ov215, ov204, ov198, ov173, ov210, ov133, ov128 and ov121, and three recurring compiler facts recorded in `docs/COMPILER_NOTES.md`; then it split the last two aggregated originals, ov133 into dup_fitting.c and dup_fitting_item.c and arm9 misc_savedata.c into misc_savedata.c, battle_examination.c and misc_savedata_2.c.

Wave 10 shaped 22 lanes around finishing the `Obj` removal: the two opaque PROSYS spellings `struct Obj0203159C` and `struct S020315D4` resolved to `struct Proc` across 886 references in 325 files, four standing per-file `*_shared_types.h` folded into their owner headers, and the five compiler-note corrections applied, so 3,874 `Obj` references remain across 37 files and 15 regions reached zero views; `docs/COMPILER_NOTES.md` now carries the refinements.

Three gap-fix lanes followed wave 10: arm9 `ui_p02.c` was folded into one whole `ui.c` (54 functions), the ov194 `namein_graphic` range was split into five originals at their real boundaries (`namein_graphic_main.c`, `namein_graphic_field.c`, `namein_graphic.c`, `namein_data.c`, `nsbtx_to_clwk.c`), the per-function verify path was generalised to a non-contiguous C piece (`contiguous: no`), and the H1 hand-written marker was applied to the 33 `cw_runtime` asm bodies (a comment-only change, awaiting owner confirmation); game code is now fully linked at 100.00 percent. 36,202 functions carry names (13 still have address names; the earlier counts were undercounts, the counter missed single-line definitions); 0 unit_ files, 0 unplaced dirs and 0 placeholder files remain. The svc stubs of ARM9 are split into their own files. The unit file names of ARM9, ov009 and ov016 were replaced by the original or SDK object names (848 files). The other overlays carry address names except where a function was named from the SDK or from a lane table. Every file stays byte-exact (`tools/gameverify.py`). `src/matched` is the raw evidence store: it holds one function per file, with per-function views by construction, so it is NOT in scope for "cleaned" and its `Obj` views are expected.

Wave 11 integrated the lane rename maps tree-wide (365 address names down to 36), folded the last shared `Obj` views and the hoisted headers, and recorded the INV-C pointer-word search shape.

Wave 12 ran the misplacement pass, the stand-in second tier and an independent verification: it removed the last address-named stand-in types (2 leftovers only), applied the ov009 SDK names, merged the ov118 non-contiguous pieces and the `wifilist` halves, and proved `layout/file_anchors.txt` was incomplete (1022 anchors; rebuilt to 1056). The remaining restructuring is a split campaign, not a move list: 76 functions across 36 files carry a `__FILE__` anchor that names a different file than the one they sit in, and 88 of the consolidated cases need a new file (`S/INT13/split_list.tsv`).

Wave 13 ran that campaign: 17 split lanes created 56 new originals and re-cut the over-merged files, so `src/game` now holds 1,267 `.c` files, all byte-exact, with unnamed down to 13 of 36,222.

The integration (INT14) then found the corrected rename status: every prior rename check looked only at DEFINITIONS, so it reported renaming done while the tree still held `func_NNNN` names used as REFERENCES. Re-measured over `src/game`, 1,544 distinct `func_`/`sub_` names are used, 1,033 of them stale (a real name exists at that address; the raw address-only count of 1,096 includes 63 cross-region false positives), 412 unknown and 36 genuine, across 21,441 occurrences. Renaming is therefore NOT done: 13 unnamed definitions PLUS 1,096 stale references (1,033 region-corrected). The wave 14 worklist is `S/INT14/wave14.tsv` and the corrected status is in `docs/NAMING.md`.

Wave 14 finished the renaming: `src/game` holds no `func_`/`sub_` address name in code, header rows, comments or notes, and every file stays byte-exact. Name clashes were fixed by correcting the wrong prototype (the SDK or GameSpy signature), not by adding second names; one documented second extern stays (`MIi_CpuClearFastAlias` in `ov013/vct_main.c`, where the original has two calls to one address). Three matched entries that were not functions were removed. Overlays ov074 (a name cut-in table getter for the ov021 field 3D cut-in) and ov109 (a screen that nothing loads) held about 1 KB of code the disassembler classed as data; both are matched, seeded in `layout/function_starts.txt` and link. Every SDK asm body was checked against the SDK objects' own line tables (one row per instruction for asm): 20 asm stand-ins became C and match, `DWCi_ScreenDC_FlushRange` is `DC_FlushRange`, and every genuine asm body carries the "hand-written in the original" marker, so the strict figure is 100.00%. Two evidence files that had stopped compiling (an ov013 second extern name lost in a rename, an ov132 struct defined twice) were repaired.

Wave 15 named the fields, parameters and locals: 26 lanes, one per region or region group, gave real names to 3,087 of the 3,299 placeholders (`fXX`, `unkXX`, `aN`, `vN`, `tmpN`), counted by the new `tools/placeholdernames.py`; the 212 left are fields that nothing reads or writes, documented per lane. `tools/protonames.py` copied the definitions' parameter names into 1,767 prototypes. Function names that contradicted their bodies were fixed: the game-clear sequence (`EVENT_GAMECLEAR_*`, was `SCRCMD_NETWORK_*CommBattle*`), the X-button field menu (`EVENT_FIELD_MENU_*`), the box functions (`BOX2_MAIN_DepositPartyMon`, `BOX2_MAIN_SwapBoxAndPartyMon`, `BOX2_MAIN_ResetShayminFormInBox`, `BOX2_MAIN_SyncItemForm`, `BOX2_SEQ_StateReleaseMon` and others), the swapped bag pair `BTL_MAIN_RemoveItemFromBag`/`BTL_MAIN_AddItemToBag`, `POKE_TOOL_LearnLevelUpMove`, `POKELIST_TryLearnMove`, and 28 offset-named getters (`ICA_ANIME_GetField1C` is `GAMESYSTEM_GetGameData`, `GAME_DATA_GetField160` is `GAME_DATA_GetStartLocation`, and so on). Data mode now covers every region (lanes D1 and D2).

Wave 16 audited meaning and borders: 13 read-only lanes checked function names against their bodies and 580 wrong names were corrected (for example the GF_STANDARD CRC-16, RTC and crossed sine/cosine helpers, the money and badge functions of the misc save, the BG priority and scroll functions, the camera script commands that were named FieldRegion, the box and trade screens), plus 17 struct fields; 13 externs that named another overlay's function at a shared address were fixed (`tools/xovcheck.py`); seven boundary lanes split the merged files (`docs/restructure/BOUNDARY.md`); the explicit `_s32_div_f`/`_u32_div_f` calls became `/` and `%` (2 left, `docs/DEBT.tsv`); `tools/romlink.py` builds the whole ROM byte-identical from src/game; and overlay 230's decrypted code was found uncounted and is now part of the figures (22 of 28 functions matched).

Wave 17 finished overlay 230: it is built with the 2.0/sp2 compiler, its second encryption layer (18 sealed anti-tamper checks) is opened, matched and sealed again from the linked C, and its last four functions closed with static inline helpers and `long` offsets (`docs/idioms`); a second meaning pass corrected 376 more names (among them the `MyStatus` fields, the misc save's Pokémon record and the battle subway save blocks), the second layout of the player status block was removed, and the full `match.py` self-test runs clean again (383 cases).


Wave 20 gave `src/game` real types and per-file headers. Phase 0 added the shared type headers (`types.h`, `sdk_*.h`); phase 1 did ARM9, put Pokémon White on the same source (`src/game/version.h`, both retail ROMs rebuild identical) and gave every function an address (`layout/function_addrs.tsv`). Phase 2 did the overlays: duplicate types went from thousands to 4, mismatched declarations from about 10,000 to 520 (`tools/protocheck.py` reads the host branch of guards), about 1,100 calls through cast function pointers were rewritten as plain calls, the battle server flow uses real battle types, and every file compiles for a host build with no failure (`tools/hostcheck.py`). Bugs kept from the original (missing returns, width mismatches, void reads, wrong argument counts) keep the DS form under `__MWERKS__` and get a host form that does what the DS does; they are listed in `docs/ORIGINAL_BUGS.md` and `docs/ORIGINAL_BUGS.tsv`, and gameplay bugs keep their fix under `BUGFIX`. Variadic functions use one header (`src/game/sdk_stdarg.h`), and the DSi data is generated C.

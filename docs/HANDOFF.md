- **TWL region and modcrypt.** The `twl` region is decrypted with a user-supplied 16-byte scrambler
  constant read from a key file kept outside the repo, located through `ALETHEIA_DSI_KEY` (or
  `--dsi-key`); no key or key-bearing dump is ever committed, and without it the region is skipped.
- **sole-ref/code extended to twl** (`dc6d427`), which let func_0206DC00 attest EXACT against the two
  TWL-only PC24 targets traced in that region.
- **Overlay 230's own decryptor, region `ov230d`** (wave 21 lane T): `tools/ovcrypt.py` replays ov230's
  static-initialiser decryptor (hash-checked, every range a clean ARM function) into the derived view
  `extract/ov230d.bin` (`python tools/ovcrypt.py write`, also run by delink.py), `python tools/disasm.py
  ov230d` lists it as `asm/ov230d/ov230d.s`, and match.py's `ov230d` symbols token attests a decrypted range
  start there (sole-ref/code without an outside branch); ROM listing labels on ciphertext are refused. The
  ROM build never reads the view. func_02011D9C (ica_anime) is EXACT with it (docs/NOTES.md).
- **`match.py` reads only manifest-listed listings**, so a stale or regenerated listing file that no
  manifest entry names cannot silently feed a compare.
- **The status gate**: a file header's `status:` line is never evidence; only a shard written by
  `match.py manifest --verify --shard` (or a fresh `match.py one` run) counts.
- **The overlay hint rule**: a small pooled absolute is refused as an overlay-number attestation unless
  a listed rule accepts it; arbitrary small constants do not pass as overlay hints.
- **`disasm.py` honours declared data objects**, so a listing no longer mis-prints a literal pool as
  Thumb instructions when a data object covers it.
- **The permuter relocation and size guard** (`196edb5`): the ranking no longer credits a variant whose
  compile dropped relocations or was truncated, which had been inflating some residue scores.
- **The data-object map regenerated** (seed round 11, `ff90363`): 32 stale rows dropped, all of them
  reclassified as code.

### 2. The wave loop as run on Windows

The loop is the one in the waves 10 to 13 section, with these differences.

1. **Lanes.** Up to 9 or 10 Opus lanes per wave, launched together in the background. Each lane takes
   families or clusters, reads AGENT-BRIEF and the family headers, files EXACT in src/matched, MATCH in
   src/pending, DIFF as an appended note section, verifies its own shards twice, writes its report and
   hands back one line. Lanes report and never commit, never touch layout/ or tools/, never spawn
   subagents.
2. **Fold-in.** `python tools/session/wave.py foldin` (replaces `foldin.sh`): worklist refresh, pending
   re-verify (`promote_fast.py --dry`), pending figure, split build and pack, ROM build with the sha1 line,
   coverage maps, then an INCLUDE list (untracked src/matched files whose shard exists) and a HOLD list
   (filed, not yet sharded).
3. **Commit.** `python tools/session/wave.py commit "<label>" <prev exact> <prev repro>` (replaces
   `commitset.sh`): README figure, stage README, shards, docs, pending and only the sharded sources,
   commit with both figures and deltas, push. Since `b7e5af9` it also stages docs/MATCHING.md (the
   regenerated idiom index).
4. **Sweep as soon as the shard exists.** A lane's sources enter the next fold-in commit once their shard
   is on disk, not when the lane reports; a wave therefore lands as four to six "set" commits.
5. **Notes per lane.** Each lane's appended notes, headers, idioms and report go in their own "lane
   notes" commit (`4c7ab9e`, `c6bdcee`, `c10f5fa`, `335a4f9`), staged by explicit file list.
6. **Seed rounds** between waves as before; since `63bdf82` they may seed overlay starts (ov010
   0x02167394, the ov014 callees), which the overlay classes then use as witnesses.
7. The whole loop runs natively on Windows (Git Bash and PowerShell; `tools/env.py` runs mwccarm.exe
   directly, wine only elsewhere).

### 5. Tool and process changes

- **`tools/env.py`** (`b566e19`): one place for repo root, interpreter, ARM binutils (`--toolchain`,
  `BW_ARM_TOOLCHAIN`, tools/gcc-arm, PATH), the mwccarm runner (the .exe on Windows, wine64 or wine
  elsewhere), the host toolchain for the port, and the scratch directory (`ALETHEIA_SCRATCH`, else
  `<tempdir>/aletheia`). build.py, match.py, cw.py, cppscan.py, permuter.py and tools/session import it.
  **`tools/selfcheck.py`** prints what env.py resolved, compiles one tracked EXACT function through
  match.py and runs one split build with it spliced in; exit 0 when all pass. Run it first on a new
  machine.
- **`tools/session/wave.py`** (`6f5aa4c`) replaces `foldin.sh` and `commitset.sh` (section 2). On a fresh
  checkout run `python tools/disasm.py arm9 --split` and `python tools/disasm.py overlay --all` once before
  any session helper works (the listings are gitignored; tools/session/README.md).
- **`tools/datascan.py`** (`84b29a4`, report `layout/datascan_report.txt`) re-tests every non-code byte of
  arm9_main (pool-owned, string and pointer-table runs excluded; 125600 bytes scanned) for a prologue and
  a clean decode to a return. 81 candidates: 78 strong (1370 B, pool-witnessed Thumb leaves without a
  push, the class seed rounds already add) and 3 weak (192 B); no pushed function hides in data. Verdict:
  at most about 0.4 percent of game code is undiscovered, so the denominator is close to the ground truth.
- **Overlay evidence classes in match.py** (`63bdf82`). The overlay is chosen by an `ovNNN` token on the
  `symbols:` line, else the overlay the function under test lives in, else the single overlapping overlay
  that qualifies (two qualifying candidates are refused). sole-ref/data per overlay (a pool word landing on
  an object start in that overlay's listing); overlay sole-ref/self (the ROM word read from the compared
  region); sole-ref/code for overlay `func_` labels with the declared ISA; matched-overlay attestation (an
  EXACT overlay entry attests only for its own overlay). Selftest 157/157, no existing verdict changed.
- **Selftest fixture change.** After ov010's listing was regenerated, `OV_DATA_POOLED + 4` gained a pool
  referrer (a pooled address is an object start), so the "address between starts is refused" case now uses
  `OV_DATA_INTERIOR` (0x0216FEE8, a data word with no start and no referrer).
- **Token parser limit.** Before `63bdf82`, `declared_symbols()` accepted one extra token, so a `symbols:`
  line could name the overlay or the alignment but not both; it now takes both in either order
  (`d_021BD574  0x021BD574  data  ov088  a4`).
- **The `git add -u` incident.** The portability lane's edits to build.py, match.py, cw.py, cppscan.py,
  permuter.py and tools/session were swept into the wave 14 second and third set commits by an unscoped
  `git add -u` before env.py existed in the tree, so HEAD did not import until `b566e19` added it. Rule
  since: while agents are writing, stage explicit per-lane file lists, never whole directories or `-u`;
  wave.py stages only the wave's own paths.

## Session of 2026-09-22 to 2026-09-23: waves 10 to 13, and the project explained

### 0. What this project is, in one page

- **Goal.** Reproduce the ARM9 static binary of Pokémon Black byte for byte from C, compiled with the
  same Metrowerks compiler Game Freak used (mwccarm, `tools/mwccarm/`, dsi/1.1p1 at `-O4,p` for almost
  everything, a few files pinned to `../2.0/sp2` or `sp2p2` with evidence rows in `docs/FRONTEND-PINS.md`).
  The repo holds only C, layout tables and tools; never game bytes. The owner's own ROM dump stays outside.
- **The unit of truth is a shard.** `tools/match.py one --src F --func NAME --addr A --arm|--thumb`
  compiles one function and compares it with the image: EXACT (identical), EXACT* (identical, the listing
  extent ends in an unlabelled follower or alignment pad), MATCH (every concrete byte right but one
  relocation site has no witness), DIFF, SIZE, CCERR. `match.py manifest --verify --shard pkt_X`
  recompiles every file claiming packet X and writes `layout/matched/arm9/pkt_X.json`. Only those shards
  count. A `status:` line in a file header is a claim, never evidence.
- **Two figures.** Exact coverage = shard bytes over the denominator; reproduced coverage adds the
  src/pending files whose FRESH verdict is MATCH (`tools/session/promote_fast.py --dry` then
  `tools/session/pending_pct.py`). The denominator is all ARM9 static code minus SDK symbols (`layout/symbols_sdk.txt`,
  from `tools/libmatch.py`, plus interior labels inside sized symbols) and the MSL runtime
  (`layout/runtime_arm9.txt`). `python3 tools/worklist.py --summary` prints it.
- **Every source-changing commit** rebuilds the ROM from the split units (`build.py --split --pack`,
  `ndsrom.py build`) and checks sha1 `26ad0b9967aa279c4a266ee69f52b9b2332399a5`, regenerates the two
  treemaps (`tools/coveragemap.py`), updates the README figure, and carries both coverage figures with
  deltas in its message. No attribution trailers, ever.
- **Evidence classes for relocation sites** (docs/MATCHING.md, AGENT-BRIEF section 5): local, matched
  (an EXACT entry covers the target), label, literal, string, veneer, runtime, data_table, sdk (a call at
  an SDK symbol), sole-ref (data, code, string, self). A MATCH file is parked in src/pending with its
  blocking class named; it turns EXACT without any C change when the witness appears (a sibling
  matched, a start seeded, a unit member listed).
- **Layout.** `layout/function_starts.txt` seeds function starts the disassembler cannot reach (leaves
  and followers with no `bl`), `tools/disasm.py arm9 --split` regenerates listings and units, and
  `worklist.py --refresh` re-cuts packets. Adding a start grows the denominator; that is bookkeeping,
  not matching, and the commit message says so.

### 2. The workflow that produced it (the wave loop)

1. **Pick targets.** `python3 tools/session/remaining.py` lists the upper-half pseudo-family clusters
   (`pseudo_families.json`, adjacency plus shared callees) with their open functions, sizes, ISA and
   state (N = a note with a best source exists, U = untouched, P = pending). `python3 tools/session/families.py`
   does the same for the anchored families (original source files from `__FILE__` strings,
   `layout/file_anchors.txt`). Rank by open bytes; take clusters and families whose header
   `docs/families/<name>.h` or `cluster_<start>.h` exists (a lane writes it first when missing).
2. **Launch one wave of at most 8 Opus lanes, in the background, all at once** (owner rules: max 8 per
   wave; never add lanes while a wave runs; the next wave starts only when every lane has reported).
   Each lane gets 2 to 5 families or clusters, smallest residue first, and the standard brief: read
   AGENT-BRIEF, the permuter section of docs/notes/permuter.md, the headers; check
   `grep -l "address:  0x<ADDR>" src/matched/*.c` before writing anything; take the freshest note; run
   the permuter (`--explain`, then `hill 800`, then `anneal 2000`, `--types`, `--jobs 6`) before any
   hand spelling sweep; try both compilers; check data flow and callers before accepting a result; file
   EXACT in src/matched, MATCH in src/pending, DIFF as an appended note section with a best-source
   marker; never edit layout/, tools/, asm/; never spawn subagents; end with the shard verify; write the
   report to scratchpad `reports/` and hand back one line.
3. **Fold in each lane as it reports.** `tools/session/foldin.sh` (worklist refresh, pending re-verify,
   pending figure, split build, ROM build and sha1, treemaps, and a list of untracked src/matched files
   split into sharded and unsharded), then `tools/session/commitset.sh "<label>" <prev exact> <prev repro>`
   (README figure, stage only sharded sources plus shards, docs and pending, commit with both figures
   and deltas, push). Files another lane has filed but not yet sharded are held out of the commit; they
   go in when their shard exists. Header-only reports get a "no coverage change" commit.
4. **Between waves: a seed round.** Every report ends with an "Integrator: seed" heading naming
   unlabelled leaves and followers it filed as witnesses. Seed only addresses that have a matched source
   (the row's comment names it), append to `layout/function_starts.txt`, run `disasm.py arm9 --split`,
   `build.py --split --only arm9`, re-verify the shards of the affected packets, fold in, commit. When a
   unit file covers several starts, list them all on its `function:` header line. Never run this while
   lanes are running: it rewrites the listings they read.
5. **Whole-image check** `python3 tools/build.py --arm9-image -j 1` in the background (25 minutes). With
   `-j 4` or more the first translation unit "times out" even at 900 s while compiling alone in under a
   second: a parallel wine start-up artefact, not a source problem. The split build plus the byte-identical
   ROM is the stronger check anyway.
6. **Interruptions.** Usage limits and stream stalls kill lanes; resume each with a message ("continue
   where you stopped, check src/matched first, foreground only, no subagents"). They pick up from the
   tree. Load average above 30 on the M4 Pro (10 lanes plus a build) causes watchdog stalls; 8 lanes is
   the practical ceiling.

### 3. What works, ranked by yield, and what does not

Works:
- **Identify the library, then write its shape.** Most of the unanchored upper half is NitroSystem
  (g2d fonts, char canvas, cell/multicell animation, OAM manager, renderer, software sprites; g3d
  resource dictionaries and texture/palette binding) and MSL (printf's `parse_format` and `__pformatter`,
  qsort, rand, `__dec2num`). Written in the library's shape (helpers as the inlines they are, the library's
  scopes and unions, the real TwlSDK inlines) these close in a few compiles where three waves of register
  permutation had failed. The owner allows cross-referencing the public NitroSystem decompilation
  (github.com/ntrtwl/NitroSystem, rev 21c8fd0, NitroSystem-071126) for SDK library shapes; Black's build
  differs in places (NNSG2dNode is 0x28 bytes, a negate-first rotate adjust), so verify every struct
  size against the image. Never copy from other Pokémon decompilation projects.
- **Declaration facts.** A callee's real argument list (registers that look like leftovers are loaded
  values or struct fields), real prototype widths (s16, u16, a u8 stack parameter read with ldrb), a
  three-argument callee whose prologue saves r2, struct by value versus scalars, bitfields for shift pairs,
  a u64 id. A residue the permuter cannot move at all is in the declarations or in the reading of the
  image, never in the body.
- **Reading fixes.** A constant pool word mistaken for a global, a callee address off by one pool word,
  main versus sub engine register base, a home-push entry four bytes before the label, the dense-switch
  table base, a listing extent that swallows an unlabelled follower (the permuter then chases the wrong
  size).
- **Shape levers,** each of which closed several functions: inline helpers written else-first with early
  returns; a wrapping `if` instead of an early return; a named local for a call result (`cmp` operand order
  names the temporary); loop-role ints declared without initialisers and assigned in image order;
  split-assign `p = base; p = p + i*stride;`; a call written in both arms of a test instead of hoisted;
  plain `x = x == 0` instead of hand-hoisted constants; reusing a loop variable across phases
  (docs/idioms); a `u16` local shared by three loops; `(unsigned)c < 0x80` for isdigit.
- **Second and third lanes on the large functions** of a cluster whose header exists (the wave-8
  strategy) and **whole-family lanes** of 2 to 5 small families per lane once the big clusters are done.
- **Compiler pins** by tell: kept branches, rematerialised `add rN, sp, #0`, zero-seeded `mla`, a
  register-held sentinel, push/pop one register wider than the image. Try 1.1p1, ../2.0/sp2 and sp2p2
  on every residue; several "impossible" 1.1p1 residues were correct C under 2.0.
- **Unit files** for runs of unlabelled accessors (unit_02020268: eight setters in one compared range),
  and the `function:` member line so the `matched` class attests each member.

Does not work, or is exhausted:
- **Random pre-screened waves** (waves 1 to 27 of the previous run) and **autonomous permuter closure**
  (benchmark 0 of 17): the permuter's value is `--explain` plus the type, return-value and declaration
  levers, and a flat result as a diagnosis.
- **Allocator ties of 2 to 14 bytes** where every instruction is right and the image keeps a value alive
  past its last use, or rotates r0/r1/r2, or picks the other `mla`/`smull` destination: pkt_0206EB00's three
  (14, 2, 8 bytes, unchanged under every compiler and 5000 permuter compiles), the clact.c set, strcpy
  keep-alive 0x02094798. Documented in their headers; skip them.
- **Evidence walls no C can cross:** an unlabelled overlay callee (symbol_save GROUP A, sub_0200F734
  blocked on ov009 0x02156460), literal pools that disasm.py prints as Thumb instructions so the pool-word
  index misses them (0x02010B84..97, 0x02010D84..97), and the three-row function 0x02014D2C..0x020155A0 in

- **Hand spelling sweeps before the permuter and before the declarations are checked.** Every lane that

### 4. What the lanes learned (all recorded in notes, `docs/families/*.h`, idioms, FRONTEND-PINS.md)

- A residue the permuter cannot move at all is in the declarations or in the reading of the image, not in
  the body: eight scalar stack parameters vs one struct by value; a callee's u16 parameter only observable
  from the caller; backwards argument order; a u32 that is really a u8 even when loaded with `ldr` from the
  stack; the dense-switch table base (the word after `addls pc,pc,rN,lsl #2` is the default fallthrough, not
  table[0]); an inferred extent swallowing already-matched leaf accessors; the mode==0 arm reached two ways
  (an explicit goto chain in source order).
- A truncation at the CALL constrains the callee's width, at the ASSIGNMENT the local's. `cmp` operand order
  names the temporary (closed the last 2 bytes four times). Shift pairs with no matching type are bitfields.
  `volatile` on one destination field defeats an unwanted stmib merge. `register` is a no-op.
- What remains unreachable from C: allocator ties where the image keeps a value alive past its last use
  (strcpy keep-alive 0x02094798), r0/r1/r2 value-numbering rotations, mla/smull destination registers
  (pkt_02063000 cluster, 0x02072374). Evidence caps: unlabelled overlay callees (mystery_data, symbol_save
  pending files), lone `bl` targets without prologue labels.
- Family headers (`docs/families/<file>.h`, `cluster_<start>.h`) are reference documents derived from matched
  siblings; they pay where siblings disagree on a prototype or field type and where a family is a 2.0 unit.

### Tooling built (all in the session scratch area, patterns documented here)
- **Call lifter**: parses `bl func_XXXX`/`sub_XXXX` targets and passes only
  the argument registers up to the last one that differs from the incoming
  parameter, so zero-argument forwarders compile without extra moves.
- **Branch lifter** (`branchlift`): one forward conditional branch per
  function is split into then/else plus an optional shared join, with each
  side lifted recursively, so nested `if`s and guard chains are covered.
  The condition is rebuilt from the tracked expressions of the preceding
  `cmp`/`teq`/`tst`.  `r0` is threaded out of blocks so a then-arm that
  falls through to a shared epilogue still returns the merged value.
- **Batch variant tester**: compile-and-compare a list of hand-written C
  spellings for one function, keep the EXACT one.

### Findings worth keeping
- `lsr` needs an `(unsigned int)` cast on its left operand or mwcc emits
  `asrs`.
- mwcc rejects declarations after statements; call temps must be declared
  up front (`int t0, t1;` before the statements).
- When a store then a load on adjacent fields is scheduled in the wrong
  order, marking the two accesses `volatile` pins the order and often turns
  a 6-byte DIFF into EXACT (`func_02061B74`).
- The verdict regex `^(...)\b` silently rejects `EXACT*`; use
  `(?:\s|$)`.
- Slice a function by its exact worklist code size; a 64-byte margin pulls
  in neighbours and fabricates branches.

Semantics (confident, and the whole decision tree reproduces):

The base offset 0x320 is materialised once as `movs r2,#0x32` / `lsls
r2,r2,#4`, and every field in the function is then addressed as
(0x320 - k) with a REGISTER offset, never an immediate.  That is what
fixes the field map:

    0x320  per-frame tick
    0x31c  the tick's limit          (0x320 - 4)
    0x318  current frame index       (0x320 - 8)
    0x314  last frame index          (0x320 - 0xc)
    0x330  payload word              (0x320 + 0x10)
    0x328  second payload word       (0x320 + 8)

Advance the tick; while it is below its limit return 0.  On reaching the
limit reset the tick to 0 and step the frame index by one.  If the stepped
index is still within the last-frame bound, store it back, call
func_02023AB0() with no arguments and func_02022EF4(self), and return 0.
Once the index passes the bound, call
func_02022F24(self[0x330], self, self[0x328]) and return 1.

Things that were established as correct along the way and should NOT be

The five varargs-shaped SDk wrappers -- 0x02084F44, 0x0208CF38, 0x0208D7E4,
0x0208D810 (packets pkt_02084F44, pkt_0208CF38, pkt_0208D7E4) and 0x02094534
(pkt_020944CC) -- share one shape that no C spelling reached:

  push {r3, lr} / add r2, sp, #0xc / bic r2, r2, #3 / ldr r1, [sp, #0xc] /
  add r2, r2, #4 / bl <internal callee> / pop {r3, lr} / add sp, sp, #0x10 /
  bx lr

i.e. the va_list is built into r2 from the incoming stack arguments, the
first stack word is passed by value in r1, and the function then discards four
words of its caller's stack arguments before returning (callee cleanup).  That
is an ABI-level convention rather than a body: a seven-named-parameter
forwarder with `&a6` compiles to a 20-byte frameless tail call and a
three-argument forwarder to 20 bytes of moves, against the original's 36.
They call into the 0x0208Dxxx/0x02084Fxx formatting core (0x02084F68 is
itself a 24-byte shuffle into `__dtoa`-style entry 0x02084FA8), so these are
library runtime, reported rather than forced.  Sites: 0x02084F44, 0x0208CF38,
0x0208D7E4, 0x0208D810, 0x02094534.

Every C spelling tried keeps r2 live and emits `addeq r0, r2, r5`, losing the
`ldreq`. Tried and rejected, all 108 bytes and otherwise byte-identical:

  1. u32 offset = msg->archive->bankOffset[msg->bankIndex];
     msg->bank = (u8 *)msg->archive + offset;
  2. the same with (void *)((u32)msg->archive + offset)
  3. a separate local u8 *p = (u8 *)msg->archive; msg->bank = p + offset;
  4. an anonymous union { struct MsgArchive *archive; u8 *base; } at offset 0,
     using ->archive for the table and ->base for the byte add (MWCC CSEs the
     two union members' loads anyway)
  5. writing the offset expression out twice, once per branch, hoping for
     partial redundancy elimination: that instead loses the hoist entirely and
     compiles to 128 bytes.

What would defeat the CSE is an intervening store the compiler cannot prove
does not alias the archive pointer, or a const/volatile qualification on the
member; neither fits the surrounding code. Left undocumented in src/ rather
than parked in src/pending/, since the file is not byte-correct.

Confirmed semantics (used by the asset lane, see src/matched/func_02045E3C.c):
the archive header holds one u32 bank offset per language at +0x0C, and a
file-backed MsgData seeks there, reads the leading u32 byte size, seeks back
and reads the whole bank. That leading u32 is why every string descriptor
offset inside a bank is bank-relative, not sub-file-relative.

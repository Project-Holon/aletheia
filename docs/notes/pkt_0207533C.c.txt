pkt_0207533C - two closures and the register-allocation residue
===============================================================

Packet: 0x0207533C..0x02075794 (0x0207533C 196, 0x02075404 192, 0x020754C4 156,
0x02075560 72, 0x020755A8 112, 0x02075618 128, 0x02075698 252).

Filed EXACT (shard layout/matched/arm9/pkt_0207533C.json):
  0x02075560  72  src/matched/func_02075560.c
  0x020755A8 112  src/matched/func_020755A8.c

Both are the same family: look an object up (func_02074324), bail out with 0 if
the lookup fails, then hand the object's three header fields to func_02075698.
0x02075560 is the two-argument form and passes `*(u8*)(p+9)`, `*(u16*)(p+4)`,
`*(u8*)(p+8)` straight through; 0x020755A8 is the six-argument form where the
2nd/3rd/4th parameters are *defaulted* from those same fields when they arrive
negative:

    if (d < 0) d = *(u8 *)(p + 8);
    if (c < 0) c = *(u16 *)(p + 4);
    if (b < 0) b = *(u8 *)(p + 9);

The parameter must be `int` for the compare to be `cmp r4, #0` / `ldrblt`
signed, which is what the image has.  Both close on the first try with only the
`symbols:` block and the right pointer types.

Near misses, all body-complete and all stopped by register allocation rather
than by a wrong shape:

  0x020754C4 156  compiled 152, 79 bytes differ.  The image holds the outer
        index in r6, the object pointer in r7, the inner index in r8, the
        parameter in r4 and a pooled zero in r5 (`mov r5, r6` once, then
        `mov r8, r5` per iteration); this front end instead puts the parameter

  0x02074E10 140 (pkt_02074CD0)  compiled 132.  One real lever found here and
        worth keeping: the header word is read as two fields of one 24-bit /
        1-bit bitfield pair, not as a mask.

            struct Hdr { unsigned v : 24; unsigned flag : 1; unsigned rest : 7; };
            if (p->flag) r = func_020750EC(p->v, c, d);
            else         r = func_02075080(p->v, c, d);

        Written `(v << 8) >> 8` this front end folds the truncation into
        `bic r0, r3, #0xff000000`; the image's `lsl r0,r0,#8 ... lsr r0,r0,#8`
        pair straddling the branch only appears for the bitfield read, which is
        the same rule as docs/idioms/shift-pair-with-no-matching-type-is-a-bitfield.md
        seen through a 24-bit field.  The `(v >> 24) & 1` test stays a `lsr` +
        `tst #1`, so the flag is a separate one-bit field rather than a shadow
        of the same read.

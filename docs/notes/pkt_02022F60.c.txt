What the function is
--------------------
A per-frame tick of a scaled-vector object.  `p->f40` counts up to `p->f3c`;
on reaching it, the counter resets and either the raw vectors (`f20/f24/f28`
plus `f2c` on the stack) or the 1/128-scaled ones (`f00/f04/f08` plus `f0c`)
are handed to func_02023D60 along with `f48`, `f34`, `f30`.  The scaled path
first ticks the sub-object at +0x10 through func_0202291C (already matched)
while `f38` is above zero; when `f38 - 1` reaches zero the raw path runs and
the function reports 1, otherwise it reports 0.

Two shape tells that took the iterations, both already in the brief:
  - the trailing `return 0` is a **shared tail**, so the body must be written
    `if (++p->f40 >= p->f3c) { ... } return 0;` and not as an early
    `if (...) return 0;` -- the early-return spelling inverts the branch and
    moves the epilogue (that alone was 123 differing bytes);
  - the `func_02023D60(scaled)` call sits *after* the inner if/else in the
    source, not inside the `if` arm; that is what makes the compiler emit
    `b` at the end of the arm and place the else arm in the middle.
The `/128` on four fields is a signed division, not a shift: the
`asrs #6 / lsrs #0x19 / adds / asrs #7` quartet at +0x4A.

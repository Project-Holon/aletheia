Three levers found this pass, two of which are new and generalise:

1. THE DISJUNCTIONS MUST BE INVERTED, not written as `||`.  Both
   `t == 1 || t == 2` and `r == 1 || r == 2` compile to a RANGE test
   (`subs r0, t, #1 / cmp r0, #1 / bhi`) that is 5 bytes shorter than the
   original's two `cmp`/branch pairs.  Writing the outer one as an early
   `if (t != 1 && t != 2) return t;` and the inner one as
   `if (r != 1 && r != 2) goto bits;` restores both pairs.  This is the
   opposite of docs/idioms/disjunction-must-be-one-expression-to-share-
   its-exit.md: there a chain of `if`s had to become one `||`; here one
   `||` has to become a negated chain, because the two constants are
   ADJACENT and so the `||` folds to a range check.  Worth its own idiom
   file if a third instance turns up.

2. func_0200725C's third parameter is u8 (see src/matched/func_0200725C.c,
   filed EXACT this wave).  Declaring it u8 here is what lets the `1` be
   shared from r4 with the `strb` (`adds r2, r4, #0` at +0x38) instead of
   rematerialised as `movs r2, #1`.

3. `u8 i` for the loop index DOES emit the guard (134 bytes against 136,
   32 out) but costs a `lsls/lsrs` truncation pair at the increment and
   turns `blt` into `blo`.  `signed char` and `short` behave the same way
   (134, 31 out); `unsigned short` is 134, 32 out.  So the index is not
   simply narrow: the original increments and compares a full word yet
   still keeps the guard.

The two DIFFs above are twins of one another and the residues recorded for
them (a 4-byte prologue register shift) were symptoms of two separate C

register-NAMING residue at the SAME instruction triple, at the original's

THREE LEVERS, in the order they were found.  All three transfer between the
twins and are worth trying first on any member of this family (the
0x02146BC8 window/bank accessors of unit 22).

  1. THE FIRST GUARD IS A BRANCH, NOT A PREDICATE.  Written as
         if (cur <= max + 1 && min <= max) ok = 1;
     the compiler predicates the second test's load and emits
     `ldrhls r3, [r0, #0xa]` / `cmpls`, and the whole function walks off.
     The original's `bgt` at 0x020632AC / 0x02063390 is a real branch, and
     it comes back only from the negated-outer spelling with a SIGNED
     compare:
         if (!((s32)cur > (s32)max + 1)) { if (min <= max) ok = 1; }
     The signedness matters: `cmp ip, r2` + `bgt` is a signed test on two
     values that were both zero-extended by `ldrh`, so the C cannot use the
     u16s directly.

  2. THE CUR FIELD IS RE-READ, AND ONLY `volatile` KEEPS THE RE-READ.
     The image loads the cursor halfword twice, at +0x08 (for the guard) and
     again at 0x020633E8 / 0x020632FC (for the array index and the return
     value).  Both front ends forward the first load and drop the second.
     Six spellings were measured -- a second named local, an index local
     distinct from the returned value, the read placed after the base
     computation, the read placed before it, a u32 index with a u16 narrowing
     cast, and a fresh `obj->cur_idx` at each use -- and every one forwards.
     Declaring the GUARD's read `*(volatile u16 *)&obj->cur_idx` (the guard's,
     not the later one's) is what makes both loads survive.  On 0x02063378
     this single change took the file from 91 concrete bytes out to 5.

  3. THE FAILURE RETURN IS A SEPARATE EPILOGUE (0x02063294 only).  The image
     branches to its own `mov r0, #0` / `pop {r4, pc}` at 0x02063368; written
     as a plain `return 0;` inside the guard, 2.0 cross-jumps it into a
     `moveq r0, #0` / `popeq` and every following instruction shifts by four.
     `goto fail;` with `fail: return 0;` as the last statement of the
     function restores it, and takes 0x02063294 from 119 out at 224 bytes to
     13 out at the original's exact 228.

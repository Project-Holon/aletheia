------------------------------------------------------------------------------
the one new codegen fact: literal address casts fold, extern data symbols do not
------------------------------------------------------------------------------

`func_021BAD50` measured DIFF at 14 bytes with the second script address spelled
`(void *)0x021C3A50`: 1.1p1 -O4,p had put `0x021C3B00` in the pool and printed
the second constant as `adds r2, r1, #0 ; subs r2, #0xb0`.  The same fold shows
up in func_021BB9C8 (`subs r2, #0xbc`) and in func_021C205C, where
`*(u32 *)(p + 0x8F4) = 1` is printed as `adds r2, r2, #5` off the 0x8EF base.

The fix for the func_021BAC24 family is to give the addresses independent
witnesses and let the compiler see them as symbols, not as integers:

    extern u8 data_021C3B00[];      /* 0x021C3B00  data  */
    ...
    func_021BAC24(a, data_021C3B00, (void *)0x021C3A50, 5, 4, 0x11);

An extern object address is a relocation, so no delta arithmetic is possible and
the three pool words come out independent, which is what the image has.  Only
the address that stays a literal can still be folded.  All four then close
EXACT with the data symbol on the `symbols:` line as plain `data` (rule 8, no
region token).

three codegen facts this lane measured on fresh shapes
------------------------------------------------------------------------------

1. A dispatch with two contiguous cases is a `switch`, not an if/else-if.
   func_021BA5F0 is the proof: as `if (c==0) f1; else if (c==1) f2;` 1.1p1
   inlines the c==0 body and inverts the test (`bne`); as a `switch (c)` with
   `case 0:` / `case 1:` it lays both case bodies out of line behind
   `beq`/`beq`, which is the image.  Same 24 bytes, 18 of them different.

2. The image reuses the `subs` flags of a decrement, so write the decrement
   as the condition.  func_021C047C and func_021BC73C both show
   `ldr r1,[r5,r4]; subs r1,r1,#1; str r1,[r5,r4]; bpl` with no `cmp`:
   `if (--*(s32 *)(p + 0x1E0) < 0)` reproduces it, while
   `x = *(s32*)...; x - 1; if (x < 0)` adds the compare and the register.

3. `if/else` on a named local beats the ternary when the image's first
   `movs` is the DEFAULT value, not the equal value.  func_021BD838 wants
   `movs r1,#0x48; cmp r0,#0; bne ahead` and only the if/else form gives it;
   the ternary emits `movs r1,#0x49; ...; beq`.

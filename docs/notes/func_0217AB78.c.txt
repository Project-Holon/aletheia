WHAT THE ROOT IS
----------------
layout/symbols_sdk.json (and symbols_sdk.txt line 2078) name
0x0217AB78 DWCi_Netcheck_Thread, TwlDWC/libdwcauth.TWL.HYB.a(dwc_netcheck.o),

    ov009 0217AB78..0217B7E8 (3184 bytes, ARM)

so the "true extent" is not in question: 3184 bytes is the SDK size and the
next label (func_0217B7E8 = DWCi_Netcheck_SetError) sits right after it.
Code runs 0x0217AB78..0x0217B788 (0xC10 = 3088 bytes; last instruction
`pop {r3,r4,r5,r6,r7,r8,sb,sl,fp,pc}` at 0x0217B784); 0x0217B788..0x0217B7E8
(0x60 = 96 bytes) is the function's own literal pool (fifteen ARM words then
a 36-byte .byte run holding the tail).  The body is ~772 instructions of a
worker-thread state machine: 89 direct `bl` sites, 10 register-indirect

(DWCnetcheckhttpparam, DWCnetcheckauthparam, DWCauthhttpparam, OSi_ThreadInfo,
errno, .bss/.data and eleven `@16828..@16838` section-local pool labels).

The exact object is present in the checkout:

    sdk/TwlDWC/lib/ARM9-TS/Rom/libdwcauth.TWL.HYB.a -> dwc_netcheck.o

Verification (tools/gcc-arm readelf + a direct section read, no objcopy):
section 50 of dwc_netcheck.o is DWCi_Netcheck_Thread, size 3184, and
comparing it to the ROM bytes from `match.py show --region ov009` leaves 0
concrete differences once the object's 107 relocation fields are skipped
(all 107 are inside the function: 89 R_ARM_PC24 call sites + 18 R_ARM_ABS32
pool words; 426 of the 428 span bytes are nonzero in ROM).  In other words

WHY NO SOURCE FILE WAS WRITTEN
------------------------------
Matchable C would have to reproduce all 3088 code bytes of dwc_netcheck.c
(the Debug DWARF puts the function at decl_file 444 = dwc_netcheck.c,
decl_line 244, with locals httpretcode/httpretcodei/DWC_netcheck_wifiinfo/
authresult/alloc/free/body302/bodywayport/retcode/url/url_len/data/data_len/
wait/wait_len/wait_sec/calinfo).  That is SDK library code, ~770 instructions
of Wi-Fi netcheck state machine, whose source is not in the tree (only the
TwlDWC headers under sdk/TwlDWC/include and the archive are).  Hand-matching
it would be a multi-session project for zero game coverage; the honest record
is this note plus the recommendation below.

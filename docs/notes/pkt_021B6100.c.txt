# pkt_021B6100 residue (lane O23 filed the DIFFs; lane O31 closed them)

Lane O23 parked ten DIFFs and one MATCH here.  Lane O31 resolved every one of them;
the stale sources are left under scratch/ov_172/diff/ only as history.  Nothing in

## The callee-saved-pointer DIFF class (10 functions, all now EXACT)

Every one of the ten was the same mistake: the parked source omitted the call the
image actually makes, or spelled the store order the way the fields are laid out
in memory instead of the way the original source ordered them.

| function | what the parked source was missing | the source that closes it |
|---|---|---|
| func_021B65C4 | the call to func_0203D7FC; a bare `*q = 0` cannot colour r4 | load the word into a local, pass *the local* to the callee, then clear the field |
| func_021BE34C | the call to func_0202F038 | same shape as func_021B65C4, offset 0x1dc |
| func_021BE100 | both calls (0x0202EB0C, 0x0202EB14) | `if (sub_0202EB0C(x) == 1 && unit_0202EB14() == 0) return 1; return 0;` |
| func_021B7590 | nothing; the guard had to be written `== 1` with the call arm in the fall-through | `if (f(x) == 1) return g(...); return 1;` |
| func_021B7B3C | the second guard is a call to func_02085D3C *with the first call's result* as its argument, which is exactly why no register is set for it | `r = f(x); if (r != 1) return; r = g(r); if (r != 1) return; veneer(3, 3, z);` |
| func_021B688C | nothing; the `!= 6 / != 0` nesting never merges the two `return 1` arms | `return v == 6 \|\| v == 0;` (one compare pair, one shared return-1 block) |
| func_021B8BFC | the increment was written read-store-read | `p[0x1ac] += 1; if (p[0x1ac] >= 0x40) p[0x1ac] -= 0x40;` |
| func_021B7888, func_021B78A0 | the word store written *last*; CW only runs `strh` past it (and so hoists `movs r4, #1` to the top, which is what forces `push {r3,r4}`) when the word store is the *first* statement | `*(u32 *)p = 1;` first, then the four `u16` fields |
| func_021B7B20 | the record base held in a local; the sum then lands in the base's register, not in the mul's | fold the offset into both store expressions: `*(u32 *)(base + i * 0x1c + 0x38) = 1;` twice |

Two rules fall out of this and are worth keeping, both measured here:

1. **A missing call is the whole class.**  In six of the ten the parked source had
   simply dropped a `bl`/`blx` the image contains (the target is outside the region
   and the lane had not named it).  With no call in the body there is no second live
   range, so the CSE'd field load keeps r0 and no `push {r4, ...}` appears.  Before
   blaming register colouring, diff the *instruction count*: a DIFF whose compiled
   body is 4 to 12 bytes shorter than the listing extent is a dropped call, not a
   colouring problem.
2. **Store order is source order.**  CW does not reorder provably independent
   stores to different offsets, so the byte order of the stores in the image *is*
   the statement order of the original, and getting it wrong is what costs the
   callee-saved constant register.

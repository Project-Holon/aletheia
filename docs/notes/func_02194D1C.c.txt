WHY IT MATTERS
--------------
ov021_func_02194CE8 is byte-correct (MATCH*) but its only two relocation sites
are calls to 0x02194D1C.  The target is real Thumb code, but disasm.py emits it
as a `.word` run (its prologue is `push {r4,r5,r6,r7}` with no `lr`, so no
`func_` label is traced), no branch anywhere outside the caller's range reaches
it, and ov009 overlaps the address with different code.  `label`,
`sole-ref/code` and `matched` all refuse, so the caller cannot leave MATCH until
the leaf itself is a matched EXACT entry.  The correct extent is
0x02194D1C..0x02194E4E (0x132 bytes of body: `pop {r4,r5,r6,r7}; bx lr` at
0x02194E4A/0x02194E4C, then 0x46C0 alignment and the literal pool
0x02194E50..0x02194E70; the next traced function is func_02194E74).

WHAT IT IS
----------
A G3 immediate-mode draw setup (NitroSDK gecom-style register writes over
0x04000440.., the same register family as src/matched/func_020155A0.c and
func_0204F7DC.c): MTX_PUSH=0 (0x04000444), the three MTX_TRANS words from
b+0x1c/0x20/0x24 (0x04000470), MTX_SCALE three times with
(b[0x5e] * b[0x28]) / 8 (0x0400046C), then TEXIMAGE_PARAM (0x040004A8) from
a+0xCC8, TEXPLTT_BASE (0x040004AC) from a+0xCCC, DIF_AMB (0x040004C0),
SPE_EMI (0x040004C4), POLYGON_ATTR (0x040004A4); if b+0x58 is set a first
quad block (BEGIN_VTXS=0, COLOR, TEXCOORD/VTX_16 pairs, END_VTXS=0); if the
third argument c==0 a second quad block (BEGIN_VTXS=1 ... END_VTXS=0); finally
MTX_POP=1 (0x04000448).

Lane O35: ov016 contested data addresses, rule 8 sweep
======================================================

Rule 8 (a DATA target on the `symbols:` line WITHOUT the region token) is
confirmed on a further 21 ov016 functions this lane, all ARM, all filed EXACT
with the data address either as a bare literal or, where the compiler insists
on folding a large constant (func_021BD3CC), as an extern array with a
token-less `data` symbols line.  Nothing here needed the `sole-ref/self`
relocation to resolve for the literal spelling: a literal address is not a
relocation site, `match.py one` reports "0 relocation site(s)" and compares
the pool word byte for byte.

Filed EXACT (21 functions, 684 bytes): see the lane report.  Distinct
contested addresses those 21 cleared as blockers: 15 --

Residues: every site below resolves every relocation it declares (the
contested-data cap is gone from all of them); the residue is register
allocation or constant materialisation only.

func_021D5FC4  0x021D5FC4  32B  arm
  Residue: 40 vs 36 bytes.  The image hoists `mov r0,#1` once and predicates
  both stores (strbeq [r2,#0x67c] / strbne [r2,#0x67d]) with `bx lr` as the
  single exit.  Both the `if/else` spelling and the conditional-address
  spelling produce a branch to a second exit instead.  Lever: force the
  single `v = 1` local to be the stored value AND the return value from one
  arm (`*(unsigned char *)(p + (a == (int)(p + 0x610) ? 0x67c : 0x67d)) = v;
  return v;` was tried and still branched).

func_021BCAE4  0x021BCAE4  36B  arm
  Residue: 5 bytes, register naming only.  Image: r0 = the global pointer
  (0x021DE508), r2 = its loaded object, r3 = 1, and the global is *reloaded*
  (`ldr r0,[r0]`) for the tail call's argument.  Source reloads through a
  named pointer and gets r2 = pointer, r0 = object.  Lever: make the reload
  the compiler's own CSE target by writing the global twice as a literal cast
  (`*(char **)0x021DE508` twice) rather than a named local.

func_021C6508  0x021C6508  40B  arm
  Residue: argument order.  Image builds r1 = byte at 0x021DA518, r0 = word
  at *(*(0x021DE5D8+4)+8), r2 = r1, then calls func_021CE7B0(r0, r1) with r2
  carrying r1 -- i.e. a three-argument call whose second and third arguments
  are the same value.  `func_021CE7B0(a, a)` written out was tried; the
  compiler keeps two distinct loads instead of one CSE'd value in r1 copied
  to r2.

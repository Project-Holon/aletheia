func_02010BB8 -- DIFF at 4 bytes: the AND-versus-BIC wall (wave r6, lane small-3)
======================================================================

Compiled 120 bytes against the original's 124; 4 concrete bytes differ and the
compiled object is exactly one literal-pool word short.

  +002A  ORIGINAL  ldr r2, [pc, #0x4c]   | COMPILED  movs r2, #0xe0
  +002C  ORIGINAL  ands r3, r2           | COMPILED  bics r3, r2
  +0034  ORIGINAL  ands r2, r3           | COMPILED  bics r3, r2
  +0036  ORIGINAL  str r2, [r0]          | COMPILED  str r3, [r0]

The image ANDs both display-control registers with the pooled word 0xFFFFFF1F
(from the pool at 0x02010C30); dsi/1.1p1 rewrites "x & 0xFFFFFF1F" into
"movs #0xE0; bics", which needs no pool word, so the whole tail is four bytes
short.

Measured control: the pooling path exists and is chosen purely by the
constant's shape.  A constant whose complement is NOT an 8-bit immediate --
0x7FFFFF1F, probed as "(u32)-(int)-2147483423" -- is pooled and ANDed by
1.1p1 (compiled 124 bytes, one byte wrong: the pool word itself).  For
0xFFFFFF1F the complement 0xE0 fits, and 1.1p1 takes BIC every time.

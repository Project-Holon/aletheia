packet pkt_0201CD10 - func_0201CD10 @ 0x0201CD10 (222 bytes) - DIFF, 2 bytes  [2026-09-21]

Size is exact (228/228 with the trailing pool) and 226 of 228 bytes are
identical.  The residue is two adjacent loads swapped at the func_0201C808
call site:

  * +0028  ldr r1, [sp, #0x28]   |  ldr r3, [sp, #4]
  * +0030  ldr r3, [sp, #4]      |  ldr r1, [sp, #0x28]

i.e. the original materialises the 5th incoming argument (sp+0x28) before
the spilled 2nd argument (sp+4); this front end does the reverse.  Nothing
in the C selects it: tried binding a4 to a local before the call, reading it
as *(u32 *)&a4, reading a1 through a volatile lvalue, casting o+0x34 to
void * versus leaving it as u8 *, and hoisting the a4 read above the first
blx (that last one is much worse -- it makes the whole argument block
stack-resident and pushes r3, costing 4 bytes and shifting everything).

What IS settled, and is worth keeping:

  - func_020311B8's argument order is (a6, fn, 0x50, a7), not
    (fn, 0x50, a6, a7): the pool word 0x0201CEE1 lands in r1, the size 0x50
    in r2.  0x0201CEE0 is a real Thumb function and the pool word carries
    the Thumb bit.
  - The function RETURNS the allocated object (`adds r0, r4, #0` at +0x00D8
    just before the epilogue), so it is `void *`, not `void`.
  - The halfword written to o[0x20] is read as *(u16 *)((u8 *)&a4 + 0x14),
    which reproduces `add r1, sp, #0x28; ldrh r2, [r1, #0x14]` exactly.
    Spelling it as a plain `(u16)a9` parameter gives `ldr r2, [sp, #0x3c]`
    and shifts every following instruction by two bytes: the arguments from
    the 5th on are addressed off one base, not read individually.
  - sub_0201CDF4 writes a 2-byte sign/magnitude pair; the original reads
    pair[1] FIRST (strb to o[0x19]) and then caches pair[0] in one register
    for the three stores to o[0x18], o[0x1C], o[0x1A].
  - The six clears of the flag byte at offset 0x22 use the house spelling
    from src/matched/unit_0201CDF4.c, two independent ((u8 *)p)[0x22]
    expressions per statement, which is what keeps load and store addresses
    recomputed (the offset is past ldrb's +31 reach,
    docs/idioms/thumb-immediate-reach-costs-an-adds.md).

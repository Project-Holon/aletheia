The mask arm comes out exactly as the image has it (`movge r0,#1` /
`lslge r2,r0,r1` / `movlt r2,#0`), which is the same condition-first lever
docs/notes/pkt_02073BF0.c.txt records for func_02073EE4.  What blocks it is
the zero:

  * the original materialises `mov r0,#0` three separate times - once for the
    f1c store, once for each func_02082A7C first argument - and never pools.
    Ours hoists one `mov r5,#0` into the prologue and reuses it for all three
    (`str r5,[r4,#0x1c]` / `mov r0, r5` x2), growing the push from
    {r4,lr} to {r3,r4,r5,lr}.
  * the same register pressure then makes the last two field loads reload the
    global address through a fresh pool word
    (`ldr r1,[pc,#0x10]` / `ldr r0,[r1,#0x24]`) instead of using r4, which
    moves the whole tail by three instructions.

See docs/idioms/a-repeated-small-constant-takes-a-callee-saved-register.md for
the minimal repro.

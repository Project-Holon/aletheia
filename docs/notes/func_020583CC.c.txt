Two findings that were missing from the first pass:

- The ldr r2,[r1] in the empty-list arm is a genuine re-read of
  node->next immediately after storing 0 to it, i.e. the source says
  node->prev = node->next. Reproducing it needs the *pointed-to struct*
  to be volatile-qualified, not the member: mwcc 1.1p1 ignores volatile
  on a pointer-typed struct member (struct Node * volatile next) and
  forwards the store to the load anyway, while volatile on an int member,
  or a volatile-qualified struct pointer parameter, keeps the load. See
  the idiom file on this.
- With that, the empty-list arm is byte-exact as a plain basic block,
  including the separate mov r2,#0 inside the arm and the b to the shared
  tail.

What remains is the non-empty arm: the original leaves it as a second
plain basic block, and -O4,p if-converts it into five predicated
instructions plus a bne, which also lets it share one mov r2,#0 hoisted
ahead of the compare. 72 bytes compiled against 80. Tried without effect:
both condition polarities, two separate ifs on a cached head instead of
if/else, volatile on the list struct as well as the node, and the
alias-forced reload ordering that fixed the other arm. Note that the
named-local lever that closed the sibling func_02058300 (binding
node->next to a local so both arms could be predicated) is exactly the
wrong direction here, where neither arm may be predicated.

struct Node;

    volatile struct Node *head;
    int count;
    volatile struct Node *tail;

struct Node {
    volatile struct Node *next;
    volatile struct Node *prev;
};

void func_020583CC(volatile struct List *list, volatile struct Node *node)
{
    volatile struct Node *head;

    head = list->head;
    if (head == 0) {
        list->head = node;
        list->tail = node;
        node->next = 0;
        node->prev = node->next;
    } else {
        node->next = head;
        node->prev = 0;
        list->head->prev = node;
        list->head = node;
    }
    list->count++;
}

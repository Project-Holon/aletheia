WHAT IT IS
----------
The dispatcher of the twenty-entry slot table at 0x0202EB0C..0x0202ED60 (see
docs/families/blink_palanm.h, PART 2).  It resolves the caller's handle `a`
to the table, looks `b` up by its two keys, and then either removes the
entry it found or inserts one by the count-capped policy:

    u32 func_0202EB9C(u32 a, void *b)
    {

        u32 n = func_0202ECB0(t, b);

            u32 v = t[n].mark ? 1 : 0;
            func_0202ED00(t, n);
            func_0202ED60(a, b, v);
            return 1;
        }

        v = func_0200856C(b);       /* not found: insert */
        if (func_0202EC44(t, v) < 5) {
            if (func_0202EC24(t) >= 0x14)
                func_0202ED00(t, 0);
        } else {
            func_0202ED00(t, func_0202EC7C(t, v));
        }
        func_0202ED60(a, b, 0);
        return 2;
    }

TWO FINDINGS, BOTH WORTH KEEPING
--------------------------------
1.  The bit read at +0x22 is `mark` (bit 3), NOT `flag` (bit 4).  The tell is
    the shift amount of the extract pair:

        0202EBBE  lsls r0, r0, #0x1c   -> bit 3   (mark)
                  lsls r0, r0, #0x1b   -> bit 4   (flag)

    Every OTHER function in the family scans on `flag` and so uses #0x1b,
    which is what makes the wrong choice easy and silent here: with the
    sibling struct copied verbatim from src/matched/func_0202EC44.c this file
    came out at 47 bytes instead of 44, the extra three being this one
    instruction and its knock-on.  src/matched/func_0202ED90.c is the one
    matched function that writes both bits and therefore fixes their relative
    positions; the family header now records the tell.

2.  func_0202EC44's result is compared UNSIGNED here (`cmp r0,#5 / bhs`).
    The definition in src/matched/func_0202EC44.c returns `s32`; declaring it
    that way in this file gives `bge` and a wrong byte.  Declared `u32` the
    branch is right.  The definition's own spelling is not constrained (its
    value never exceeds 5), so this call site is the stronger evidence.

Both were applied; they take the file from 47 to 44 concrete bytes out.

gap that follows from it:

The original holds `a` in r5, `b` in r6 and the key/flag temporary in r7;
this front end rotates all three (a->r6, b->r7, temp->r5).  Every
instruction is otherwise in place through +0x52, and the four-byte gap is
entirely downstream of the rotation, in the branch displacements and the
tail layout of the insert arm.

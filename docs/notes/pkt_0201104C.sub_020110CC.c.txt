What it is: the multi-slot variant of sub_0201104C (same packet).  Early out when
*(u8 *)(0x02146208 + 0x1a) == 0x30 with 0xff; otherwise take the object from
func_0201AB28(a0, func_0201AB08()), walk the four slots 0x36+i / 0x3e+i / 0x3a+i
through func_02017E1C, clamp the 0x3a value to func_0201C158((u16)count,
(u8)v) plus *(u16 *)(0x02146228 + 0xe), and store it back with func_02017E40.

Spellings that are load bearing (both found by diffing, not guessed):

  * the whole body must sit inside `if (*(u8 *)(g02146208 + 0x1a) != 0x30) { ... }
    return 0xff;` -- i.e. the 0xff exit is the function's LAST statement and the
    `beq`/`bne` layout is the original's.  Written as `if (...) return 0xff;`
    first, mwcc rotates the blocks and the whole function is a diff.
  * `i` must be unsigned: `u32 i` gives the original's `cmp r5,#4 / blo`; `int i`
    gives `blt` and shifts everything after +0x78.
  * the third argument of func_02017E1C is a literal 0 and stays a `movs r2, #0`
    per call only while `i` is unsigned; with an extra live local mwcc hoists a
    zero register and the loop grows two instructions.
  * the 0x3a term must be `v = func_02017E1C(...); v += *(u16 *)(g02146228+0xe);`
    (the call result is the accumulator: `adds r2, r0, r1`).  Written as one
    expression with the call first, or with the load first, the operand order in
    the `adds` is wrong --
    docs/idioms/the-accumulator-of-a-commutative-chain-is-its-second-operand.md.

spelling tried emits the save first and then reuses the freed r0 for the load.

...` local read before the test, a `u32 t` local, the reversed comparison

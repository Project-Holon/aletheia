2026-09-21, large-function lane: relocation-witness screen of three
untouched 1 KB ARM functions.  ALL THREE FAIL, but only just, and the
gating decision is named per address at the end.  No source was filed for
any of them and no C was written beyond the screening stubs, per the
brief's rule that a target whose sites have no witness of any class is
abandoned rather than polished into a park.

METHOD, AND TWO WAYS TO GET IT WRONG (both paid for here).  For each
address: one `match.py show --addr` to fix the ISA and extent, then a
screening stub declaring every `bl` target and every non-zero pool word in
the function's own literal pool, compiled with `match.py one --arm --cc
1.1p1` so that `resolve_relocations()` prints an evidence class per site.

  TRAP 1, THE STUB MUST BE THE RIGHT LENGTH.  A short stub is not a screen:
  its compared range is only as long as it compiles, so a witness that will
  be inside the real range is never exercised and every site reads
  "resolved".  Each stub was therefore padded with dead `if (k == N) f();`
  arms until its compiled length reached the function's real extent, which
  is what puts the function's own pool and its own internal call sites
  INSIDE the compared range, as they will be when the real body is written.
  Over-padding is equally invalid: a stub compiled to 2896 bytes against a
  1088-byte original swallows genuine outside witnesses and reported nine
  false failures on target 3 before it was corrected.

  TRAP 2, THE STUB MUST LIVE INSIDE THE REPO.  `source_key()` in
  tools/match.py returns None for any path whose relpath to ROOT starts
  with "../", and `attest_matched()` refuses outright when `src` is None
  ("without it self-reference cannot be checked").  A stub written to a
  scratchpad outside the tree therefore loses the ENTIRE `matched` class
  silently: it reports as "no witness outside <range>", which is
  indistinguishable from a genuine evidence failure.  On 0x02065438 this
  turned four unresolved sites into nine.  Screening stubs go in
  scratch/ (gitignored) or anywhere under ROOT, never in /tmp.

1. 0x02067340, ARM, 1052 bytes (show: 02067340..0206775C), pkt_02066E30.
   Prologue `push {r3, r4, r5, r6, r7, r8, sb, sl, fp, lr}` / `sub sp, sp,
   #0x40`.  Three `bl` targets (0x02067080, 0x02067B50, 0x02067B64) and 11
   pool loads.  Stub 2016 bytes -> range 02067340..02067B20, 245 of 247
   sites resolved.

   TWO SITES UNRESOLVED:
     PC24  func_02067080  -> no witness outside 02067340..02067B20
     ABS32 data_020A18AC  -> no witness outside 02067340..02067B20

   func_02067080 has exactly ONE branch anywhere in the image, the `bl` at
   0x02067588, and 0x02067588 is inside this function's own body, so
   `label` refuses it.  (grep of asm/arm9/src/*.s for `bl func_02067080`
   returns that one site; the three .s files that show it are three
   delinkings of the same range, not three call sites.)  It has no
   `matched` entry either -- confirmed by calling attest_matched() directly.
   0x020A18AC's only pool word image-wide is this function's own at
   0x02067744.  Being one function, there is no `--suggest-split` cut.
   0x02067B50 and 0x02067B64 both resolve `label` x36.
   CAPS AT MATCH.

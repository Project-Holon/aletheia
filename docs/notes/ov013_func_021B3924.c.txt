func_021B3924 (0x021B3924, ov013, ARM, 210-byte body) -- DIFF near miss
========================================================================

Every instruction reproduces except one nine-instruction scheduling block.
The image keeps the low word of the func_020870D0 timestamp in r0 through the
type test, then moves it to the r3 argument slot inside the taken branch:

    ldrb r2, [r7, #4]
    and  r3, r2, #0xf0          ; type nibble in r3
    cmp  r3, #0x40
    bne  0x021b39bc
    ldr  r2, [sb, #4]
    mov  r3, r0                 ; lo -> 4th arg, only here
    add  r0, r2, #1
    str  r0, [sb, #4]
    str  r1, [sp]               ; hi -> 5th arg
    mov  r0, r8

Every build instead pre-colours the low word into r3 at definition (right
after the bl) and does the AND in r0:

    ldrb r2, [r7, #4]
    mov  r3, r0                 ; hoisted
    and  r0, r2, #0xf0
    cmp  r0, #0x40
    bne  0x021b39bc
    ldr  r2, [sb, #4]
    mov  r0, r8
    add  r2, r2, #1
    str  r2, [sb, #4]
    str  r1, [sp]

Semantics settled: reject a null header (the compiler folds this into
`movs r7, r1`, whose flags drive the `popeq`), reject magic != 'TCV_'
(0x5F564354) with 2, reject when the ov013 global 0x021B60CC has +0x1c == 0
or +0x08 == 0; clear a3[0]/a3[1]; take a 64-bit timestamp; when the header's
type nibble (f4 & 0xf0) is 0x40 bump 0x021B60CC+4 and call
func_021B0F38(a0, h, a2, lo, hi); when f4 is 0 or 0xff return
func_021B2488(a0, h, a2, a3) != 0; otherwise return 0.

Variants tried, all 31 bytes out with the same pre-colouring: passing
`(u32)t, (u32)(t >> 32)` inline; binding `lo`/`hi` locals inside the branch;
declaring an explicit `typ = h->f4 & 0xf0` local; passing the raw `t`,
`t >> 32` to a `u32` parameter.  The four relocations (func_020870D0, the two
ov013 callees and the 0x021B60CC global) all resolve.  Parked as a
scheduler/colouring wall -- the timestamp lives in r0:r1 in the image and r1:r3
here across the test.

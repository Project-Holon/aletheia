2. The wrapper family (func_021DF3B0/3E8/420/458)
-------------------------------------------------
One shape, four members, differing only in the probe callee and the warning
code:

    s32 f(s32 a)
    {
        s32 v = probe(a);

        if (v != 0)
            post(pick(v), warn(code, v));
        return v;
    }

The trap that cost the first compile on all four: an early `return v;` inside
the `if` compiles to `popeq`, while the image branches to the shared epilogue
(`beq #epilogue`, then `mov r0, r5`).  The image's form is the guarded body
plus a single trailing `return v;`.  Same residue on all four, so it is the
shape to reach for first on any "call, test, post, return handle" wrapper here.
func_021DF358 is the eight-argument member of the same family: the four
register arguments are forwarded untouched and the outgoing stack frame is
(a4, a5->f18, a5, a6), with the same guarded post.

3. Other cheap classes that closed first compile
------------------------------------------------
* `if (p == 0) return 2; if (*(u32 *)(p + 0x50) != 0) { reset(p); dtor(p); }
  return 0;` - the shared `mov r0, #0` tail is what the `beq` targets, so write
  the positive test and let the return fall through (func_021DFA3C).
* Two-arm state reset with a memset pair: the 0x28-byte blocks at +0x5c and
  +0x84, then two byte constants 0xde/0xad on each block's front and a live
  flag (func_021DF884/DF8D4).  gcc keeps `0` and `0x28` in two callee-saved
  registers and reuses the 0 for the final store, so declaring `u32 z = 0;`
  rather than writing literal zeros is the spelling that reproduces it.
* ARM jump tables DO reproduce from a plain `switch` here, and the table index
  is the case VALUE, not the position in the source.  func_021DF5E4 was 4
  bytes wrong because I read the table entry at byte offset +0x20 as case 6;
  the table starts at +0x0c (the first entry is the out-of-range branch), so
  +0x20 is value 5.  Count the table base before assigning a case value.
* A bswap32 written as an expression whose result is stored in a local whose
  address is taken gives the whole stack round-trip: `u32 w = ((v >> 24) &
  0xff) | ((v >> 8) & 0xff00) | ((v << 8) & 0xff0000) | ((v << 24) &
  0xff000000); u8 *q = (u8 *)&w; dst[0] = q[0]; ...`, and the ADVANCE must be
  the return value (`return dst + 4;`) or gcc drops the `add r0, r0, #4`
  (func_021E054C, 4 bytes short on the first compile).
* A struct init that clears non-adjacent words reproduces by writing the
  stores in the image's order, not the struct's order: func_021E06DC emits
  +0, +4, +8, +0xc, +0x2c, +0x28, +0x30, +0x14, +0x10, +0x18, +0x48 and that
  order in the C source is what the compiler kept.

CODEGEN NOTE THAT COST REAL TIME, found in pkt_02060E94 (func_02060E94,
EXACT*), which an idiom file should probably carry:

1. A loop-invariant sub-expression written INLINE in the loop body is
   hoisted by mwcc into the loop preheader, and the preheader is emitted
   AFTER the loop's entry test:

       02060E94  ...
       02060EB4  beq   0x02060F10        /* entry test, branches out */
       02060EB8  sub   r4, r0, #1        /* hoisted size-1        */
       02060EBC  mvn   r5, r4            /* hoisted ~(size-1)     */

   Written as two named locals instead they are emitted in source order,
   before the test, and the allocator's choices shift throughout the
   function; the version with named locals is 128 bytes and 32
   instructions, the same function with them inline is 132 bytes and 33 --
   the missing instruction being the epilogue's `mov r0, r3`, because the
   early-out can only `popeq` straight out of r0 when the result local was
   hoisted into r0.  "Same size, register names only" is not what this looks
   like: it looks like a whole function one instruction short.

2. The declaration order of the small result locals relative to the loop
   cursor decides the caller-saved register assignment for the whole
   function.  For

       s32 size = func_02091588(x);
       u32 best = 0;
       u32 ofs = -1;
       struct HeapBlock *blk = heap->head;

   the assignment is blk -> lr, best -> r3, ofs -> ip (the original); moving
   the `blk` line above `best`/`ofs` rotates those three, and the body
   temporaries follow, which reads as a 20-byte mismatch over 5 registers
   with the size already right.  Declaring size first is forced (the abs
   call is emitted first) but the other three are free parameters.

3. `u32 ofs = -1;` is spelled `sub ip, r3, #1` -- rematerialised off the
   zero register holding `best`, not `mvn ip, #0`.  See
   docs/idioms/a-small-constant-is-rematerialised-off-a-zero-register-
   unless-an-argument-shares-it.md, which is about `adds` off a zero but
   covers this: it is the cheapest way to check whether a small constant
   local was declared at all.

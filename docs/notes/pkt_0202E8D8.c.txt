Two things are pinned by that listing and both are already in the drafted C:
the 0xfffe/0xffff pair must be spelled as two literals one apart (the second
comes out of the first with `adds r0, r0, #1`, so a re-load of 0xffff loses
four bytes), and the magnitude test is unsigned (`bhi`, so an `int` a2 gives
`bgt` instead).

WHAT IS STILL WRONG
-------------------
The final arm.  The original keeps the two arms as written source order:

    cmp r5, #3 / bhi <0x1f arm> / movs r0, #0xf / b <store> / movs r0, #0x1f / store

The compiler keeps hoisting whichever arm is written as the `if` body ahead of
the compare:

  - with `else if (a2 > 3) { v = 0x1f; } else { v = 0xf; }` mwcc emits
    `movs r0, #0x1f` BEFORE `cmp r5, #3` and drops the trailing `b` - 2 bytes
    short, 20 bytes of residue;
  - with `else if (a2 <= 3) { v = 0xf; } else { v = 0x1f; }` it emits
    `movs r0, #0xf` first and closes with `bls`, again 2 bytes short.

Neither matches the original's branch-before-both-arms layout.  The remaining
candidates are a four-case `switch (a2)` with the two empty-ish defaults, or
the ladder written with the two high sentinels as the `if` bodies and the
magnitude test as the shared else.  Both are shape experiments, not new
evidence; the three earlier `else if` spellings are dead ends.

pkt_02083250 - hand-written ARM, not compiled C
==============================================================================

pkt_02083250 holds 0x02083250, 0x02083298, 0x02083334 and 0x020833D0, the byte-swapping memcpy family of the high window.  They
are hand-written ARM, not compiled C, and no C will ever reproduce them; the
finding is written up in full in docs/notes/pkt_02086368.c.txt section 1 by the
wave that first hit it.  The three tells, quoted there:

  * the byte tail at 0x0208314C is reached with a plain `b` (no relocation)
    from 0x02082F80, 0x02083018 and 0x020830B0 -- three functions jump into
    the middle of the body of a fourth, which no single translation unit can
    emit, since mwccarm gives every function its own section and a
    cross-section branch is a relocation;
  * a dispatcher at 0x02082EFC enters each variant's middle with
    `and r3, r1, #3; bic r1, r1, #3; cmp r3, #0; beq ...`;
  * the byte tail is `tst r2, #4` plus eight `ldrbne`/`strbne` pairs, a shape
    this front end emits for no loop.

They want the treatment layout/runtime_arm9.txt gives its routines: a curated
table entry, which would attest all eight at once.  Veredict for this lane:
blocking class `artifact`, evidence = the cross-section branch at 0x02082F80 ->
0x0208314C (plain `b`, no relocation field) and the 32-byte block loop's
`lsl`/`lsr` pair per word.  Not attempted as C on purpose: two waves of this
project have now spent budget on this family and both concluded it is not
compiler output.
re-verified 2026-09-21: no recoverable source in this note

== wave 11 appendix, 2026-09-23: NOT FUNCTIONS -- interior of TwlSDK libmi ==
These addresses are interior kernels of two SDK `asm` functions that
layout/symbols_sdk.json already matched over their whole extent:
MI_CpuCopy 0x02082EA4 (752 bytes, 752/752 concrete, to 0x02083194) and
MI_CpuMove 0x02083194 (788 bytes, 785/788 concrete, to 0x020834A8).
0x02082F48 is entered by `beq` at 0x02082F30 inside MI_CpuCopy; the kernels
pop {r4-r10, lr} without pc and fall into the shared tail.  They are open
only because the worklist excludes an SDK symbol's start and not its body.
No best source exists and none is filed on purpose (a fragment file would
invent a function boundary); no permuter run is possible without a source.
Integrator: drop the interior starts 0x02082F48 0x02082F90 0x02083028
0x020830C0 0x02083250 0x02083298 0x02083334 0x020833D0, or let the sdk class
cover a libmatch symbol's full size.  The wave-7 "MSL memmove" reading of
0x02083298.. is corrected: the library is libmi (MI_CpuMove).
docs/families/cluster_02083028.h, cluster_02083298.h.

Levers worth carrying forward from this run
-------------------------------------------
1. A conditional return inside a loop body must be written as the `else` of
   the positive test.  `if (f() == 0) return 0;` following the body makes mwcc
   if-convert the epilogue into `moveq`/`popeq` and loses eight bytes;
   `if (f() != 0) body; else return 0;` reproduces the out-of-line block.
   (func_02039CD8, 180 -> 188 bytes.)
2. A short-circuit `&&` in a guard loses the predicated `ldrbne`/`cmpne` chain
   and emits a real branch.  `if (a == 0 || b == c) goto L;` is what produces
   the predicated pair the originals show.  (func_0203A020, func_0203B390.)
3. The `else` of a two-arm guard belongs at the end of the function, not as a
   leading `return`: write `if (cond) { ...body... } else { fail; }` and let
   the fail arm fall out of line.  (func_0203A020.)
4. A function pointer called through a member is loaded into r1, not r0, when
   the same statement also passes the preceding call's return value as the
   first argument: `((void (*)(u32))p->f2c)(func_0203D650());`
   (func_0203B52C, 172 -> 168 bytes and byte-exact.)
5. Declaring the loop index unsigned is what turns the loop back-edge into
   `blo`; a signed `int` emits `blt`.  (func_0204767C 192 -> 188 EXACT;
   func_0204E410.)
6. Two pool words two bytes apart (0x020A1480 / 0x020A1482) are two separate
   symbols, not one four-byte record: a struct collapses them onto one base
   plus offsets and loses a relocation.

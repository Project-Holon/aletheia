Blocker evidence, promotion lane 1 (scratch/promo_lane1.md: 15 parks whose named
callee is <= 256 bytes).  Written for the next pass so the same walls are not
re-walked.  Every line below is `tools/match.py` output or an `attest()` probe
run by scratch/l1_triage3.py, not a guess.

The list is built on "match the callee and the park unblocks".  That holds only
when the callee is itself attestable end to end.  Of the 15 rows, 11 stop short
of that, and the reasons fall into three groups.

A. Callee has a site nothing in the image can witness

  row 1  func_02073108 <- 0x02072894 (MATCH, parked src/pending/func_02072894.c)
         The park's site is fine; 0x02072894 is capped because 0x0208A0A4 (the
         SDK leaf it tail-calls) has exactly one caller, this one.  0x0208A0A4
         is 264 bytes of ARM with ZERO relocations, so it is pure transcription
         and was attempted: ~50 C spellings land on a 4-5 byte residue in the
         second node computation (an add/sub tree order plus the register the
         pair lands in).  Best spelling: pre-loop
         `{ u32 cur = *(u32 *)(base + 0x11C0); node = (off == 0) ? 0 : base +
         (off - cur); }` with the destination-byte index reached as
         `u8 *row = base + a * 0x24; row += b; sel = row[0x548];`.  Then the
         loop's copy of the same expression is 5 bytes off; the pointer-cast
         spelling `(u8 *)(base + off) - c` gets the registers right and the
         tree wrong (4 bytes).  A wall on the same pattern as
         docs/notes/pkt_02036568.c.txt.

  row 2  func_0200A300 <- 0x0200A358
         0x0200A358 is 120 bytes of Thumb and reproduces to a 4-byte residue
         (the original has two extra `b` stubs that mwcc tail-merges for every
         spelling tried, including the switch form).  It does not matter: two
         of its sites, `bl` to 0x021DFEAC and 0x021DFE90, have no witness of any
         class.  Seven overlays map that window (ov093, ov119, ov137, ov170,
         ov175, ov183, ov228) and NOT ONE of them labels either address as a
         function (`grep -n "func_021DFEAC" asm/overlays/*.s` is empty; ov228
         holds both only as `.word` data), so a region hint cannot rescue them
         either.  Its argument 0xE4 is the same FS_OVERLAY_ID shape as the 0xBC
         in docs/idioms/a-pooled-small-constant-argument-is-a-linker-symbol.md,
         but unlike 0xBC it DOES have outside witnesses (`literal x3`), so that
         site is not the problem.

  row 3  func_0200D298 <- 0x0200D2D8 (MATCH, src/pending/func_0200D2D8.c)
         Chain: 0x0200D2D8 -> 0x0200C780 -> the data table 0x0209DE2C, which
         has one pool word image-wide and it is inside 0x0200C780's own extent.
         Terminal: unattestable data, not a code problem.

  row 11 sub_02034EF8 <- 0x0203545C (MATCH, src/pending/sub_0203545C.c)
         All 16 sites resolve except `bl PM_GoSleepMode` = 0x0208C154, which is
         in layout/symbols_sdk.json (`TwlSDK/libspi.TWL.HYB.a`, pm.o, arm, 760
         bytes) but has no branch anywhere in asm/arm9 or asm/overlays - the SDK
         blob's internal callers are not in any listing, so `label` is empty and
         `literal` too.  An SDK symbol that nothing in game code calls is not
         attestable from here; it needs the SDK library itself in the manifest.

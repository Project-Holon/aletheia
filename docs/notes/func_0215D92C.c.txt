WHAT IT IS
----------
SOCLi_CopyCPSBuffer(socket, buffer, buffer_len, *remote_port, *remote_ip).
Sets up cpsbuffer + cpsbuffer_len, resolves the locally-unreachable
remote_port/remote_ip/his_ip/his_port, then on a full (cpsbuffer == 0)
buffer runs SOCLi_GetRecvBuffer result = -0x1c and clears `state` bits 1..2,
then writes his_port/his_ip back through remote_port/remote_ip and publishes
my_port if local_port == 0.  On success it accumulates
`socket->recv_pipe->consumed += result` when flag_noconsume == 0.

The image KEEPS the branch over a 3-instruction guard body closed by a tail
branch.  dsi/1.1p1 (and 1.2, 1.2p1, 1.2p2, 1.3) -O4,p unconditionally
if-converts any guard arm of 5 instructions or fewer (see
docs/idioms/an-arm-guard-block-of-five-instructions-or-fewer-is-predicated.md);
the block here is 3 instructions, so there is no C shape at those front ends
that leaves the branch.  The family lane (../1.2/sp2: 272/125, ../2.0/sp2:
268/61, ../2.0/sp2p2: 268/61, all verified this session) keeps the guard
branch but instead emits a branch for the image's predicated `&&` tail chain
and mis-orders the else-arm constant select, so no build we have reproduces
the full function: the original mixes a 2.0-style kept branch (-p forbids
predication there) with 1.1p1-style predicated tail and *mvnne* select.

CONCLUSION
----------
No pinned front end emits byte-identical output for this function: 1.1p1
(and every 4.0-family build) can only predicate the +0x90 guard; the 2.0
family can only branch it and then branches the tail.  This is the
"front-end whole-function pin" residue class, not a C lever.  Kept in
src/pending with status DIFF, the else-arm lever (ternary 0:-0x1c) applied
so the DIFF is the single 4-byte guard shape; 260/264 bytes, 101 concrete
bytes differ, blocker is the mixed predication policy.
Do not re-attempt without a source reading that gives the guard arm a call
or a sixth IR operation, or a front end between 4.0.x and 2.0.0.79 that
keeps short branches but still predicates the && tail.

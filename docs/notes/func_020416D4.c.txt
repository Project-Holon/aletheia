func_020416D4 - window-clipped row, not filable from the 0-64 byte band
======================================================================

func_020416D4 @ 0x020416D4 (row size 28, listing extent 784, arm9, ARM)
verdict: not filable in this lane; the row's window is the switch dispatcher

Same situation as docs/notes/func_0203DC70.c.txt: the band's 28-byte row is
the nine-way dispatch head of a 784-byte function (the next `func_` label is
0x020419E4), and every one of the nine arms (0x02041704, 0x02041724, ...,
0x02041928) plus the shared default at 0x020419B4 lies far past the window.

  020416D4  sub sp, sp, #0x20
  020416D8  cmp r0, #7
  020416DC  addls pc, pc, r0, lsl #2
  020416E0  b   #0x20419b4
  020416E4  b   #0x2041704
  ...

Each arm reads a halfword from one of four pool-initialised globals, extracts a
2-bit field (`lsl #0x1e` / `lsr #0x1e`), stashes the raw halfword in a distinct
stack slot (`strh r1, [sp, #0x1e]`, `#0x1c`, `#0x1a`, ...) and returns the
field zero-extended - so the function is also the only reader of those stack
slots, and every arm would have to be written to reach the extent the harness
compares against.

Not attempted: the switch head cannot be compiled as a standalone fragment, so
no C file can land on this row's 28 bytes.

Addresses are Black-image addresses.

APPENDED 2026-09-21: the note above is STALE.  The 28-byte 'row' framing
is wrong: func_020416D4 is a 784-byte function and it IS compilable as a
whole.  Size now reproduces EXACTLY (784/784) and the first 0x88 bytes are

WHAT CLOSED THE STRUCTURE (these are settled, do not re-derive):
  * The return is a 2-BIT BITFIELD READ, not a mask.  Declaring
        struct BgCnt { u16 prio : 2; u16 rest : 14; };
    and COPYING the register into a local struct is what produces the
    'lsl #0x1e / lsr #0x1e' pair AND the 'strh r1, [sp, #N]' spill in one
    go.  A plain '(x & 3)' loses both; a plain u16 local loses the spill.
  * Each arm needs its OWN local (c0..cN).  The distinct locals are what
    place the spills at the descending slots 0x1e, 0x1c, 0x1a, ... .  One
    reused local collapses them all onto [sp].
  * The return type is u8: that is the 'and r0, r0, #0xff'.
  * The eight top-level arms must all be present to keep the dense
    'addls pc, pc, r0, lsl #2' table (empty-switch-arms idiom).
  * The four sub-dispatch arms read the SAME register in all sub-cases;
    only the stack slot differs.  Resolved pool words, per arm:
        layer 0 -> 0x04000008   layer 1 -> 0x0400000A
        layer 2 -> 0x0400000C   layer 3 -> 0x0400000E
        layer 4 -> 0x04001008   layer 5 -> 0x0400100A
        layer 6 -> 0x0400100C   layer 7 -> 0x0400100E
    i.e. engine A/B BGxCNT.  The sub-dispatch key is the slot's +0x1C
    mode byte, read via the 0x2c-stride record off g_02146A44.

THE ONE REMAINING BLOCKER, concrete:
  The original emits the FULL comparison chain before any arm body:
        cmp r0,#0 ; beq A ; cmp r0,#1 ; beq B ; cmp r0,#2 ; beq C ; <fall>
  Every spelling tried either fuses the first test ('cmp r0,#0 / bne')
  or restores the chain at the cost of size:
        if/else-if chain           784 bytes (EXACT SIZE), 303 differ, fused
        mode cached in a u8 local  784 bytes, 303 differ, still fused
        inner switch, 3 cases      768 bytes, 545 differ
        inner switch, 4 locals     928 bytes, 660 differ
  So the residue is ONE codegen question: what source shape emits an
  unfused three-way cmp/beq chain that still falls through to a fourth
  copy of the arm body.  Everything else about the function is solved.

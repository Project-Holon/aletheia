FINDING 1 -- THE SWITCH TABLE BASE WAS MISREAD, AND THE NOTE ABOVE IS WRONG
---------------------------------------------------------------------------
The mapping in the original note ("case 0 -> 0x0203CD04, case 1 -> 0x0203CD18,
case 2 -> 0x0203CC90 ...") is off by one, because the word at 0x0203CC70 was
counted as table[0].  It is not.  The dispatch is

  0203CC68  cmp   r0, #6
  0203CC6C  addls pc, pc, r0, lsl #2
  0203CC70  b     #0x203cd04        <- NOT table[0]
  0203CC74  b     #0x203cd18        <- table[0]

`addls pc, pc, ...` reads pc as the instruction address PLUS 8, so the base is
0x0203CC6C + 8 = 0x0203CC74 and entry k lives at 0x0203CC74 + 4k.  The word at
0x0203CC70 is the out-of-range fallthrough to the default arm.  The true
mapping is therefore

  case 0 -> 0x203cd18  common tail (break)
  case 1 -> 0x203cc90  vtable arm      case 2 -> 0x203cc90  vtable arm
  case 3 -> 0x203ccc0  beacon arm      case 4 -> 0x203ccc0  beacon arm
  case 5 -> 0x203cd18  common tail (break)
  case 6 -> 0x203cc90  vtable arm
  default -> 0x203cd04  the line-0x8e error arm

and the error arm MUST be spelled `default:`, not `case 0:`.  The same
off-by-one was present in docs/notes/pkt_0203CDD4.c.txt for func_0203CDD4 at
0x0203CDD4; correcting it there took that function from DIFF straight to EXACT
(now src/matched/func_0203CDD4.c), which is the independent confirmation that
this reading of the base is the right one.

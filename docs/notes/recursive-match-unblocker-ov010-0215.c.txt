Target 0x02167848 (blocks func_0217FF78, ov019) -- RESOLVED
-----------------------------------------------------------
0x02167848 is an **unlabelled Thumb leaf** living in ov010.  ov009 holds ARM
data at the address, ov011/ov018/ov019 only call it (their `bl 0x02167848`
sites), and `disasm.py` emitted ov010's body as the `pool_02167844` word run
because the prologue `push {r4, r5}` saves no `lr` (the standard
`unlabelled-leaf-functions-hide-in-word-runs.md` case).  No `func_` label
exists in any overlay, so `label` and `sole-ref/code` cannot fire, and the only
reference image-wide is the call inside func_0217FF78's own range; the only
class that can witness it is `matched`, which needs an EXACT entry.

Prior waves reached it repeatedly as DIFF (34 of 34 bytes) on register
allocation and documented it as an allocator coin-flip.  The lever was the
source shape, not the hints: the 12-byte block is one aggregate
assignment, `struct { u64 lo; u32 hi; }`, which makes mwcc compute the
destination address first and leaves the source pointer in r2:

  0x02167848  34 B  EXACT  ov010.  `*(Blk12 *)(dst+8) = *(Blk12 *)(a2+4)` then
                           the u16 at +0x18 and the u32 at +0x14.  Splitting the
                           aggregate into a `u64` store plus a `u32` store (or an
                           explicit `dst` local, a `u32` index, `Src`/`Dst`
                           structs, an `off` local) moves a2 into r4 and loses
                           the whole range.  See
                           docs/idioms/a-twelve-byte-aggregate-copy-pins-the-destination-first.md.

  func_0217FF78  106 B  EXACT  the original park (ov019).  The +005C call now
                           resolves `matched x1` against the new ov010 entry; all
                           seven relocation sites resolve and the body was already
                           byte-exact.

----------------

Both sites print "declared thumb, no image evidence for the ISA" because
`isa_evidence()` consults only each listing's own `func_` labels, and neither
unlabelled leaf has one; a `matched` overlay entry is deliberately not used for
the ISA check.  The suffix is expected and does not affect the EXACT verdict.

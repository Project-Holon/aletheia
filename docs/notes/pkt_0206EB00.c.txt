wave r4-6, lane 6: 0x0206EC50 (144 bytes) -- structure, 103-byte residue
==============================================================================

Not covered by any earlier note.  It is the "fetch the argument record" walker:
the object is `*(void **)0x02148DB0`, its table sits at +0xD4, the index byte is
`*(u8 *)(*(u8 **)o + 1)`, the entry is
`tbl + t + 4 + k * idx` with t/k the halfwords at tbl+6 and tbl+t, the flags
word is the entry's first halfword (post-increment `ldrh r3, [r1], #4`), bit 0
clear -> skip 0xC, bit 2 set -> straight to the call, bit 8 set -> +4 else
+0x10, and the tail is the function pointer at +0xE8 with the record in r1 and
the incoming r0 forwarded.

Shape written, 136 compiled against the image's 144: the object pointer is
hoisted into ip and reused for +0xE8 (the image's `ldr ip, [ip, #0xE8]`), the
table walk is `q = tbl + t + 4 + k * idx` (the multiplier is the second
operand), the tail is `if (!(f & 1)) p += 0xc; if ((f & 2) != 0) goto call;
if ((f & 8) != 0) p += 4; else p += 0x10;`, and the `add #0xc8` + `add #0x1000`
pair is NOT folded - the two adds are what the image has, so the +0x10c8/-0x10e0
field must be spelled as two nested offsets, not one constant.

Residue: the image emits TWO branches on the same `cmp r4, #0` flags
(`beq 0x0206ECAC` for the outer else, `beq 0x0206EC98` for the inner zero arm),
i.e. its source tests `tbl == 0` twice and keeps both tests; every spelling
written merges them into one branch and then if-converts the whole table walk
(`ldrhlo`/`addlo`/`mlalo`) where the image branches (`bhs`).  103 concrete bytes
differ.  Recorded, not ground further - the sibling 0x0206EBB8 (152 bytes) opens
with the very same double `beq` on one compare, so the two are one finding.

The decisive finding for this packet is that FOUR of its eight functions carry
the "kept branches" front-end tell of docs/FRONTEND-PINS.md at the same place:
the resolve prologue they share emits TWO `beq` on ONE `cmp rX, #0`
(0x0206EBCC/D0/D4, 0x0206EC68/6C/70, 0x0206ECFC/ED00/ED04), and the guard
bodies further down are kept as branches where dsi/1.1p1 -O4,p predicates
them.  Under ../2.0/sp2 the SAME C that 1.1p1 builds four bytes short builds
to the original's length with zero concrete mismatches.

Filed EXACT under the pin this pass:
  0x0206EB00  124 B  src/matched/func_0206EB00.c
  0x0206EBB8  152 B  src/matched/func_0206EBB8.c

The shared resolve is the one already derived in src/matched/unit_0206E394.c,
with the root read from the global stash at 0x02148DB0 instead of a parameter:
  idx = root->hdr->b[1];  bank = root->[0xD4];
  if (!bank) -> node = 0; if (idx >= bank->b[1]) -> entry = 0;
  t = (u8 *)bank + bank->h[6]; entry = t + 4 + (*(u16 *)t) * idx;

Writing `t` as a NAMED LOCAL is what reproduces `mla r2, r1, r3, r2`; folding
the two `bank + off06` reads into one expression flips the mla's dest register
and is the whole difference between DIFF and EXACT on 0x0206EBB8.

0x0206EB00's own tell is the counter zero: dsi/1.1p1 CSEs the loop counter's
`mov r4, #0` into the clear call's first argument and then needs a FOURTH
callee-saved register, giving `push {r4, r5, r6, lr}` against the original's
`push {r3, r4, r5, lr}` at the same 124 bytes.  ../2.0/sp2 rematerialises the
zero.  The second lever, worth 11 bytes on its own, is that BOTH halfword
accesses in the loop must be SUBSCRIPTS on u16 pointers
(`((u16 *)(dst + 0x1A))[i]` and `((u16 *)ix)[i]`); any byte-offset spelling
(`*(u16 *)(ix + i * 2)`, `(i << 1)`, `(i + i)`) lets the compiler
strength-reduce one of them into a separate `ip` cursor and costs one
instruction the image does not have.

--- 0x0206ECE0 (384 bytes): DIFF, 19 bytes, register naming only
Same story one size up: under the pin the source compiles to 384 against 384
with every instruction, every branch target and every relocation right, and
the residue is a three-cycle in the callee-saved names -- the image is
{node = r5, k = r4, u = r7, v = r6} and every declaration order tried gives
{node = r4, k = r7, u = r5, v = r6} (or a rotation of it); `node` always wins
r4 because its live range opens first.

Three shape findings that DID close and are the reusable part:
  * the `f & 2` arm (`out[0] |= 2`) and the `f & 8 == 0` straight-copy arm are
    both written LAST, reached by `goto`; the rotation arm is the source order
    (docs/idioms/the-fall-through-arm-is-the-source-order.md).  Writing either
    as an inline `if` body inverts a branch and costs ~35 bytes.
  * `k` is SIGNED: the image's `asr r4, r2, #4`, not `lsr`.
  * the four permutation tables at 0x020A1998..0x020A199B are ONE table of
    4-byte rows read as four columns.  Declaring them `u8 x[]` and indexing
    `x[k * 4]` lets the compiler CSE `k * 4` into an `lsl` the image does not
    have; declaring `typedef struct { u8 c; u8 pad[3]; } Perm;` and indexing
    `x[k].c` rematerialises `[rN, r4, lsl #2]` at every site, which is what
    the image does, and is worth 24 bytes.
  * the call to 0x020834A8 (thumb, reached by `blx`) takes ONE argument,
    `out + 10`; r6/r7 are loaded before it because they are needed after,
    not because they are passed.

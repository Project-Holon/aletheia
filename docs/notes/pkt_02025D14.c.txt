/*
 * Declaring a Thumb tail-call target as `thumb` in the symbols: block makes
 * the compiler store an ODD pool word (address | 1), because the ABS32
 * relocation for a Thumb function carries the low bit.  A bare tail-call
 * leaf whose original pool word is EVEN (0x0204B3F4, 0x020307B0, 0x020461D4)
 * therefore comes out MATCH with exactly one concrete byte wrong: the low
 * byte of the pool word is +1.
 *
 * Fix: declare the extern `arm` in the symbols: block even though the target
 * is Thumb code.  The compiler then stores the plain even address, which is
 * what the original holds (the linker sets the Thumb bit only for `bl`/`blx`
 * sites, not for a raw ABS32 that a `bx r3` consults).
 *
 * Seen on: func_02025D14 (0x02025D14 -> func_02030164),
 *           func_02021540 (0x02021540 -> func_020307B0),
 *           func_020083EC (0x020083EC -> func_020461D4),
 *           func_020257C4 (0x020257C4 -> func_0204B3F4, still parked).
 *
 * The reverse also bites: a caller that names the target by prefix only
 * (func_02021540, no symbols: entry) is inferred `arm` from the name, so the
 * `matched` witness for a Thumb target will not fire and the site stays
 * wildcarded.  Add an explicit `thumb` symbols: line in that case.
 */

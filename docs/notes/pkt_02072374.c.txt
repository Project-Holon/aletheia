pkt_02072374 - func_02072374 reduced from 17 to 7, register names only
======================================================================

docs/notes/pkt_02071DD4.c.txt records this address as "204 B, DIFF 17,
correct size and instruction sequence, register allocation only", and
docs/notes/pkt_02071B2C.c.txt records the same residue class on 0x02071C14
(13 out, r4/r5 vs ip/lr).  Both notes' levers were taken.  The residue is now
SEVEN concrete bytes, one register pair, and the function is still not filed.

THE ONE LEVER THAT MOVED IT, and it is new for this family: THE TWO `<< 12`
SHIFTED ANGLE VALUES ARE NAMED LOCALS LIVE ACROSS THE WHOLE BODY.  The image
spends `mov r0, fp` / `mov r1, r8` at 0x02072390/0x02072394 and again
`mov r0, r8` / `mov r1, fp` at 0x020723F4/0x020723F8, i.e. it computes
`f2c << 12` into r8 and `f2e << 12` into fp ONCE, before the first
func_0207C930, and re-feeds the SAME two registers to the second call with the
arguments swapped.  That is what forces the ten-register
`push {r3, r4, r5, r6, r7, r8, sb, sl, fp, lr}` (`f8 4f 2d e9`).

Spelling the two calls inline --

    func_0207C930((s32)s->f2e << 12, (s32)s->f2c << 12);
    ...
    func_0207C930((s32)s->f2c << 12, (s32)s->f2e << 12);

-- makes the compiler RE-READ f2c/f2e and re-shift at the second call (`ldrh
r0,[r8,#0x2c]` / `ldrh r1,[r8,#0x2e]` / two `lsl`s at +0x78..+0x84), which
frees sl and fp and gives an EIGHT-register push: still 204 bytes, but 43
concrete bytes out.  Binding them:

    f12 = (s32)s->f2c << 12;
    e12 = (s32)s->f2e << 12;
    func_0207C930(e12, f12);
    ...
    func_0207C930(f12, e12);

takes it from 43 to 13 in one step.  This is the mirror of the "kept constants"
pin tell: here the IMAGE keeps the value live and the naive C rematerialises
it, so the fix is in the C, not in the compiler.

Two more, each worth 2-4 bytes, both from pkt_02071DD4's L1/L3:

  * `q` (the f18*f20 term) IS COMPUTED BEFORE `r` (the f1c*f22 term), with

1. The true extent -- 2770 is a split-label cut, not the function
-----------------------------------------------------------------
`match.py show --addr 0x022040E0 --region ov195` reports
0x022040E0..0x02204BB2 (2770 bytes) because the next `func_` label is
func_02204BB2.  That label is not a real function start: func_02204BB2
(0x02204BB2) has NO prologue, does not save lr, and operates on r4/r5/r6 set by
the root -- it is the root's shared tail reached by both `bl` and `b` from the
body.  The root's real code therefore runs to the `pop {r4,r5,r6,r7,pc}` at
0x02204BB0 and on through the 0x02204BB2 body to the `pop` at 0x02204BB2+0x64
= 0x02204C16; func_02204C24 (0x02204C24, `push {r3,r4,r5,r6,r7,lr}`) is the
first genuine follower.  Real extent ~0x022040E0..0x02204C16 (~2870 bytes,
~1000 Thumb instructions), plus its pools.  The listing is also unreliable past
0x02204112: disasm.py lost sync at the PC halfword switch table and emitted the
case bodies as `.word` runs; `show`/capstone decodes them correctly.

2. What the root is
--------------------
A `switch` state machine dispatched on `[obj+0x28]` through a PC-relative
halfword table at 0x02204112 (0x2d+ cases, guard `bls` -> tail).  The object
is the ov195 field/scene object; the root reads the ARM9 frame tick
(blx 0x02031330) and drives load/enter/update/exit states, calling the scene
object accessors and the ARM9 alloc/timer/render helpers.  106 `bl`/`blx`
sites, 74 distinct targets, no register-indirect calls, no `__FILE__` sites
notable.  The state word at +0x28 and the shared tail make it one function.

4. The root: verdict and why no C was written
---------------------------------------------
VERDICT: report-only.  There is no recoverable source in the tree, and the
root is not a candidate for a C rewrite at this project's scale.  The body is
~1000 instructions of a 0x2d-case load/enter/update/exit state machine over a
large scene object whose field map is only partially recovered (the +0x00..
+0xf4 block is touched directly, plus a PC halfword switch table).  The
project's largest matched bodies are a few hundred bytes (the 2026-09-21
report-only note puts the max matched body at ~604 B); the two big dependency
trees that did close EXACT were 124-137 lines of C, and the largest root ever
attempted (ov121 func_021DEFAC, 1334 code bytes, ~600 instructions) still came
out DIFF on stack layout.  A 2870-byte state machine is 2x that root and 4-5x
any matched body.  Spending the budget transcribing it would be a multi-session
project for zero closed coverage; the honest record is this note.

Attestation is not the blocker for the callees: every unresolved pool site
inside the closed leaves resolves against `literal`/`matched` witnesses outside
the range.  The blocker is magnitude plus the unrecovered scene-object layout.

band lane ov168-191 (LO=128 HI=256) -- DIFF near misses
=======================================================

Two functions were fully reconstructed (semantics and all relocation sites
resolved) but could not be brought byte-identical within budget.  Neither is
parked: a DIFF is not a filing decision.  The shapes are recorded so the next
agent does not re-derive them.

func_021C03C0 = GetLong (ov172, TwlSDK/libssp exifdec.o) -- DIFF 124 vs 128
--------------------------------------------------------------------------
ARM leaf: u32 GetLong(const u8 *p, int off, int big), returning
  p[off] | (p[off+1]<<8 & 0xff00) | (p[off+2]<<16 & 0xff0000) | (p[off+3]<<24 & 0xff000000)
for big==0, byte-reversed for big!=0.  The explicit per-byte masks are real:
mwcc keeps `(x<<n) & mask` after the shift, so the source is not the plain
unmasked OR.  Both arms and the masks reproduce; the two blockers are:

  * the original prologue is `push {r3, lr}` and each arm ends `pop {r3, pc}`,
    with lr used as the p[off] scratch in the little-endian arm.  The compiled
    object is a true leaf (`bx lr`, no frame) because mwcc found a register
    allocation that does not need lr.
  * the original computes `add r2, r0, r1` (q = p+off) before the `bne`, and
    loads p[off] as `[r0, r1]` while p[off+1..3] use `[r2, #n]`; the compiler
    instead strength-reduces to `[r0, r1+n]`.

Tried: q local vs p[off+n] direct; masked vs unmasked; if(!big) vs if(big)
order.  A source spelling that forces the lr scratch and the shared q
register may close it.

func_021DFD24 = scReportSetPlayerData (ov175) -- DIFF 200 vs 216
----------------------------------------------------------------
ARM.  Membership scan `for (i=0;i<ctx[4];i++) if (ctx[5+i]==a3) ...`, append
with overflow `return 5`, then a chain of `if (status==0) status = f(...)`
over 4 callees.  All four relocations resolve (func_021DFF78/FFA0 via sdk,
func_021DFFC8/FFF8 via label).  The compiled size is 16 short and differs only
in register allocation / scheduling:

  * original keeps the loop count in lr and a `notfound` flag in ip (1 =
    not found, cleared on match); compiled keeps count in ip and the flag in
    r2.
  * original does `cmp r1,#0x40` then `str r1,[r6,#0x10]`; compiled stores
    before the compare.

Tried: found (0=absent) vs notfound (1=absent) polarity, and reordering the
locals.  Neither flipped the allocation.  A declaration order that pins lr
for the count may close it.

func_021DD290 (0x021DD290, arm, 32 instruction bytes, DIFF, 37 of 60 bytes)
==========================================================================

Body: latch the +0x28 word, copy the 0x19-byte name from the source into
+0x2c, then set the +0x24 live flag.  Best spelling (reaches the same size, 60)
and the residue, straight from `match.py one --diff`:

    void func_021DD290(char *p, u32 v, u8 *src)
    {
        int n = 0xc;
        u8 *d = (u8 *)(p + 0x2c);

        *(u32 *)(p + 0x28) = v;
        do {
            d[1] = src[1];
            d[0] = *src;
            d += 2;
            src += 2;
        } while (--n);
        *d = *src;
        *(u32 *)(p + 0x24) = 1;
    }

Two distinct differences, both register allocation, not instruction selection:

 1. the destination pointer lives in `lr` in the image (hence the push/pop
    frame) and in a scratch (`ip` here, `r3` for the indexed spelling) on this
    compiler.  In the image the byte temp is `r3`; here it collapses to `r1`,
    which is what frees the scratch register for the pointer.
 2. the image's loop test is the decrement itself (`subs ip, ip, #1; bne`);
    every `--n` spelling here emits `sub; cmp; bgt`.

Four source spellings all reach the same residue (identical instruction
selection, different register roles): a pointer walk (above), an indexed
`p[0x2c + i*2 + 1] = src[i*2 + 1]; p[0x2c + i*2] = src[i*2];` loop,
`for (n = 0xc; n != 0; n--)`, and a `while (--n)` form.  Two others are
required or the body does not even get the right sizes: `p[0x28] = v` must be
`*(u32 *)(p + 0x28) = v;` (a `char *p` store is a `strb`), and the byte
pointers must be `unsigned char *` because the target is built `-char signed`
(`ldrb` in the image, `ldrsb` here otherwise).

Left to try: a struct-typed destination (`*(Name19 *)(p + 0x2c) = *(Name19 *)src;`)
or a walk whose destination starts at `p + 0x2c` but is advanced before the
last byte rather than after, in case the live-range boundary is what pushes the
pointer into `lr` in the original.

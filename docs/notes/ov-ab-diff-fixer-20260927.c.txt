Falsified claim in docs/idioms/argument-register-match-names-a-coerced-extern.md
--------------------------------------------------------------------------------
That idiom says declaring the field `s32` (or the callee's parameter `int`)
"resolves func_021B6984, where `int v = *(s32 *)(p + 0x1c)` puts the dead
comparison temporary in r1 rather than r0".  It does not.  With dsi/1.1p1:

  func_021B6984 (ov180): `int`, `s32`, `unsigned`, `void *`, `int *`, an inline
    expression, an arg of `unsigned`, and a callee parameter of `unsigned` all
    still emit `ldr r0,[r4,#0x1c]; cmp r0,#0` where the image has r1.
  func_021BEA54 (ov210): named u8 local, inline expression, an address local
    reused for both byte reads, and pointer-deref spelling all emit
    `ldrb r0,[r0,#3]; cmp r0,#0xff` where the image has r1.
  func_021BD3AC (ov210): the same shape, `ldrb r0,...` vs `ldrb r1,...`.

The register an argument sits in is a real tell; the register a *dead test
load* lands in under this compiler is not, and the idiom generalised one to
the other.  Treat `argument-register-match...` as unproven for the dead-load
case.

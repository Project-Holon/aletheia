Shape is understood exactly; the residue is allocation, not semantics.

  surface at a0: u32 base @+0, u16 w @+4, u16 h @+6
  xend = min(a1 + a3, w);  yend = min(a2 + a4, h);  rowbytes = (w + (w & 7)) >> 3
  if (a2 >= yend) return;

                       + ((y<<2)&0x1c);

That reproduces every branch, every constant and every mask; the 4bpp tiled
offset arithmetic is confirmed by the masks (0x3fe0 = tile row, 0x1c = row in
tile, (x>>1)&3 = byte in tile row).

What is wrong is only which values live in registers.  The original runs out
of registers and spills BOTH loop-invariants it computed before the loops:

  02044BF4  sub sp, sp, #8                 <- a frame; every spelling tried gives none
  02044C28  ldr sl, [sp, #0x34]            a5
  02044C30  str r3, [sp, #4]               rowbytes, reloaded at 02044C54
  02044C3C  lsl r3, sl, #4
  02044C40  str r3, [sp]                   (a5<<4), reloaded at 02044C60
  02044C4C  ldr r3, [pc, #0x84]            0x3FE0 reloaded from the pool each
                                           outer iteration, not held

and it re-reads the surface's base pointer INSIDE the inner loop
(`ldr r5, [r0]` at 02044C80, every iteration), which only happens when the
field is spelled `volatile` (that variant did move the load into the loop, but
still allocated a5/(a5<<4) into r8/r5 instead of spilling, giving 212 bytes).

Spellings tried, all landing 212-220 bytes against the original 240:
  plain struct member vs `volatile u32` base member;
  rowbytes computed before vs after the two clamps;
  `u8 *p = ...` local vs the address inline at both the load and the store;
  address operands in the original's addition order;
  `int`/`u16` mixes for w, h and a4.

So the missing lever is the source-level one that costs mwcc two stack slots
here.  Every constant, branch and byte of the body is accounted for; nothing
about the semantics is in doubt.  Next agent: the two spilled values are both
loop-invariants computed *between* the clamps and the `if (a2 >= yend) return`,
so a spelling that makes them live across the whole loop (rather than
rematerialised) is what is wanted.

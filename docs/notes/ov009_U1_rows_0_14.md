# Lane U1 — ov009 open SDK rows 0-14 (indices 0..14 of `open_rows.py ov009 0 15`)

Slice: 15 rows, 2,309 bytes, all TwlSDK middleware (`TwlDWC/`, `TwlWiFi_base/`, `TwlWiFi/`).
**Filed EXACT: none.** All 15 re-measured with `tools/match.py one ... --cc 1.1p1 --lang c99 --diff`;

## The one new measurement that matters: the non-dsi compiler families

`sdkobj.py` stamps for the whole slice are only two:

| stamp | rows | our build |
|---|---|---|
| `4.0.0.1024` | 0215D070 0215E6B8 0215F0F0 02158524 02163E40 02166600 02167E20 | `dsi/1.1p1` (we have it) |
| `4.0.0.1025` | 0216980C 021700C8 0217D280 0217D8E0 02195278 021990A0 0219FE44 021A174C | **no build writes this stamp** |

Per the lane brief, every `4.0.0.1025` row was given the once-per-row non-dsi check
`--cc ../2.0/base`, `../2.0/sp1p2`, `../1.2/sp3`. **No row improved**, and `../2.0/base` /

**The 2.0 family is not this slice's compiler.** One near-miss worth recording: `../1.2/sp3`
*does* emit the instruction `021990A0` needs (`mvn r1, #0x80000000`) but its whole codegen family
is different (`stmdb sp!` / `ldm sp!` instead of `push`/`pop`, 68 B vs 52 B), so it is not the build.

Corollary for whoever takes the rest of ov009: the six `4.0.0.1024` rows map to a compiler we
*have*, so their residues are body residues in principle; the `4.0.0.1025` rows are the ones where
a build we do not own is a live suspect. Six of the fifteen are in the second class.

## Per-row residue

**0x0217D8E0 gsLargeIntDiv (36 B, `4.0.0.1025`) — parked.**
First diff `+0004`: image `mov lr, r1` | ours `str r3, [sp]`.
Residue: the argument parallel move. The image saves **both** divisor and dest to temps
(`mov lr,r1` / `mov ip,r2`) *before* the `ldr r1,[r0],#4` length load, then restores them
(`mov r2,lr` / `mov r3,ip`) — 4 moves. 1.1p1 emits the tighter 3-move form: it frees r3 with the
`str r3,[sp]` first, moves dest straight to its final `r3`, and only divisor goes through `ip`.
DWARF (`divisor r14`, `dest r12`) confirms the image's assignment is the vendor's. Not steerable
from the source; identical at `../2.0/base` and `../2.0/sp1p2`.

**0x021990A0 GetClientUniqueID (52 B, `4.0.0.1025`) — parked.**
First diff `+0020`: image `mvn r1, #0x80000000` | ours `sub r1, r0, #0x80000002`.
Residue: one instruction, the materialisation of `0x7fffffff`. 1.1p1 folds the constant against
the already-live `r0 == 1` (`1 - 0x80000002`); the vendor build uses the plain `mvn`. Named:
the `4.0.0.1025` build lacks 1.1p1's constant-from-register peephole. Note `../1.2/sp3` regains
`mvn` but is a different codegen family (68 B, `stmdb`/`ldm`) — recorded above.

**0x02167E20 WcmWmcbSetDCFDataAsync (104 B, `4.0.0.1024`) — parked.**
First diff `+003C`: image `cmp r0, #0` | ours `ldr r6, [r4, #0x2c]`.
Residue: the one-statement then-arm is if-converted. Image keeps a real branch
(`mov r5,#0` / `cmp r0,#0` / `beq` / `mvn r5,#4`) and hoists the `[r4,#0x2c]` load *below* the
branch; 1.1p1 folds the arm to `subne r5,r5,#5` and pulls the load above the compare (100 B vs
104 B). Not retried by this lane beyond re-measuring.

**0x02163E40 CPSi_rc4_init (120 B, `4.0.0.1024`) — parked.**
First diff `+0010`: image `add r4, r0, #2` | ours `add lr, r0, #2`.
Residue: a pure four-register mirror — image `m`=r4, `m_i`=lr, zero-temp=r0, chain=r3;
ours `m`=lr, `m_i`=r4, zero-temp=r3, chain=r0. Every opcode is already right. Re-measured this
lane: four more declaration permutations (`m` last, `m` first, `m_i` first, `m` folded into the
char declarator) all stay at 21 B; `m` last and the folded form rise to 32 B.
DWARF order (`m_i, k, j, m, i`) does not reproduce the vendor's assignment.

**0x02166600 WCMi_MergeToBuffer (128 B, `4.0.0.1024`) — parked.**
First diff `+000C`: image `cmp r0, #1` | ours `mov r6, r1`.
Residue: 8 B short. The image tests `deviceId==1` / `==2` first and only then materialises
`mov r6, r1` in the default arm; every switch spelling this lane and w9 tried hoists `mov r6, r1`
above the compares and if-converts the `case 2` byte-swap. Not retried.

**0x0215F0F0 SOCLi_IsIPv4ValidDNSAddr (148 B, `4.0.0.1024`) — parked.**
First diff `+0000`: image `push {r4, lr}` | ours `push {r3, r4, r5, lr}`.
Residue: cross-condition CSE. The image **rematerialises** `(addr ^ dns) & netmask` in isB
(`eor r2,r2,r1` / `tst r0,r2`) and every flags test is a bare `tst`; 1.1p1 CSEs the AND across
isA/isB into a live `r5` (`ands r5, r0, r2`), which is also what forces the extra `r5` on the
stack (152 B vs 148 B). Re-measured this lane: swapping the XOR operands
(`(m & (a^d))`, `(d^a) & m`) and an empty-then/else spelling are all canonicalised — still 99 B
of diff. The register the value is cached in is not steerable from the expression.

**0x021700C8 DWCi_EncodeBinaryMsgCommand (160 B, `4.0.0.1025`) — parked.**
First diff `+0030`: image `ldr ip, [pc, #0x64]` | ours `ldr r0, [pc, #0x64]`.
Residue: a register rotation over the same 20-instruction body. Image: id-pool base in `ip`,
`len*4` in `r0`, byte temps `r2`/`r3`, the `0x5a` literal in `r1` (stored with `str r1,[r5,#4]`).
Ours: base in `r0`, `len*4` in `r1`, temps `ip`/`r3`, literal in `r2`. All 20 concrete bytes are
register fields; no opcode differs. Not steerable from the source (`len *= 4`, `len << 2`, a u8
local, five store orders already tried in w8/w9).

**0x0215E6B8 SOCL_Shutdown (172 B, `4.0.0.1024`) — parked, but the 80-byte residue is now named to the instruction.**
First diff `+0004`: image `mov r4, r0` | ours `mov r5, r0`.
1. image `mov r4, r0` (param `s` -> r4) | ours `mov r5, r0` — DWARF agrees with the image
   (`param s r4`, `variable send_pipe r5`); the two registers are transposed, ours allocating the
   declared local before the parameter. Not declaration-driven (w10_t2 tried all four permutations;
   this lane re-ran the inverted-guard body and got the same transposition).
2. image `ldrsh r0, [r4, #0xac]` before `orr r0,r0,#8` | ours reuses the flags still live in `r0`.
   **New this lane: the image's four separate `ldrsh r0,[r4,#0xac]` reads are explained by
   `volatile short flags;`.** With the member marked volatile, the compiled size becomes *exactly*
   172 B (from 164), i.e. the missing reload appears; the remaining diff is the same boolean
   materialisation. Measured: `volatile short flags` + the committed body = 172 B / 126 concrete;
   `volatile` + inverted guard = 176 B / 138; `volatile` + `result = (a && b)` / nested-if /
   `if (!result)` spellings all give the identical 172 B / 126.
3. image `movne r1, #1` (bool home r1, `mov r1,#0` scheduled before the null test) | ours
   `movne r0,#1` / `bne` / `mov r0,#0` (bool home r0, select-with-branch). Same class of residue as
   `0215D070` below: the vendor build predicates a boolean into a low scratch register, 1.1p1
   selects through the return register. The inverted-guard spelling
   (`if (pipe != 0 && pipe->queue != 0) { ... } return 0;`) *does* restore the image's real branch at
   the pipe guard (`beq` to a shared `mov r0,#0; pop`, per
   `docs/idioms/a-bare-constant-return-guard-is-predicated-unless-its-exit-is-shared.md`) —
   168 B instead of the predicated 164 B — but the `+= 4` it recovers is spent on the two
   register residues above.

## Bottom line

No row in this slice is closer than one instruction (021990A0, 0219FE44, 0215D070) and none of the
three closes from the source: in each case the image's instruction is a *different encoding of the
same value* that the project's front ends pick differently (`mvn` for a foldable constant, a
predicated `movne` for a materialised boolean, a commutative eor's operand slots). The compiler
axis is now documented for all eight `4.0.0.1025` rows of the slice and is dead:
`../2.0/base` and `../2.0/sp1p2` are byte-identical to `dsi/1.1p1` or worse on every one of them,
and `../1.2/sp3` is a different codegen family entirely (`stmdb`/`ldm sp!`).

func_0202EE0C - `((d - c) - e) << 8` times `b`, divided by `a`, then folded onto
`c` and `e >> 1`. The divide is unsigned, so it reaches 0x0209C2B0 (recorded in
layout/runtime_arm9.txt as `_div_by_zero_check`):

    u32 func_0202EE0C(u32 a, u32 b, u32 c, u32 d, u32 e)
    {
        u32 t = ((d - c) - e) << 8;
        return (_div_by_zero_check(t * b, a) >> 8) + c + (e >> 1);
    }

Residue (the four instructions after the call, same length):

    +0018  lsrs r2, r0, #8       | ldr r1, [sp, #0x10]
    +001A  ldr r0, [sp, #0x10]   | lsrs r0, r0, #8
    +001C  lsrs r1, r0, #1       | lsrs r1, r1, #1
    +001E  adds r0, r4, r2       | adds r0, r4, r0

The original shifts the quotient before re-reading the fifth argument; this front
end re-reads the argument into r1 first because the quotient is still live in r0.
Ruled out: binding the quotient to a named `u32 q` local, and the
`c + (q >> 8) + (e >> 1)` order.

once, before the loop, while the per-iteration branch returns to 0x0216FEB8's
next instruction. A plain

    for (i = 0; i < 0x30; i++)
        if (func_0216FE2C(a, i, b, c) == 0) n++;

second `n < 0x30` term (`&&`, either order, `for` or `while`) puts the second
guard in the loop (46 bytes) but still not the entry-only shape. Tried the
plausible spellings of the second condition and both declaration orders; none
reaches 42 bytes. This is a front-end loop-rotation artefact, not a wrong
reading of the body; a permuter run is the next thing to try, not another
hand spelling. Nothing filed.

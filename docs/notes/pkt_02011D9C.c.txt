== 2026-09-24 wave 21, lane H2: what the three BLX targets are ==

Answer: 0x021882A0, 0x02188354 and 0x02188390 are genuine ARM entry points
in ov230, but ov230 stores them ENCRYPTED; they are plain code only after
ov230's own static initialiser has decrypted them in RAM.  No listing can
label them from the stored bytes without labelling ciphertext, so the
function stays MATCH in src/pending.

1. Decoding.  Image halfwords at the sites: +0x20 F176 EA70, +0x48 F176 EAB6,
   +0x72 F176 EAC0.  First halfword 11110 (offset high, 0x176 -> +0x176000),
   second 11101 = BLX (to ARM; the H bit pattern 11111 would be BL/Thumb).
   Targets recomputed: 0x02011DC0+0x176000+0x4E0 = 0x021882A0,
   0x02011DE8+0x176000+0x56C = 0x02188354, (0x02011E12+0x176000+0x580)&~3
   = 0x02188390 (BLX clears bit 1).  All word aligned, all ARM.  Not Thumb.
2. Overlay context.  The only reference to 0x02011D9C is the pointer
   0x02011D9D at 0x0209DF9C, first of an {init 0x02011D9C, main 0x02011EAC,
   exit 0x02011EC0} proc triple.  The function itself calls
   sub_02034AC4(ov230_id) immediately before the first probe and
   sub_02034A5C(ov230_id) after the third (both OVERLAY_ID_CONSUMERS,
   overlay_id class already attested).  sub_02034AC4 reaches FS_LoadOverlay
   (0x02079264), which calls FS_StartOverlay (0x0207902C, bl at 0x020792A4),
   i.e. runs the overlay's static-initialiser table.  ov230's image
   [0x02187F00,0x021899A0) covers all three targets, so whatever was loaded
   before, the bytes executed at the three BLXs are ov230's.
3. Other regions.  Every y9 entry whose [ram, ram+size+bss) covers the
   targets: ov009 (0x02155160+0x53100+0x68C0), ov021 (0x02187F00+0x56800
   +0x10040), ov096 (0x02187F00+0x28C0+0x20), ov230 (0x02187F00+0x1AA0+0x20).
   No fifth.  match.regions_containing() agrees; twl window
   0x02700000..0x02732DA0 does not cover them (no DSi key needed).
4. ov009 is not it.  0x021882A0 is `cmp r0,#0` right after
   `bl func_02193418`; 0x02188354 is the `bl func_0217F1E0` one instruction
   after loc_02188350 (which sets r0 = sp+0x14; entering at +4 would drop
   it); 0x02188390 is `mov r1, r5` right after `mov r5,#1` at 0x02188384.
   No return or pool precedes any of them.  Also the caller keeps r5 as its
   own flag (movs r5,#0/#1 right before each BLX); callee-saved, it is no
   argument, so the "continuation" reading has no support.
5. The ov230 mechanism (traced from asm/overlays/ov230.s, then emulated).
   ov230's sinit table (y9 sinit 0x02189974..0x0218998C) = 0x02188408,
   0x021889B0, 0x02188CB0, 0x02189448, 0x02189908.  Each is
   `orr r0,pc,#0; adds r0,r0,#4; bne loc_02188A48` followed by a table of
   (start+0x1600, ...) pairs.  loc_02188A48 walks the table: range =
   [w0-0x1600, w0-0x1600 + ((w1 - 0x021899A0 - 0x1600) & ~3)), key reset
   to 0xF0618C46 per range; words func_02188A0C classifies as B/BL/BLX get
   their offset field adjusted by 0xFFFFFA7E and top byte toggled, others
   are XOR-decoded with a rolling key; then func_021889E4 flushes the
   cache over the range.  Table of 0x02188408 (0x02188414..0x02188443):
   0x021898A0, 0x021898DC, 0x02189918, 0x02189954, 0x02189990, 0x021899CC
   (each paired with 0x0218AFC4) -> ranges of 0x24 bytes at 0x021882A0,
   0x021882DC, 0x02188318, 0x02188354, 0x02188390, 0x021883CC.  The three
   targets are entries 0, 3 and 4 of that table, exactly.
   Decrypted, each 0x3C-byte slot is a complete thunk:
     orr ip,pc,pc; ands ip,ip,ip; moveq ip,#0; addne ip,ip,#0x1C;
     ldr ip,[ip,#0x14]; sub ip,ip,#0x1600; stmdb sp!,{ip};
     orr ip,pc,pc; ldm sp!,{pc}
   followed by a 6-word parameter block (third word per slot:
   0x02189500/0x021895A0/0x02189640/0x021896E0/0x02189780/0x02189810, i.e.
   the encrypted bodies at 0x02187F00.. after -0x1600; last word 0x0218A260
   -> dispatcher 0x02188C60).  The dispatcher (itself a decrypted range of
   sinit 0x02188CB0) is `push {r0-r3}; ... bl 0x02188B48 (decrypt body);
   pop {r0-r3}; blx ip; ... bl 0x02188BD0 (re-encrypt); bx lr`, so the
   caller's r0..r2 (start, end, 0) pass straight to the body.  Every slot
   ends in `ldm sp!,{pc}`: nothing falls into the next one.  Scratch
   emulator: /tmp/aletheia_laneH2/decrypt230.py.
6. What match.py allows.  Region hints tested on scratch copies
   (ov009, ov021, ov096, ov230, twl, none): all MATCH, 22 of 25, the three
   sites unresolved (the message text is the same whatever the hint): no

   Mechanical test only: disasm.py overlay 230 with a scratch layout whose

   arm` does emit func_ labels, and match.py one with ov230's listing

## Wave 21, lane T (tools): ov230's decryptor in the pipeline

replays ov230's static-initialiser decryptor.  The decryptor bytes are
SHA-1 checked, the parameters come from its own pool words and immediates,

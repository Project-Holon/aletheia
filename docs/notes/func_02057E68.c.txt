two s16 key values at _00/_02/_04 and two u8 breakpoints at _06/_07. Below
the first breakpoint it interpolates _00 to _02 over [0, _06]; between the

label class, 152 witnesses), so the divisors are runtime values, not the
magic-multiply form.

Under -O4,p -proc arm7tdmi the C at the end gives the same logic, the same
predicated early returns (ldrshlt / strhlt / bxlt lr), the same operand
order in both mul, and the same rsb r1, r3, #0xff. Two differences remain:

1. push {r4, r5, lr} + sub sp, sp, #4 in the original against
   push {r3, r4, r5, lr} in every compile. mwcc 1.1p1 never emits an
   explicit 4-byte alignment sub: with an odd saved-register count it
   pushes a free caller-saved register as padding instead. Checked across
   dsi/1.1 through dsi/1.3p1, -O0 through -O4 in both p and s, -align8,
   -proc v4/v4t/v5t/v5te/generic/arm9tdmi/arm920t/arm7ej/arm9ej, C and
   C++, an unused fourth parameter, and unused locals of scalar, array,
   struct and long long type. Every function in this translation unit with
   an odd saved-register count has the same explicit sub sp, sp, #4
   (0x02056460, 0x02057AB8, 0x02057B10, 0x02057B5C, 0x02057E68), and every
   function with an even count has no stack adjust at all, so this is a
   property of the unit's build, not of one function's locals. Nothing in
   any of them ever reads or writes the reserved word.

2. The second breakpoint ldrb r3, [ip, #7] is loaded up front in the
   original, next to ldrb r1, [ip, #6], rather than inside the second

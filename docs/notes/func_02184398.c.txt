WHAT IS CLOSED
--------------
The 0x120 work-buffer size is kept live in a callee-saved register across the
two allocating calls, so the original spills `c` to [sp+4] and derives
`p[2] = size - 0x20` with `subs rN, #0x20`.  Written with
`unsigned int size = 0x120;` mwcc constant-folds `size - 0x20` to 0x100,
drops the live size register, keeps c in r7 and emits 104 bytes (93 out).

Typing the size as an enum defeats the fold:

    typedef enum { SIZE_0 = 0x120 } SizeE;
    SizeE size = SIZE_0;

That is the same lever docs/idioms/an-enum-type-keeps-values-out-of-constant-
folding.md records for loop counters; here it applies to a size used as a call
argument and then decremented.  With it the compile is 112 bytes and every
instruction is present.  The two `(unsigned short)a` narrowings also need
func_02006CBC and func_02030734 declared with an `unsigned short` first
parameter (instead of an explicit cast at the call), otherwise the cast is
CSE'd into one register.

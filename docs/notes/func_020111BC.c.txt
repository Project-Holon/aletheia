func_020111BC (0x020111BC, packet pkt_020111BC) - DIFF, two residues and
fifteen spellings
================================================================================

34 bytes of code, 44 with its two pool words.  Nothing about the shape is in
doubt: a byte at +0x1e of one global gates the body, and the body is one
64-bit multiply followed by a divide by 100, both of which are calls to the
compiler's own runtime helpers.

The multiply takes the u16 first (r0:r1, high word zero because a u16 promotes
to a non-negative int) and the argument second (r2:r3, sign extended) - so the
expression is `v * (s64)a0`, not `(s64)a0 * v`.  The `_ll_mul` pool-word name
and the `_ll_divmod_body` address both come from layout/runtime_arm9.txt (see
docs/idioms/consecutive-ll-udiv-calls-are-one-chained-64-bit-expression.md);
the compiler emits `_ll_sdiv` for the divide, so the symbols block pins
`_ll_sdiv 0x0209BE5C arm` - the same address under the other name, exactly the
move that file describes for `_ll_mul` / `_ull_mul` at 0x0209C054.

The best spelling found is

48 bytes compiled against the original's 34, 20 concrete bytes differ, and the
residue is two separate things:

1.  **The guard's registers.**  The original loads the address into r1 and the
    byte through r1, keeping r0 (the argument) live until the `adds r2, r0, #0`
    in between; every spelling here loads the address into r0 and the byte
    through r0, because the compiler has already committed the argument to r2
    before the load and is free to reuse r0.  Five bytes, and no spelling
    moves it: reading the byte into a `u32 b` local first, the `!= 0x30` /
    inverted-guard form, binding `s64 t = (s64)a0` before the guard, and
    putting the byte load after the argument copy all give the same order.

2.  **The truncation of the 64-bit quotient to the 32-bit return type.**  The
    original returns the quotient's low word directly (`pop {r3, pc}`), so the
    division's result is the last thing the function computes.  Every spelling
    that keeps the value live - `return (u32)(...)`, `return (s32)(...)`, a
    `u32 r` local, an `s64` local, a `union`, a non-volatile local - emits two
    extra instructions before the pop,

        adds r2, r0, #0
        adds r0, r2, #0

    which is mwccarm's register-pair copy for "take the low word of this 64-bit
    value".  The only spelling that makes the truncation free is a *store*
    (`out = (s32)(...)` into a volatile local reproduces the function exactly
    at 44 bytes, the original's extent, and differs by the store alone) -
    which is what the matched example in the idiom file above does, storing
    into a struct field.  There is no store in this function.

So: 34 of the original's bytes reproduce in every spelling, and the two
residues are a register choice and a 64-bit-to-32-bit return conversion.  The
function is worth one more look only with a spelling that both keeps the
argument in r0 across the guard load and returns the low word of a 64-bit
quotient without a copy.

Fifteen spellings tried, all DIFF, none smaller than 20 concrete bytes:

  `(s64)a0 * v / 100`; `v * (s64)a0 / 100`; `(s64)(u16)v * a0 / 100`;
  `(u64)(u16)v * (s64)a0 / 100` (needs a u64 typedef, the spelling that first
  resolved all four sites); `(void)(...)` (the whole expression is removed as
  dead and the function comes out 12 bytes); a `s64 v` local; a `u32 r` local

  `_ll_mod` pinned at the same address; the inverted guard; the byte in a
  `u32 b` local; the guard as `!= 0x30` with the division in the arm.

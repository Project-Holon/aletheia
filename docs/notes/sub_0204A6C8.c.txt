WHAT IT IS
----------

(top bit of +0x3C set), build the object for it, publish it through
func_0204E0D0, then clear the pending mark and the counter at +0x24.
The slot index is the return value; -1 means nothing was waiting.

The owner block sits 0x104 bytes into the object at 0x02146A74 and
carries two tables side by side: the 0x40-byte one at +0x08 with its
count at +0x14 (this function), and a 0x18-byte one at +0x0C with its
count at +0x16 (sub_0204AC18, the twin).  src/matched/func_0204E0D0.c
already named the 0x40 stride and the +0x3C status word; the `>> 31`
here is the other half of its `& ~0x80000000`.

WHAT IS PINNED, AND HOW MUCH IT COST
------------------------------------
Four spellings are forced, and between them they took the residue from
44 bytes to 4.  All four transfer to the twin, sub_0204AC18, which they
close outright (that file is byte-correct, parked at MATCH in
src/pending only for a missing witness, not for codegen).

  `count` is `volatile`.  The loop reads it from memory on every
  iteration (`ldrh r4, [r7, #0x14]` inside the body, after the entry test
  has already read it) while the table pointer beside it is hoisted once.
  Without `volatile` the compiler hoists the count as well and the loop
  is four bytes short, with a register renaming cascading through the
  rest of the function.  This is the reverse of the reading in
  docs/idioms/a-global-reread-across-a-call-to-a-visible-static-needs-
  volatile.md: there is no call in this loop at all, so nothing but the
  qualifier can keep the load alive.

  The outer pointer must be bound to a local (`sys`) and re-used after
  the loop for the slot address.  That keeps it live across the loop,
  which is what makes the compiler read the table once as +0x08 off the
  owner and once as +0x10C off the outer object.  Dropping `sys` and
  spelling the slot as `&owner->slots[i]` loses the outer pointer's live
  range and costs 26 bytes of register renaming.

  The not-found value is reached by falling out of the loop, so the exit
  from the body is `goto` past `i = -1`, not `break` followed by
  `if (i >= owner->count) i = -1;`.  The second form emits an extra count
  read (now that the field is volatile it cannot be folded away) and a
  predicated `mvnhs` where the original has a plain `mvn`.

  The first `return` returns the literal -1, not `i`.  The original's
  `moveq r0, r4` takes the register holding the -1 the comparison just
  built, not r5 which holds `i`.  The twin is the opposite (`moveq r0,
  r4` there is `i`), so each function's own bytes decide this and the two
  must not be made to look alike.

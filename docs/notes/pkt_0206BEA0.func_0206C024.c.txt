THE DOUBLED `beq` IS SOLVED.  The note's own tell -- "the doubled `beq` on the
same flags in the original is the tell that the source had both
zero-assignments as separate statements" -- was half right.  It is one
statement: an INLINED helper whose own `if (t == 0) return 0;` the compiler
kept even though the caller had already tested the same pointer.  The twin
function func_0206BEA0 at 0x0206BEA0 makes this unambiguous, because there the
helper's argument is `rec + 4` rather than `rec`, so the redundant test shows
up as `adds ip, lr, #4` / `beq` -- a test on a value that cannot be zero.  The
helper is written out in docs/families/cluster_0206BEA0.h as
`gx_rec_lookup()`.  It must be spelled INLINE at the call site with the
redundant null test kept; written as a real `static`, 2.0/sp2 emits an
out-of-line `bl` (112 bytes, 58 out).

THE ZERO ARMS ARE `goto`s, NOT if/else.  Same finding as on the twin: with
if/else, 2.0/sp2 if-converts each zero arm to a predicated `moveq`/`movhs`
beside its branch (8 bytes short, value in the wrong register); with explicit
`goto`s to one shared zero label per lookup the image's `b` / `mov r2,#0` /
`cmp r2,#0` triple reproduces.  On func_0206BEA0 this was worth 36 concrete
bytes.  It was NOT separately re-measured on func_0206C024 in this wave --
the twin took the budget -- so the first thing the next lane should do here is
transplant the shape from func_0206BEA0's best source (appended to
docs/notes/pkt_0206BEA0.c.txt) onto this function, whose only structural
differences are the missing `+ 4`, the +0xdc base instead of +0xd8, the
tbl_020A82D8 table instead of tbl_020A82C8, and the simpler three-bit gate.

pkt_0206164C -- near miss, 10 concrete bytes, register assignment only.

0x0206164C and 0x0206168C (60 bytes each, exact mirrors) copy five 2-word pairs
between the caller's buffer and the table of 0x18-byte records at 0x020A816C.
Every instruction reproduces; the residue is which of three loop quantities
gets which register.

    original:  r3 = i,  ip(r12) = t (the table pointer),  lr = j (the dst index)
    this C:    r3 = i,  ip = j,                            lr = t

so `add ip, ip, #0x18` / `add lr, lr, #2` come out swapped while the
`str r1, [r0, lr, lsl #2]` / `add r1, r0, lr, lsl #2` pair is byte-identical.
The best spelling is

```c
int i;
int j = 0;
struct Ent *t = g_020A816C;
for (i = 0; i < 5; i++) {
    dst[j] = t->w[0];
    dst[j + 1] = t->w[1];
    j += 2;
    t++;
}
```

Declaration order moves the residue but never removes it: (t,i,j) 15 bytes,
(i,j,t) 10, (j,i,t) 13, `j` uninitialised and assigned before the loop 10, `t`
typed `u32 *` with `t += 6` 10, `t` as the last declaration 15, walking the
destination with `*d++` 37, plain `dst[i*2]`/`g[i].w[...]` indexing 59,
`dst[i*2] = ...` with `t += 6` and no `j` 41.

The 10-byte version differs only in those two `add`s, so the range is
otherwise complete; the pointer-to-`lr` preference is an allocator decision.

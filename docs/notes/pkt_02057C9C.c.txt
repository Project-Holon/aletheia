What the function is: a two-segment RGB555 colour keyframe blend.

    func_02057C9C(struct Out *out, struct Ctx *ctx, s32 t)

    ctx->f00  struct Node *   the live rig node; its u16 at +0x22 is the
                              current colour
    ctx->f08  struct Key *    the keyframe record
    out->f36  u16             where the result is written, by all four exits

    key +0x00 u16 c0    +0x02 u16 c1
        +0x04 u8  t0    +0x05 u8  t1    +0x06 u8  t2    +0x08 u16 flags

  t <  t0   -> out->f36 = k->c0                       (predicated, `lt`)
  t <  t1   -> blend k->c0 towards node->col          (predicated exit, `eq`)
  t <  t2   -> blend k->c1 towards node->col          (predicated exit, `eq`)
  otherwise -> out->f36 = k->c1

Each blend is the same five-bit-per-channel shape: mask the three channels of
both colours with `& 0x1f` after an `asr` by 0 / 5 / 10, then per channel
`base + (t - ta) * (target - base) / (tb - ta)`, the division being three
separate `bl _s32_div_f` calls in the order BLUE, RED, GREEN (0x02057D44,
0x02057D58, 0x02057D6C). The reassembly is `r | (g << 5) | (b << 10)`.

TWO TELLS SETTLED FROM THE BYTES:

  * The flag test is `lsrs r4, r4, #0x1f` at 0x02057CFC -- a LOGICAL shift --
    after `lsl r4, r0, #0x1d`. So the flags field must be read into an
    UNSIGNED variable: `s32 f` gives `asrs` and is wrong. When bit 2 of the
    flags is clear the blend is skipped entirely and the (already masked and
    reassembled) colour is stored by the predicated `eq` exit.
  * Which colour that short-circuit exit writes is NOT the same in the two
    segments. In the first it writes the NODE's colour (`orreq r1, sb, r7,
    lsl #5` with sb/r7/r0 all derived from node->col at 0x02057CDC); in the
    second it writes the KEY's c1 (`orreq r1, r7, r5, lsl #5` with r7 from
    `ldrh r7, [r4, #2]` at 0x02057D9C). Writing the same one in both costs
    the whole second half.
  * In the first segment the three MASKS of the base colour land AFTER the
    predicated exit (0x02057D14..0x02057D20) while the three SHIFTS land
    before it; declaring all six as initialisers in one run reproduces this,
    declaring the base's three after the `if` does not.

THE RESIDUE, 8 bytes, and it is the frame. The image is
`push {r4..fp, lr}` (NINE registers) plus `sub sp, sp, #4`, i.e. exactly one
spill slot, and each of the four exits pays one `add sp, sp, #4`. Under
`../1.2/sp2 -proc arm7tdmi` the same C gets the nine-register push and the
`sub sp` -- the frame SHAPE is right, and offsets +0x30/+0x34, +0x8C/+0x90 and
+0xA4/+0xA8 line up byte for byte -- but the frame is `#0xc`, three words, so
1.2 spills two more values than the image does. The image keeps all three
division results live in registers (sb, r7, r0) across the two remaining
calls; 1.2 spills one (`str r0, [sp]` at 0x02057D48's offset) and 1.1p1
collapses the frame to `push {r3, r4, ...}` + `#0x1c` and loses 28 bytes.

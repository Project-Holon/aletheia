WHAT IT IS
----------
A scaled-span helper.  The span (a3 - a2 - a4) is raised eight bits,
multiplied by the caller's rate a1, divided by the total a0 and shifted back
down; the quotient's top bits join a2 and half of a4:

    u32 func_0202EE0C(u32 a0, u32 a1, u32 a2, u32 a3, u32 a4)
    {
        return a2 + ((a1 * (((a3 - a2) - a4) << 8)) / a0 >> 8) + (a4 >> 1);
    }

The division is the *unsigned* runtime helper, and that is the one real
finding here: the image's call target is 0x0209C2B0, which
layout/runtime_arm9.txt names `_div_by_zero_check`, but the code at that
address is not a check - it is the unsigned divide entry (`cmp r1,#0; bxeq
lr; cmp r0,r1; movlo r1,r0; ...` and then the restoring-division body), and
it returns quotient in r0 and remainder in r1.  It is `_u32_div_f` in this
front end's own naming: `unsigned / unsigned` emits exactly this target, while
`signed / signed` emits `_s32_div_f`, which is the routine at 0x0209C0A4 that
sign-fixes both operands and branches into the body at 0x0209C29C.

Declaring `_u32_div_f` at 0x0209C2B0 in the file's `symbols:` block resolves
the site (class `runtime`), and the whole expression then compiles in the
right shape - the guard, the shift, the multiply, the divide, all four
instruction groups land where the original has them.

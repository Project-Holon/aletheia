## ARM functions are the bulk of ov172's SHARD-OK stratum

Of the 69 READY rows, 19 have every ov172 callee already shard-recorded, and 14
of those 19 are **ARM** (the rest of the lane's machinery assumed Thumb).  The
compile is `--arm` with the same `--cc dsi/1.1p1`; the listing's `/* addr BYTES */`
column distinguishes them: four bytes per instruction (`.` word` order
little-endian, e.g. `08 40 2D E9` = `push {r3, lr}`) versus two for Thumb.

## What closed these two, and what did not

1. **A shared out-of-line `return`/tail block is the tell for a `break`-shaped
   case, not a `return`.**  `func_021C2AD0` is a mode validator.  Written with
   `if (ok) return 1; return 0;` in each of its three cases, CW if-converts the
   tail (`moveq r0,#1; bxeq lr`) and the function comes out 4 bytes short.  Written
   instead with `if (bad) return 0; break;` per case plus `default: return 0;` and
   a single `return 1;` after the `switch`, the three success paths share CW's
   out-of-line tail and the whole 164-byte body reproduces byte for byte.  The
   image's own shape is the evidence: all three cases branch to ONE
   `mov r0,#1; bx lr` at the end of the function, while each case keeps its own
   `mov r0,#0; bx lr` as the fall-through of its second test.
2. **Guards joined by `||` share one fail block; separate `if (x) return 0;`
   statements get one fail block each.**  `func_021C2AD0`'s four range guards all
   branch to the same 0x021C2AF4, so they are one
   `if (a0 == 0 || a0 > 0xffff || a1 == 0 || a1 > 0xffff) return 0;`.  Split into
   two statements the same function comes out 12 bytes long.
3. **A struct field read as `s32` while the load is `ldrb` is what produces
   `asr`.**  `func_021BF610` shifts `g->byte` right by the bit counter and the
   image has `asr r0, r0, r1`, not `lsr`.  Declaring the field `int`/`s32` (the
   stored value stays a zero-extended `ldrb` result, so nothing else changes) is
   the whole fix.
4. **Dereference the global at every site, do not cache it in a local.**  The same
   function loads its pool word three times (0x021BF614, 0x021BF660, 0x021BF66C):
   once for the initial test, again at the inner join (`bits = 8`), again in the
   tail.  A `BitState *st = g_021C88F0;` local produces one load and a body 8 bytes
   short; writing `g_021C88F0[0].field` at each use reproduces all three.
   The cursor update must also be `*a1 = i + 1;` before the byte load and
   `(*a1)++;` inside the escape branch -- `*a1 = i + 2` is one byte off at +0x38.
5. **The ov172 data page rule (O65's) held again, from the other direction.**
   `g_021C88F0  ... data ov172` is refused as contested; the identical source with
   the token deleted is EXACT with `sole-ref x1`.  `g_021C719C` resolves sole-ref
   *with* the token, so the order is: try the token, drop it on the contested
   message.

# Lane O85 (ARM-first drain) -- filed 2, residues for 3

Filed under `pkt_021C2AD0` and recorded by `manifest --verify --shard`:

| function | address | bytes | isa | verdict |
|---|---|---|---|---|

| func_021B8130 | 0x021B8130 | 36 | thumb | EXACT* |

## The pool-global rule is a `volatile` declaration

O75's finding 4 ("dereference the global at every use site") reproduced only when
the global is declared `volatile`.  `func_021C1248` reads the limit at +8 of
`g_021CADE4` in a pre-check and again after the first copy loop; with
`extern u32 g_021CADE4[];` CW CSEs the load, the second guard reuses the first
one's register and the body is exactly 8 bytes short (164 vs 172).  With
`extern volatile u32 g_021CADE4[];` both sites reload the pool word and the
function is byte exact on the first try.  Use this whenever two reads of the same
global are separated by code that stores nothing to it.

**Caveat:** `volatile` also forbids the LDM/STM merge, so it is the wrong tool for
a function whose two adjacent field reads compile to `ldm`/`stm` (see func_021C0C3C
below).

## Bit tests written as mask pairs do not reproduce: use the shift pair

`func_021B8130`'s image is `lsls r0,r0,#0x1e; lsrs r0,r0,#0x1f; bne`.  The source
is `if ((((u32)a1[0x2d] << 30) >> 31) == 0) return 1;`.  Written as
`(a1[0x2d] & 2)` it comes out `movs r0,#2; tst r0,r2`; written with a *signed*
carrier it comes out `asrs` instead of `lsrs` (that one byte pair is the whole
residue).  The `== 0` orientation also matters: `if (cond) {...} return 1;` makes
CW invert the branch (`beq` past the tail) and costs the layout.

## `g_021C4D10` is contested with a token and resolves without one

`func_021B6ADC` and `func_021B6B68` both read the signed-byte table at
`0x021C4D10`.  `g_021C4D10  0x021C4D10  data   ov172` is refused ("the ov172 hint
is contested"); the same line with the token deleted resolves `sole-ref x1`.  Both
sources then compile with every relocation witnessed.

## Untouched ARM rows, in the order they should be tried

and is the one ARM row of that family still open: it reads g_021CADE4[0] and [1]

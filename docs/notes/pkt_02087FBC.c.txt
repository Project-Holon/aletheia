CORRECTION TO THIS NOTE'S MAIN FINDING.  The paragraph above concludes that
"mwcc 1.1p1 will not emit a two-register ldm/stm pair at this size" and that
"the threshold for the ldm/stm form is between 8 and 12 bytes".  That is not
right, and it sent the earlier pass down a dead end.  mwcc 1.1p1 -O4,p
-proc arm946e DOES emit the pair for an 8-byte copy -- but only for a BARE
`unsigned long long`, not for a struct that wraps one.  Measured directly,
each of these compiled on its own at this address:

    void c_u64 (u64 *d,  u64 *s)  { *d = *s; }
        -> ldm r1, {r2, r3} / stm r0, {r2, r3} / bx lr      <-- THE IMAGE'S FORM
    void c_pair(Pair *d, Pair *s) { *d = *s; }   /* struct {u32 a,b;} */
        -> ldr r2,[r1] / ldr r1,[r1,#4] / str r2,[r0] / str r1,[r0,#4]
    void c_tri (Tri *d,  Tri *s)  { *d = *s; }   /* struct {u32 a,b,c;} */
        -> mov r3,r0 / ldm r1,{r0,r1,r2} / stm r3,{r0,r1,r2}
    void c_arr (u32 *d,  u32 *s)  { d[0]=s[0]; d[1]=s[1]; }
        -> ldr/str/ldr/str

So the rule is not a size threshold at all: it is that the ldm/stm pair comes
from the 64-bit SCALAR type's natural register pair, and separately from any
aggregate of 12 bytes or more.  An 8-byte aggregate falls between the two and
gets neither.  The note's own list of tried spellings confirms this in
hindsight -- every one of them was an aggregate (`struct {u32 a; u32 b;}`,
`struct {u32 v[2];}`, `P8` i.e. a struct wrapping a u64, or two scalar
assignments); the bare `u64` was the one shape never tried.

    +0038    stm r5, {r2, r3}    |  stm r0, {r2, r3}      (register tie only)

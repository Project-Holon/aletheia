This one is four bytes short and it is a scheduling decision, not a missing
statement or a wrong constant.

The original:

  0203CEAC  push {r3, r4, r5, lr}
  0203CEB0  mov  r5, r0
  0203CEB4  bl   0x203d788

  0203CEC8  ldrb r0, [r4, #0x65]
  0203CECC  str  r5, [r4, #0x348]
  0203CED0  cmp  r0, #1
  0203CED4  bne  0x203cee4
  0203CED8  ldr  r0, [pc, #0x20]    <- 0x0203CDD4, loaded in this arm
  0203CEDC  bl   0x203c774
  0203CEE0  b    0x203ceec
  0203CEE4  ldr  r0, [pc, #0x14]    <- the same pool word again, second load
  0203CEE8  bl   0x203bf9c
  0203CEEC  bl   0x20370c8

  0203CEF4  pop  {r3, r4, r5, pc}

  0203CEFC  pop  {r3, r4, r5, pc}
  0203CF00  .word 0x0203CDD4        (one pool word, both loads use it)

What every spelling tried so far produces instead:

  0203CEC8  ldrb r0, [r4, #0x65]
  0203CECC  cmp  r0, #1             <- the compare is hoisted above the store
  0203CED0  str  r5, [r4, #0x348]
  0203CED4  ldr  r0, [pc, #0x20]    <- ONE load, shared by both arms
  0203CED8  bne  0x203cee4
  ...

so the compiled range is 84 bytes against the original's 88.  The pool holds a
single word in both cases; the difference is only that mwcc commoned the one
`ldr` out of the two arms while the original reloads it per arm and keeps the
compare below the store.

Spellings tried and their result (all 84 bytes, same single residue):

  if (s == 0) return 0; with s->unk348 = a then if (s->unk65 == 1) ... 
      -> `moveq r0,#0 / popeq`, i.e. the early return is if-converted
  if (s != 0) { body; return 1; } return 0;
      -> the out-of-line `return 0` comes back and the residue is exactly the
         compare/load hoist above
  u8 t = s[0x65];  ... str ... if (t == 1)         (temp, load first)
  u32 t = s[0x65]; ... str ... if (t == 1)
  switch (t) { case 1: ...; default: ...; }
  the two call arguments written as (u32)func_0203CDD4 instead of 0x0203CDD4
      -> mwcc folds the extern's address back to a constant and the object no
         longer even carries the relocation

So the file parked nowhere is this one: it is a DIFF, not byte-correct, and it
is recorded here rather than in src/.  It is also not a witness for anything
(the two callers of 0x0203CEAC, 0x0203BDEC and 0x0203BE5C, are both matched
independently).

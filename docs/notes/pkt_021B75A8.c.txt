### lane O61 residue -- func_021E6DAC (140 B extent, 126 B code), func_021D4558 (164 B extent, 146 B code)

Both are *characterised*, not guessed: the control flow and the field writes are
settled and reproduce; what does not reproduce is one register-allocation
decision that shifts everything after it by 2 bytes.  Neither is filed.

func_021E6DAC  `(void *a, int b, int c, void *d)`, 140-byte extent.  Semantics
as written up in `scratch/ov_093/o61/func_021E6DAC_diff.c`: gate on
`c == func_021D775C(2)`; `k = (u8)func_021D775C(0xe)`, and when `k == 6` the key
is rebuilt by `func_021C7D00(b,c)`, `func_021C815C(b)`, `func_021B8C20(...,0)`;
then `func_021C7F68(b,k,d)`, the record `func_021D67A8(func_021C7CF4(b,*(u8*)d))`,
and an `if` between the `func_021D76BC(0x12,r)/(0xd,k)` pair and
`func_021D76BC(0x41,1)`.

The one thing the image does that no spelling reached: it saves the third
argument (c, r2) into **r4** and puts the (u8) key **k** in **r6**; mwcc here
puts c in r6 and k in r4, i.e. it allocates k's register before c's.  Measured
attempts, all giving k->r4/c->r6 at offset +0x06 and a 2-byte-longer body:
  `u8 k;` declared at the top of the function          -> 128 B, 70 bytes differ
  `int k;` declared at the top                         -> 128 B, same
  `u8 k` declared inside a block opened after the gate -> 128 B, same
  arms swapped (`if (p == 0 || test == 0) {0x41} else {0x12/0xd}`) -> 128 B, same
That last one *is* needed on its own account: with the predicate written
`p != 0 && test != 0` mwcc emits an extra branch over the else arm, whereas the
image lays the `0x41,1` block inline and jumps to the `0x12`/`0xd` block with
`bne` -- the `||`-of-failures form.  So one arm-order byte is right and only the
k/c register swap is open.  Next probe: a shape that makes c's live range end
before k is born (e.g. `k` as the *fourth* declared local, or c re-read from a
spilled copy).

func_021D4558  `(int a, int b, int c)`, 164-byte extent.  Semantics settled and
filed-adjacent: `c == 4` returns the a'th 0xBBC element of the table at
`*0x021F3B88 + 0xBF4`; otherwise the masked 16-bit field at +4 of that
structure goes to the ARM helper `func_02030734(v, c, 1, 0x021F3A98, 0x021F)`
and the result is stored and re-read at `+0x3B14 + a*4`.  Its twin
**func_021D4954 closed EXACT\* on the first compile** with the identical tail
and no `a`-index; the difference is entirely the early-out.

Residue: the image keeps `a` in **r0** and multiplies `muls r1, r0, r1`
(`a * 0xBBC`, destination = the constant's register), and computes `a*4` with
`lsls r5, r0, #2` as the first instruction of the out-of-line block.  mwcc
instead saves `a` into **r5** at +0x02 -- *before* the `c == 4` test -- so every
subsequent pool load takes the register r0 would have had, the multiply becomes
`muls r0, r5, r0` and the body is 16 bytes short at 100 B.  Measured attempts:
  `off = a * 4;` hoisted above the field computation    -> still saves a, 100 B
  `a * 4` inlined at both use sites (CSE bait)          -> still saves a, 100 B
  `u8 *p = ...; return (u32)p;` in the early-out        -> still saves a, 100 B
Both files are parked in `scratch/ov_093/o61/` as `*_diff.c`; the C7CF4/C88A4
family next door (15 members filed) shows the same shape closing on the first
compile, so the missing thing is one allocator hint, not a wrong model.

### lane O69 residue -- five parked record-builders from the same family

All five are *characterised*: gates, field offsets, constant pool words and call
lists reproduce; each fails on one mwcc codegen choice worth 2 to 4 bytes that
shifts the rest of the body.  Sources are in `src/pending/` with the blocker in
the header.

**func_021DF0C4** (124 B code, ours 120; DIFF at +0x02, 119 bytes) -- the image
opens `push {r3,r4,r5,r6,r7,lr}; sub sp,#8; str r0,[sp]`: an 8-byte frame with
one spilled word.  mwcc here spills `a` into the pushed r3 dummy slot with *no*
frame, so everything after +0x02 sits 2 bytes early and the `add sp,#8` is
missing too.  Every other instruction is identical, in the same order (including
the `ldr r2,pool` before `adds r0,#0x14`).  Probes: `void *a` and `int a` (with
func_021D70A8 taking int) both give 120/no frame.  This is the same prologue as
func_021DD588 (8-byte frame for *two* spills) and func_021E3CB0/func_021E25FC
(8-byte frame, one [sp] access and one [sp] read) -- four functions in ov093 show
the frame, so it is a real source shape, not noise.  Likely a second stack-resident
local that mwcc kept the slot for; from the source it needs a hint that mwcc
counts two spill slots.

**func_021DFABC** (130 B code; DIFF, 48 bytes) -- the only residue is the
`(u8)` of `func_021DCFF8(a,2)`: the image truncates *into the argument register*
(`lsls r0,r0,#0x18; lsrs r1,r0,#0x18`), mwcc copies first (`adds r1,r0,#0;
lsls r1,r1,#0x18; lsrs r1,r1,#0x18`), 2 bytes longer, and the tail shifts.
Probes: declaring func_021D7B74's second parameter `u8`, and routing the truncation
through a `u8` local, both made it worse (65 bytes).

**func_021E4A70** (144 B extent; DIFF, 73 bytes) -- the `-2` written to +0xc is
materialised in the image as `subs r0, r0, #3` *from the 1 already in r0* and then
spilled to `[sp]` for the second record, which re-reads it.  mwcc folds the
constant to `movs r0,#0xfe` and never spills.  So the source evidently carries the
value in a variable that mwcc keeps live across the second `func_021C88A4`; the
constant must not fold at the front end.

**func_021D85F4** (DIFF, 31 bytes) -- two residues.  (a) the `0xff` at +0xc: the
image does `subs r0, r2, #2` from the 1 in r2, mwcc emits `movs r0,#0xff`, and the
same choice flips the record pointer from r1 to r2 for the whole body.  (b) the
`func_021C8120(b,6)` result is copied through r4 before the byte-copy loop.

**func_021E7388** (DIFF, 108 bytes) -- the scan loop.  The image is
`n = func_021D775C(5); i = <pooled zero>; beq end; do {...} while (++i < n)`: the
counter's zero comes from a literal pool word at 0x021E740C and the `n == 0` test
is the `beq` on the `adds r7,r0,#0`.  The natural `for (i = 0; i < n; i++)` gives
`movs r5,#0` plus a separate `cmp r7,#0; bls` pre-test, shifting the loop.  If a
source shape is ever found that makes mwcc put a zero in the pool, this one closes.

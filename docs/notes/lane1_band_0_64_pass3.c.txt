---------------------------------------

problem, and three of them are the same wall.

* **0x0200E0BC** (38 B, `pkt_0200E0BC`) - the rotated loop.  Best of eight
  spellings this pass is the struct field read plus a redundant counter guard
  plus an **unsigned** counter (`u32 i`, which is what turns the two compares
  into `bhs`/`blo` as the original has them): 44 bytes, size right, 9 concrete
  bytes off.  Those nine bytes are the invariant pool load, which the original
  schedules BETWEEN the peeled entry test and the loop body and this front end
  hoists into the preheader, plus the back edge that follows from it.  That is
  the residue docs/notes/pkt_02010DB4.c.txt already recorded for 0x02010DCC
  (nine bytes, same cause), byte for byte.  Three functions, one wall.

* **0x02010DF4** (28 B, `pkt_02010DB4`) - the same wall without a table, and
  the closest thing in the set: the note's `for` plus redundant
  `if (i >= 13) break;` reproduces the size and every instruction but the back
  edge (1 byte).  Not re-derived this pass.
* **0x020120B4** (10 B, `pkt_020120B4`) - real call with a frame in the
  original, tail call from this front end for all fifteen spellings tried

Bytes: `04 f0 1f e5` (`ldr pc, [pc, #-4]`) plus the pointer word, ARM, in the
middle of Thumb code - `mwld`'s long branch veneer for a Thumb `bl` that could
not reach.  No C spelling produces them and the `veneer` class cannot carry
them either: rule 4 wants the pointer word to name code inside a region of
layout/layout.json, and all four land in 0x0270_xxxx / 0x0273_xxxx, the
TWL-only `arm9i` module this project does not extract.  Full write-up:
docs/idioms/a-four-byte-arm-function-in-a-thumb-packet-is-a-long-branch-veneer.md.
Correction to the second pass's note, which listed 0x02005454 and 0x02005B6C
among the four stubs that *do* attest: re-run this pass, 0x02005440's site to
0x02005454 and 0x02005B24's site to 0x02005B6C both report `no witness outside`
(the only branch to each is the one inside the function under test, which the
honesty rule discards).  Only 0x020053E4 and 0x02006D3C have an outside branch.

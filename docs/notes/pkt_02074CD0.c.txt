The 24-bit read is right for the *value*: spelled through a
`struct Hdr { unsigned v : 24; unsigned flag : 1; unsigned rest : 7; }` view
the original's `lsl r0,r0,#8` / `lsr r0,r0,#8` pair straddling the branch comes
out exactly as docs/notes/pkt_0207533C.c.txt records - writing `(w << 8) >> 8`
instead folds to `bic r0, r0, #0xff000000` and loses it.  What does not come
out is the *flag* test: taking `flag` from the same bitfield view gives
`lsl r1,r0,#7` / `lsrs r1,r1,#0x1f`, where the original has
`lsr r1,r0,#0x18` / `tst r1,#1`.  Moving the flag test to a plain u32 read of
the same word (`(o->w >> 24) & 1`) and keeping the bitfield view for the value
instead costs the whole function: same idea, 132 bytes compiled, 67 concrete
bytes differ, because the two views stop sharing the header load.

Note also that func_020750EC has no witness outside this range in the
image-wide branch scan, so even a byte-perfect body caps at MATCH on that site
(func_02075080 resolves as `matched`).  This is the same one-caller SDK shape
as docs/notes/pkt_02074A6C.c.txt.

## The rule

A scan placement is rejected when it starts strictly inside the extent of another function known in that region. Known functions:

- **listing:** a `func_XXXXXXXX` label in the region's disasm.py listing. The listing is `units_arm9.json` / `units_itcm.json` files for arm9 and ITCM, `asm/twl/twl.s`, and `asm/overlays/ovNNN.s`. The label's extent is its traced code: from the label to the end of the last instruction before the next label.
- **catalog:** a `layout/symbols_sdk.json` row with a size.
- **matched:** a `layout/matched` shard entry. Its extent is the catalog size at that address, or else the listing extent that starts there.

A placement is exempt when something known starts at exactly its address: a listing label, a catalog row or a shard entry. Every rejection goes into the existing `rejected` list with the reason `interior: starts inside <kind> <name> <start>..<end> (+off)`, and the run prints them.

Two refinements of the brief were needed. Without them the rule removed real functions.

1. **Label-to-next-label extents.** A first version used label-to-next-label as the listing extent, and it dropped 179 rows / 11,692 B. Most of those were real SDK functions that disasm.py never reached. disasm.py writes untraced code as `.word` data after a function's pool. Examples: OSi_IrqDma0..NDma3 after OSi_IrqHandler's pool, GX_DisableBankFor*, FX_DivS32, MATH_QSort and PXI_InitFifo. Limiting the listing extent to traced instructions puts these outside.
2. **Catalog and shard starts are exempt too.** disasm.py traces straight from MI_CpuCopy8 (0x02082D44) through MI_CpuComp8 (0x02082E74) and MI_CpuCopy (0x02082EA4). Both are catalog rows and matched shards. With only the listing-label exemption they were rejected. ov021 EL_GetLibSize and ov093 CTRDGi_IsTaskBusy were kept the same way.

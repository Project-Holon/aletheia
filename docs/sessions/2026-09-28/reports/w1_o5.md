## Near misses and residue

- ov114 0x021C99D0 (ValidateResponse): byte-correct, MATCH*. The pool word at +0x184 is the
  `hextbl` initializer template (vendor `@16077`, image 0x021CE1B8). `vendor_template` finds
  no template at this slot, and `_template_unique` accepts ARM9 addresses only. No existing
  class attests an initializer template in an overlay. A `@16077 0x021CE1B8 data` symbols
  line is present but does not resolve. This is a tooling gap, not a C problem.
- ov114 0x021C9B64 (CompleteCallback): 6 instructions differ. In the 20-byte secretkey struct
  copy into `tmpbuf`, the source and destination pointer registers are swapped (image src r3,
  dst ip; ours the reverse). About 14 spellings were tried: casts, block pointers, u8 element
  type, const, and declaration position. Even when fixed, the `hextbl` template (`@16117`,
  0x021CE1CC) caps it at MATCH* for the reason above.
- ov175 0x021E11F0 (GdbCancelRequest): 20 instructions differ, and all of it is register
  colouring. The image holds 0x38 in r5, `s_tbl` in r6 and the constant 3 in r7; ours gives
  r6, r7, r5. The case order is right (2,3,4,7..13 sake; 5,6 ghttp; default), as are the
  cross-jumped per-case duplicate blocks and the `mla` address for case 6. About 17
  attempts.
- ov009 0x0217CF5C (gsCryptRSAVerifySignedHash): draft, 100 instructions differ from an
  early shift. There are two residues:
  - The image loads `sigLen` once into r2, where ours reloads it for `memcpy`.
  - The image keeps `i+1` as its own value for the `(i+1)+0x22` and `(i+1)+0x23` length
    compares, where ours folds to `i+0x23`.

  Both header arrays are initializer templates (`@13305`, `@13307`), so MATCH* is the
  ceiling in an overlay until the template class covers overlays.

## Shape notes (C spellings not visible in DWARF)

- 0x021CA240: a block-scoped `char *p = g_session.request` keeps the request load in r6
  across `strlen`. `strlen` is declared returning `unsigned long`; the `int` or `unsigned
  int` returns give `rsb` plus an indexed store instead of `strb r2, [r1, -r0]`. The alloc
  size sum is written in reverse operand order, because mwcc evaluates right to left.
- 0x021C99D0: a block-scoped `Key20 *d` fixes the second key copy's register order. The
  subtractions use `40u` so that `len - 40` is one unsigned CSE shared by B64Encode,
  b64size and `decodedbuflen`. The strncmp offset stays signed.
- 0x0217CA40: `mIsStaticInitComplete` is declared `volatile`. Without it, mwcc hoists the
  field load above the refcount branch, while the image keeps one load per arm. sdkobj
  renders the DWARF member as plain `int`. This is recorded in the header notes.
- 0x021BF6EC: the ternaries must be written `x == 0 ? 0 : y` to get `mov #0; cmp; ldrne`.
- 0x021BF8C0: `errorCode += -810` (not `-= 810`) gives the image's literal-pool add.
- 0x021C9EE4, 0x021E10CC: `DWC_InitGHTTP` is called with r0 = 0 although its DWARF
  prototype is `(void)`. It is declared unprototyped and called with `(0)`.

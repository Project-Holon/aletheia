## Near misses

- ov009 0x021573C4 CPS_Startup (536 B): 188 bytes differ. The residue is register
  allocation only; the layout, the stores and the call sequence all match. In the target,
  `config` is in r4 and the wfailed base is in r5. The zero for the high word of the
  MATH_InitRand32 `add` field is materialized in r6 before the `random_seed == 0 ?
  OS_GetTick()` branch, and a separate zero is created in r4 after `config` dies. Here the
  compiler shares one zero, so every register shifts by one. Tried: an inline
  MATH_InitRand32/MATH_Rand32, if/else and ternary seed forms, a local seed, a chained
  zero store and a `(void *)0` thread argument; the count stayed at 161 to 188.
- ov009 0x0215BF88 dhcp_analyze_response (880 B): 237 bytes differ, all register
  allocation. The target hoists the `CPSDhcpMode & 2` load out of the option loop into
  ip, with no named local in DWARF. In the original TU CPSDhcpMode is a separate global,
  so it cannot alias the struct stores inside the loop. With one struct standing in for
  the wfailed block, the load stays in the loop and `timeout` is not spilled. An explicit
  local `mode` gets the frame and the switch right, but puts `s + 0xf0` in ip and `mode`
  in r3 instead of the reverse. Declaration position and type did not change this. Both
  near misses probably need the separate-global model of network.o's .bss.

## Notes for the next pass

- network.o rules learned: declare locals in reverse DWARF order (this fixed both
  CPSi_TcpWrite2Raw and dispatch_udp outright). Byte swaps use
  `((u16)x >> 8) | ((u16)x << 8)`. Big-endian byte reads use `p[1] | (p[0] << 8)` in
  some functions and `(p[0] << 8) | p[1]` in others, so check which byte loads first.
  In resolve_common the label counter is the address-taken `len`, and the rdata reads use
  integer address arithmetic (`(u8 *)((u32)d + 6 + cnt)`).
- The wfailed block (0x021A826C) is modelled per file as a struct with the offsets used:
  +0x02 ipid, +0x14 alloc, +0x18 link_is_on, +0x20 wlan_buf, +0x44 free, +0x50 myip,
  +0x5c..+0x64 wlan buffer, +0x78 rand ctx.
- The crypto_bobj1.o rows have no DWARF subprograms. They were written to the object's
  code shape (OpenSSL 0.9.7-era BN code); BN_sub_word has a special case for top <= 1.
- No asm bodies. No name disagreements beyond the missing DWARF for the crypto rows.
- CPS_Startup's relocations include OSi_ReferSymbol (0x02004EB0), empty_func (0x021573B8)
  and default_link_is_on (0x021573BC), which the catalog lists as game/unknown. Its
  evidence will need checking if it is ever matched.

# sdk9w2_catalog: catalog tie-break and reference checks

Lane sdk9w2_catalog, 2026-09-28. This pass changes which SDK rows the catalog places and what it names them, so it moves the SDK and game figures; every change is listed below. No .c or .h under `sdk/` was opened, and no matched source file was renamed.

## Files changed

- `tools/libmatch.py`: tie-break and reference checks (below).
- `tools/sdkclass.py`: the same reference checks applied to its placement scan. This file is outside the lane's four owned files, but it is the only generator of `layout/sdk_class.json`. Without the change, every dropped catalog row stayed SDK through `sdkclass.union()`.
- `layout/symbols_sdk.txt`, `layout/symbols_sdk.json`: the new tool output, merged into the committed files (method below).
- `layout/sdk_class.json`: regenerated by `python tools/sdkclass.py`.
- `layout/worklist.json`: rewritten by the verification step `worklist.py --refresh` (not hand-edited).
- This report.

`tools/match.py`, `layout/units_arm9.json` and `layout/function_starts.txt` also show as modified in the working tree. Those changes come from other lanes.

## What changed in tools/libmatch.py

1. **Tie-break.** The greedy pass now sorts ties by (size, concrete bytes, profile score, votes, support, section order in the object, address). Before, it sorted by name.
   - **Votes:** how many candidate placements call this address by this name.
   - **Support:** how many other functions of the same object verify at exactly one place within 4 KiB.
   - **Section order** is the link order. It splits same-bytes families such as GX_/GXS_LoadBGnScr and GX_ResetBankForX / GX_DisableBankForX in object order.
2. **Once per region.** A STB_GLOBAL name is placed at most once per region: the best-ranked copy wins, and the other addresses are left to a twin. Statics and weak symbols are exempt, because libdwcutil's scene objects repeat statics.
3. **Twin shapes.** Some patterns verify at exactly the same addresses as another name's pattern. One example is the 16-byte getter shape shared by GX_GetBankForLCDC, GX_IsDispOn, OS_IsTickAvailable, OS_IsAlarmAvailable, OS_IsVAlarmAvailable and OS_IsResetOccurred. Such a pattern is placed only where votes or support say which name it is; otherwise the address is left unnamed.
4. **Reference checks** (class `Checker`, applied to every candidate before the greedy pass and in pass 2):
   - **callee:** every named callee must land where that callee's own bytes verify. A callee is a PC24/CALL/JUMP24/XPC25 branch, a Thumb BL/BLX pair, or an ABS32 code pointer. The check follows Thumb `ldr rN,[pc]; bx rN` and ARM `ldr pc,[pc,#-4]` / `ldr ip; bx ip` forwarders.
   - A callee with any unscannable pattern proves nothing, unless one of its scannable patterns verifies elsewhere in the target region.
   - **data:** a global that the function loads (ABS32, non-local symbol) must sit where the functions that verify at exactly one place put it. This is a per-region consensus.
   - A placement fails when at least half of its checkable callees and globals disagree. One odd reference in a large function does not remove it: CARDi_ReadRom and OSi_InitCommon keep their rows.
   - **static:** no `ldr` in code outside the object's code span may load one of the object's local data objects. `_ZZ...` inline-function statics are exempt, because they are shared.
   - Relocations through section symbols (the way CodeWarrior reaches statics) are resolved to the named symbol at that offset. RELA branch addends (-8/-4) are normalised.
   - Patterns deduplicated across objects keep each object's reference set, and a placement passes if any set agrees.
5. `symbols_sdk.json` gains a `rejected` list: every rejected candidate with its reason (addresses and names only).

Three rules were tried and dropped because they removed real functions:

- A post-placement "callee name placed elsewhere" pass. It removed callers of aliases such as PXI_Init/PXI_InitFifo and OS_VSNPrintf/STD_TVSNPrintf.
- A "never-scannable callee lands on another name's bytes" rule. It removed gsCoreInitialize, NHTTPi_* and VPrintf through aliases.
- A data consensus for statics. It failed because ar truncates member names (there are two `scenesetusbready` members).

## What changed in tools/sdkclass.py

- Hits that fail `Checker.bad()` anchor nothing (2046 hits dropped).
- Patterns whose hit set equals another name's anchor nothing (318 patterns).
- A member whose candidate bases tie is left unplaced (112 members).
- Before this change, those one-function members were placed at their lowest-address hit. That is how CameraStandbyCallback/RTCi_ResetAsync at 0x02033400 and GX_GetBankForLCDC at 0x02045A98 stayed SDK.
- `layout/sdk_class.json` gains a `rejected` list.

## How the catalog was regenerated

I ran `libmatch.py scan --outdir <scratch>` twice: once with the old tool (base) and once with the new tool (new). The base-to-new delta was then applied to the committed files, as the 2026-09-27 lane did. A plain scan would drop the hand rows and add 211 twl rows. The merge rules:

- A committed row that base places and new does not is removed.
- A row whose committed name equals the base name takes the new name.
- Hand rows are kept: 0x0204047C game, CRYPTO_RC4Encrypt, MATHi_SHA1Transform, and the STD_TSScanf/STD_TSNPrintf names.
- twl rows are not added.
- Owner removals stay removed.
- `dupes` is recomputed over the merged set.

The JSON still carried 0x0203CFF0 DWC_IsSendableReliable and 0x0203D000 FATFS_FormatDrive, which the owner had removed from the txt only. The new tool rejects both, so they are now gone from the JSON too.

**Kept against the rule (owner decision needed):** ov029 0x021F2BF0 CTRDG_IsAgbCartridge and ov231 0x021809D8 IRC_Check. These are the owner-approved hand additions of commit 0f90fc81. The callee check rejects both:

- 0x021F2BF0 calls CTRDGi_IsAgbCartridgeAtInit at arm9 0x02035C60, where CTRDGi_IsAgbCartridgeAtInit's bytes do not verify.
- 0x021809D8 calls IRCi_Check at 0x02180820, where IRCi_Check's bytes do not verify.

I left both rows in place.

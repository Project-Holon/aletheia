## Near misses

- 0x021CB3B4 BN_add_word, DIFF, 20 mismatched words, layout and semantics identical. The original
  hoists the constant 0 into r2 at function entry (used by `a->neg = 0`, `a->top = 0` before the
  call), so the a->neg / a->top loads use r3 and the later `mov r2,#0` is a reload; the compiler
  here keeps constant 0 inline (mov r0/r2 at each store) and everything after the first neg test
  is renamed. Tried about ten variants: `int i = 0` at entry, `i = 0` after the w == 0 test, a
  local `z = 0` used for every zero store, reordering the two stores, second zero-store in the
  neg path first; none moves the hoist.
- 0x021CA5E4 ASN1Skip, DIFF, 32 mismatched words, control flow identical. Register allocation
  only: the original keeps `data` in r4 (post-increment ldrb), the tag byte and the first `*dlenp`
  temp in lr, `len` in r12; here data lands in lr/ip and the temps in r4. Tried all 24 declaration
  orders, initializer versus assignment forms, `*data++` versus split increment, the `*dlenp - 1`
  CSE form (gave more registers, worse), `while (l--)` versus do/while.

## Notes for the integrator and the next pass

- Symbols: every callee is func_XXXXXXXX with an `ov009`/`ov114` token when in the same overlay
  and no hint for ARM9 callees. `_u32_div_f` (0x0209C2B0) is written by that name in the header of
  ov114 0x021CC4A0 because it is a compiler-emitted call (implicit division), not a C reference.
- Data: g_021A826C (libcps network vars block) and g_021AB184 (DWC auth global block) are typed
  as structs so the compiler produces the base-plus-offset addressing seen in the original;
  g_021AB188, g_021AB1F4 and g_021AB208 are separate externs because the original loads them
  through their own literals.
- DWARF/catalog name disagreements: the catalog lists the relocation at 0x021AB184 as
  `DWCiswfcutil`, but the code indexes it as [+4] (the auth context pointer, DWARF name
  `DWCauth` at 0x021AB188); the relocation for CRYPTOi_MyAlloc names `CRYPTOi_MyFreeFunc`
  (0x021D422C) although the load is at +4 (the alloc pointer). Both are address-correct.
  libcrypto crypto_bobj1.o functions have no DWARF subprogram; BIGNUM/BN_CTX layouts were
  inferred from the code (BIGNUM = {d, top, dmax, neg, flags}, 0x14 bytes).
- Discovery worth recording: the DWARF locals list is in reverse declaration order and it
  mattered for register assignment (dacktimer_reschedule). A function-static in the same
  section as a global is not aliased by a pointer store, so a local copy is needed when the
  original CSE'd a reload (dhcp_request_server, `save`).

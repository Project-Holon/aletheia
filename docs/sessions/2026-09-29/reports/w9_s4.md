## Levers

- **Zero fill as `__builtin__clear` on an int-typed object (GetWLanSetElement).** Two arms
  zero 32 and 72 bytes with `stm r2!, {r0, r1}` runs. `memset` calls, and `__builtin__clear` on a
  `char[]` (byte strb loop), do not give that. Declaring the externs as `struct { int w[8]; }`
  and calling `__builtin__clear(&g, 32)` does.
- **Byte swap term order.** `((x >> 8) & 0xff) | ((x << 8) & 0xff00)` with the `>>` term first
  in source matched the object (the `<<` first order gave the reverse).
- **Loop-invariant swap needs a block-local `u16 v`.** A function-scope `int v` kept the
  swap but changed the loop registers; `{ u16 v = SWAP16(...); for (...) a[i].f = v; }` matched.
- **`*lpe++` in the hex loop.** `wp += PutHex(wp, *(char *)lpw++)` gives the object's
  `adds r7, r6, #0; ldrsb r1, [r5, r7]` with the pointer bumping each iteration.
- **Param write-back in the prologue.** `lpe = lpelement; lpe += 8; lpb = lpe; retv = 0;
  len = SWAP16(*(u16 *)lpelement);` in that order reproduces the object's double store to sp+4.
  A frame with `lpe + len` recomputed at each call (no `lplimit` local) matches.
- **Locals in reverse listing order (renewInfo).** `info, desc, elems, i, j, k` gave the
  object's coloring (info r6, desc r4, j r5); the DWARF order gave info r7, desc r6.
- **memcmp from libc/memcmp/string.h with a `memcmp` symbols line.** Naming the callee
  `func_020923F0` in the header left the call as a wildcard reloc and the result MATCH; a
  symbols line `memcmp 0x020923F0 arm` gave EXACT.
- **Post-index stores from pointer walking (MB_Init).** `dst = (u16 *)p_parm->uname;
  *dst++ = ...` produces the object's `strh r1, [r2], #2`; array indexing gives an add per
  iteration. Load-once temp `ch = *src; if (ch == 0) break; g.gname = src + 1; *dst++ = ch;`
  matches the second loop exactly.
- **Declaration order matters again once the loops are pointer walks (MB_Init).** A
  sampled search over the 8 locals found order (p_parm-first variants) that fixes p_parm r8,
  p_com sb; the order now in the file is that best sample.

## Near misses and residue

- **ov107 0x021F5904 MB_Init (472 B, size equal).** Everything matches except the first
  loop (nameLength copy): the object holds the destination pointer in r2 and the halfword in r1,
  and issues `ldrb r0,[r7,#1]` (the next nameLength load) before `add r6, r6, #1`; ours puts the
  pointer in r1, the halfword in r0, and schedules `add` before the load. 22 concrete bytes.
  Tried: `ch` temp, direct `*dst++ = user->name[i]`, `c` versus `dst` for the pointer, about 100
  declaration permutations. Callees all resolve (WM_GetNextTgid, OS_*, MIi_CpuClear*, MI_CpuCopy8
  matched or labelled ARM9, MBi_GetBeaconPeriodDispersion is our matched ov107 row).
  Types: WmBase (dma, wmSysBuf, p_parm at +0xC, p_com at +0x10) as in 021F5BE0; the object at
  0x021F6E58 is a struct of four u16, an int and a `u16 *gname` at +0xC.
- **ov009 0x021758C4 DWCi_ProcessRequestMatch (480 B, compiled 484).** All register colors match
  except the pNodeInfo in the immediate branch: the object reuses sl (the dead AID register)
  for `GetNodeInfoForAID(AID)`'s result and every later use; ours picks r7, which makes 4 extra
  bytes (a branch instead of the object's conditional `addne sp; movne r0,#0; popne` return).
  Tried scoped versus function-scope pNodeInfo and 60 permutations of the other locals.
  The bRet condition is `(suspend && sm) || (!suspend && !sm)` inverted with a 1-first
  assignment; `senddata[sendlen++]` stores are needed to stop sendlen constant folding.
  All ten callees resolve as matched ov009 rows (DWCi_* and DWC_*).
- **ov114 0x021BC740 NHTTPi_RecvProxyConnectHeader (484 B, compiled 456).** First draft only.

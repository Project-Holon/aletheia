# w8_s2 (overlay SDK wave 8, lane s2)

Region ov009, libsoc (socl_ssl, socl_startup, socl_write) and libssl (arc4, biginteger, sha1, ssl), all
4.0.0.1024 objects, dsi/1.1p1, -O4,p, arm. 18 rows; 14 EXACT/EXACT*, 4 near misses. All matched files were
first verified with `match.py one`, then `manifest --verify --force --shard ov009/pkt_ov009_XXXXXXXX`; the
header status is the manifest output.

Shards: layout/matched/ov009/pkt_ov009_XXXXXXXX.json for the same 14 addresses.

Levers that worked: local declaration order swaps (big_add: `i` before `carry`; big_mult: `i` before `j`);
big_sub is a single `for` with `i < digits_a || (i < digits && borrow != 0)` and `(int)tmp >> 16`;
EnableSsl needed the second predicate as `int r = 0; if (s) r = (s->state & 1) ? 1 : 0;` (a plain
`&&` return folds the branch and drops the state reload); enter_computebound needs a local `thread`
holding the current thread; date2sec needs `date` declared before `time`.

Callback pointer: 0x0215FD00 references SOCLi_EnableSslCallBack (0x0215FD40) by ABS32; the callback was
matched in the same lane, so the witness is `sdk`. 0x02163E10 calls CPSi_sha1_calc (0x02163CF0), which is
not one of my rows; the shard verified, so it attests as-is.

Data notes: 0x02163E10 pool word is padding+1 (0x021A1F29); the extern is the array at 0x021A1F28 and the
call passes `+ 1` (header note). 0x0215CAE4 store lands at 0x021AA440+0xC (SOCLiUDPSendSocket), declared as an
array at the pool address. No volatile used anywhere.

## Near misses (4, drafts in src/pending/ov_sdk/, no shard, about 12 attempts each)

- 0x0215E2C0 SOCLi_GetWriteBufferFreeSize (36 B): 4 bytes. Original loads halfword +0x100 first (r1) then
  +0x102 (r0) and computes `sub r0,r0,r1`; ours loads +0x102 first and computes `sub r0,r1,r0`.
  Tried decl order permutations, unsigned short locals, `-in + out - 1`, `(out - 1) - in`, pre-loading in via
  available_len. The compiler always loads the left operand first. Untested: volatile (not used).
- 0x0215E588 SOCLi_GetOptimumSendBufLen (152 B): 21 bytes, control flow identical (all three branch merges
  match). Register assignment only: original holds winSize in r3 and mss in r2 with the pool pointer in r1
  loaded before the compares; ours uses r2/r1 and loads the pool pointer after. Tried single/nested ifs,
  local w with int/ushort, cfg pointer local.
- 0x02163E40 CPSi_rc4_init (120 B): 21 bytes, instruction stream identical, registers only. Original keeps
  `m` in r4 from the first loop (`add r4,r0,#2`) and a zero constant in r0 for `k = 0`; ours puts `m` in lr
  and the zero in r3. Tried 40 combinations of decl order, x/y-store order, `j = k = 0` forms, `m` init at
  declaration.
- 0x02160130 get_rootCA (76 B): 12 bytes. Original loads `rootCa` (con+0x814) once after the loop guard
  (`ble`) into r5 with the count in r6; ours emits the load before the guard and swaps r5/r6. Locals `n`
  and `list` hoist the reloads correctly; placing the list load after the guard did not reproduce
  (do-while, if(n>0) wrappers, for-init comma all tried).

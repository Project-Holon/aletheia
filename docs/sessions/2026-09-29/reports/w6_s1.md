## New levers

- Alias hazard fixes load order (ICONlInit): a byte load from a table cannot move above a byte store through another
  pointer, so the load goes in the source before the store: `g_MemIcon = alloc(); idx = tbl[type << 2];
  g_MemIcon->type = type; g_MemIcon->obj = f(0, idx);` reproduces `ldrb` before `strb`. The old draft had the load in the
  call argument, after the store.
- Bitfield extraction from a value that was just stored (checkParam): `lsl #28; lsr #28; cmp #1` comes from reading a
  4-bit bitfield through the global the value was stored into (`*(unsigned int *)&g.param = param; g.param.mode > 1`), so the
  compiler forwards the register and extracts. `(param << 28) >> 28`, `& 0xF` and bitfield unions on locals give `and` or
  stack spills. Struct-by-value parameters spill through the stack.
- Second literal-pool word for `&g_021DE5E4` (endScene3): `func_021D6438((void *)0x021DE5E4)` reproduces the duplicated
  pool word and verifies EXACT (a plain `&g` shares the word).
- Local `void (*FUNC[5])(char *)` copied from a data table (procWin1): a one-member struct `{ void (*f[5])(char *); }` with
  `FuncTable FUNC = g_021DB4DC;` gives the `ldm`/`stm` copy; the call is `FUNC.f[prm](...)`.
- `char` is signed here: vendor `char` arrays read with `ldrb` (isOver text and buffer) must be `unsigned char`.
- A trailing call written in both arms of an if/else (`SetShift(0)` in procInit1) reproduces the cross-jumped tail; a
  single trailing call does not.
- `if (r == 0) {...} else if (r == 2) {...} else {...}` reproduced the 0/2/other dispatch in endScene2 (optmovwait,
  seteditaddress); `switch` reproduced procScene and procWin. `if (r != 0) { if (r != 1) return; ... } else {...}`
  reproduced button (0 tested first, branch to the later block).
- Non-constant aggregate initialisers (`RECT r = { a->x, ... }`) are a compile error (`illegal constant expression`) under
  this compiler.

## Near misses (about 12-15 attempts each)

- 0x021D600C Coord2Rect (compiled 48 B, 17 B differ). Object loads x, y (coord) then w, h (size) before any store;
  compiler loads x, w, y, h. Tried locals in all 24 declaration orders and 3 store orders (previous wave), direct field
  stores in all 24 statement orders with both add operand orders (96 variants, best 34 B), a `static inline InputRect(rect,
  l, t, r, b)` helper (18 B; the compiler evaluates call arguments right to left, giving y, h, x, w).
- 0x021D6B04 TPlCheckATrigger (compiled 96 B, 12 B differ). Only the schedule differs: the compiler loads a->w before a->y.
  Best form is locals `int x, y, w, h` inside a block with a `static inline InputRect(&r, x, y, x + w, y + h)`. Tried all
  24 load orders with natural stores, 96 direct-field permutations (best 25 B; part of that sweep ran while another sweep
  shared `match.py` temp state and printed no count, so treat it as partial), `unsigned short *` indexing, struct temp plus
  `r = t`, `r.r += r.l` forms, an `Area2Rect(a, &r)` helper (28 B). Coord2Rect and this row share the scheduling problem.
- 0x021C7960 dispCaret (compiled 72 B, 6 B differ). Only a register swap: the object loads the X table byte into r2 and
  the attr word into r1; the compiler picks r1 and r2. Tried locals `x`/`p` in different orders, a `GXOamAttr *o` local,
  an `unsigned int *w` alias, a `SetPos(o, x)` inline helper, `unsigned int x`, and a bitfield `GXOamAttr` (y:8, x:9) with
  separate stores or a struct copy (88 to 103 B). Table access is `X_IPT[p * 3 + 2]` on a flat byte array (an `[N][3]`
  array folds the +2 into the pool word, which the object does not do).
- 0x021C78A0 drawAddress (compiled 192 B vs 176 B extent in the object; 135 B differ). The object keeps `struct tagAREA a`
  (x, y, w, h u16 at sp+0x14) and `unsigned short buf[2]` (sp+0x10) in memory and reloads a.h, a.y, a.w every iteration
  (a.x is forwarded from the register); the compiler scalarises `a` completely (uses sl/fp). Only `volatile AREA a`
  reproduces the frame (`sub sp, #0x1c`, same prologue, 65 B differ, remainder is ordering) but `volatile` is not an honest
  spelling. Also tried `AREA a = {0}`, `unsigned short a[4]`, a struct holding both `buf` and `a`, pointer aliases
  (`AREA *p = &a`), and a `static inline InputArea(&a, ...)` helper: all scalarised. The object has no relocation for
  `DWCi_InputArea`, so the vendor inlined it. Needs a lever that makes the compiler treat a local struct as address-taken
  without a call.

## Notes for the integrator

- Callees in 0x021Bxxxx-0x021Dxxxx carry the `ov016` token; ARM9 callees (MI_CpuClear16 0x02082A48, MI_CpuCopy16 0x02082A60,
  MI_CpuCopy8 0x02082D44, atoi 0x020964E0, GX_LoadOBJPltt 0x0207E51C) carry none.
- endScene3 (0x021C77F4) writes `HEAPlFree_((void *)0x021DE5E4)` for the duplicated pool word; the vendor relocation is
  against the `MemSsea` static in both words. The second literal has no relocation in my compile, and the shard still
  verifies EXACT. The w6_nm lane used a named alias (`g_021DE558_b`) for the same idiom; the integrator may want one spelling.
- Evidence classes seen in verify output: same-overlay callees resolve as `label` or `sdk`; `g_021DE5C0` (Comment) resolves
  as `string`; `g_021DE5B8`, `g_021DE5C4` as `sole-ref`.
- Data notes: `g_021DE5C0` is a two-byte pair (byte 0 read by procInit and SceneOptMovFailure, byte 1 by button and
  endScene1/2); `g_021DE5E4` (MemSsea) has `bg` at +0, caret OAM pointer at +4, `text[4][3]` at +8, `pos` at +0x14, `result`
  at +0x15; `g_021DE5CC` (Choose in setaossbutton) is `{ u8 way; pad; void *task }`; `g_021DA5D4` (X_IPT) is read with
  stride 3 (+2) in dispCaret and stride 1 in drawAddress.
- No asm bodies.

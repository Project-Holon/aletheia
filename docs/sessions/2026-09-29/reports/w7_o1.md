## Levers

- **strlen from the house string.h (SVLTokenWaitThread).** The object holds a global pointer
  load in a callee-saved register across `strlen` and reloads it after `OS_SNPrintf`. This
  needs `strlen` from `../arm9_sdk/libc/string.h`, which marks it as writing no memory. With a
  local prototype, the load repeats after every call. From pending, the path is
  `../../matched/arm9_sdk/libc/string.h`. Change it when the file moves.
- **Stack-array order follows the reverse DWARF listing.** SVLTokenWaitThread lists
  `errorcode, token, url`, and declaring them `url, token, errorcode` gives the object's stack
  slots. The same reversal fixed register coloring in send_client_hello (`con, sec, buf, d, i`)
  and EvaluateServers (`eval, deleteFlag, localDelete, profileID, i, server`).
- **The `NELEMS` bound gives `blo` (endScene2, send_client_hello).** An int `i` compared against
  `sizeof(a) / sizeof(a[0])` compiles to the object's unsigned `blo`. A literal `3` or `2` gives
  `blt`.
- **`> sizeof(x) - 1` versus `>= sizeof(x)`.** The object's `cmp #0xff; bls` comes from
  `> sizeof(url) - 1`. The `>=` form gives `cmp #0x100; blo`.
- **A late zero copies into the named variable (DoCancelMatch).** The object has
  `mov r4,#0; bl; mov r5,r4; str r5`. That shape comes from writing `cnt->w680 = 0;` first and
  `anyGT2ConnectionExist = 0;` on the next line, with no initializer at the declaration. An
  initialized declaration materializes r5 before the call.
- **Read the tick through a block local before the store's getter (RequestSuspendMatch).**
  The object calls `OS_GetTick` before `DWCi_GetMatchCnt` when storing the tick, so the file
  uses `{ u64 now = OS_GetTick(); GetMatchCnt()->f20 = now; }`. The direct assignment calls the
  getter first.
- **An unsigned accumulator moves coloring (NHTTPi_SendPostData).** The DWARF types `offset` as
  int. With int, `length` lands in r7 and the two SaveBuf stack stores merge into one `stm`.
  With `u32 offset`, the function matches. A `(int)length` cast does not help. The file notes
  this.
- **A switch with grouped cases compiles to a compare chain (SendPostData).** The chain
  `cmp #0; ldrne; cmpne #1; beq; cmp #2; beq` comes from `switch (sendtype) { case 0: case 1:
  ...; case 2: ... }`. `if (t == 0 || t == 1)` folds to an unsigned `<= 1` (`bhi`).
- **`break` to a shared `return 0` (SendPostData).** The object's bottom `mov r0,#0` block is a
  `break` out of `while (1)` followed by `return 0`, not an inline return.
- **Read the jump table off `addls pc`.** Entry k sits at the `addls` address + 8 + 4k. In
  MBi_CommParentSendData, I first misread the case values by one (3/5/6/9/12 instead of
  2/5/4/8/11). The case bodies then follow the object's layout order.
- **Statics addressed off one anchor.** dwci_nd.o (DWCi_Ndi_dlcallback 0x021D3B9C), dwc_nd.o
  (s_userCallback 0x021D3B68) and scenesetselectap (FocusPos 0x021DE60C, with MemSssa at +4) use
  a struct overlay named by offset. endScene2 also takes `&MemSssa` through its own pool word,
  so g_021DE610 is declared separately for that argument.

## DWARF disagreements

- DWCi_DoCancelMatch: DWCi_CancelReservation is declared `(void)`, but every call site loads
  r0 = 0. The file passes 0.
- validate_signature: CPSi_char_from_big is declared with 3 parameters, but the call site
  loads digits into r3. The file passes it as a fourth argument.
- NHTTPi_SendPostData: `offset` is int in the DWARF and u32 in the file (see Levers).
- The catalog names and the DWARF names agree for all ten rows.

Levers that closed each:
- MakeGameInfo: two independent `!ReadIconInfo()` flags, then `icon_disable |= icon_disable2;` as its own statement (the `||` and `|` in the if-condition both compile to cmp/cmpeq).
- make_ciphertext: `switch (suite)` with case 4 / case 5 (not if/else), locals declared p, len, tmp, mac.
- CPSi_big_montpower: locals declared in reverse of the sdkobj listing; loop bound `(unsigned)i < (unsigned)(rdigits * 16)` (blo, not ble); `0x8000u >> (i & 15)` for the lsr. montmult `b` argument is passed as the literal pointers 1 and 0 (matches the existing func_0216497C).
- ConnectToAnybody: single extern for the data word (the pool holds one copy referenced twice, no `_b` alias), `DWCi_QR2Startup` takes the profile id argument in the object (r0 loaded before the call) though the DWARF says void, `(ptr + len)[-1] = 0` for `add r0, r0, r4` operand order.

## Near misses (drafts in src/pending/ov_sdk/, no shard)

1. ov107 0x021F2E58 MBi_calc_sendblock (124 B): src/pending/ov_sdk/ov107_func_021F2E58.c (about 14 attempts). Best form has the right layout (112 B code plus pool) with 27 concrete bytes differing. Residue: the original keeps the entry pointer (mbc + file_id*0x5d4) in r12 (`mla ip, ...`) and, in the `y > x` arm, recomputes `add r0, ip, #0x1d00` before the store (r3 = y stays live), while ours puts the pointer in r1, reuses r0 in the store, and gets y in r1 instead of r3. Tried: local pointer, Blk sub-struct pointer, macro expression per use (no local, gives 46 bytes but different layout), goto shared tail, early-return arms, mbc as struct array (emits mul+add instead of mla). Next pass idea: the hi arm probably reads through a second differently typed access path so the compiler cannot reuse r0; not found.

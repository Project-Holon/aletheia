## Near misses (src/pending/ov_sdk/, no shard)

Both are scenesetrakubutt endScene2 (identical shape, different addresses).

- 0x021CAA9C endScene2 (204 B): ov016_func_021CAA9C.c (Choose at 0x021DE5F8, callees SelectWay
  0x021CC998 / RakuButton1 0x021CAC64).
- 0x021CB5D8 endScene2 (204 B): ov016_func_021CB5D8.c (Choose at 0x021DE604, RakuButton1
  0x021CA838).

Residue (about 14 attempts): the instruction stream and block order match, but the compiler
hoists the constant 1 into r5 (`mov r5,#1; mov r0,r5; mov r1,r5` for GXlInvisible(1,1) and
`mov r1,r5` for SetParam_(2,1)), so the prologue is `push {r3,r4,r5,lr}` and every pop/literal
offset shifts. The target keeps only 0 in r4 (`mov r0,#1; mov r1,r0` for GXlInvisible(1,1),
`mov r0,#2; mov r1,#1` for SetParam_) and pushes `{r4,lr}`. Tried: (void*)1 spellings
(cast, unsigned char cast, `Choose + 1`, `Choose == 0`), int SetParam_ params, else-first block
order, a `t = 1` local for the GXlInvisible pair. None changes the hoist. The sibling
scenesetsearch endScene2 (0x021CBB70), which does hoist 1 into r4 and 0 into r5, matched, so the
difference is in how the SetParam_(2,1) arm is written in the source of this object.

## Notes and evidence

1. 0x021CAF78 checkRaku: `sdkobj` cannot pair this row with a vendor object ("image
   unavailable"; the archive has several members truncated to `scenesetrakubutt`, and the tool
   picks the 144-byte checkRaku at 0x021CAB68 instead). The function was written from the image
   listing (`match.py show`) with the callee list taken from the catalog: DWCi_RAKUlGetState,
   DWCi_SNDlStop, DWCi_RAKUlSetResult (0x021C15D0, catalog row), DWCi_SNDlPlay, DWCi_WINlInitEx,
   DWCi_BTNlDisable, DWCi_ChangeScene, statics endScene 0x021CAE34 and procError 0x021CB05C
   (catalog rows), Choose at 0x021DE5FC. It verifies EXACT and every relocation resolves, but
   its prototype is inferred from the twin at 0x021CAB68, not read from its own DWARF.
2. Data spellings: Choose/Count/FocusPos-with-MemSssa are declared as vendor-offset bss structs
   (`scenesetsearch_bss` at 0x021DE608 with Choose at 0 and Count at 2; `scenesetselectap_bss`
   at 0x021DE60C with FocusPos at 0 and MemSssa at 4) in the files whose object stores both.
   Files that touch only the byte use `extern unsigned char Choose/FocusPos`. The 0x20-byte
   MemSssa block layout differs between files: the early ones (0x021CBC90, 0x021CC208,
   0x021CC244) pad to state at 0x1D; the later ones (0x021CC6AC, 0x021CC8C4) name palette at 0,
   cellA[3] at 4, cellB[3] at 0x10. The integrator may unify to the later layout; both verify.
3. Two `@NNNNN` initialiser rodata words in dispPush (0x021CC8C4) are declared as
   `g_021DA7B4` and `g_021DA7B8` (byte-array struct PLT4), copied into locals with struct
   assignment, which reproduces the 8-byte ldrb/strb pattern.
4. Levers that mattered: `(unsigned int)type > 3` for the hi compare with an int local (dispPush),
   `(unsigned int)i < 7` for the blo loop (input), `while (!DWCi_SEARCHlStop()) {}` for a
   branch-to-self, swapped if/else arm order to match block layout (endScene2 0x021CBB70),
   store order Count before Choose (DWCi_SceneSetSearch).
5. Function-address callees marked `data` by sdkobj (no DWARF externs such as
   DWCi_SceneSetList 0x021C82FC, SelectWay, RakuButton1, ApList) are listed as `arm` in the
   symbols block, otherwise their ABS32 words do not resolve.
6. DWCi_HLlLoadSet vs DWARF: no name disagreement found. DWARF names procInit1/procError1 kept
   as static names; catalog shows procError1 as procConfirm1 at 0x021CB760.

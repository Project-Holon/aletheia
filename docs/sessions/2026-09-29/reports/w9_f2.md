## The finding: 0x0209B648..0x0209B750 was never data

layout/runtime_arm9.txt, docs/notes/pkt_0209AF34_soft_float_library.c.txt and src/matched/arm9/dmul.c all called the 264 bytes after `__dmul` a "rounding/normalisation table" and carried 66 raw `dcd` words inside `__dmul`. Only the first word (0x0209B648 = 0x7FF00000, loaded by two `ldr r1,[pc,#imm]` inside `__dmul`) is data. From 0x0209B64C the bytes decode as a 260-byte ARM leaf routine (`and r2,r1,#0x80000000`, exponent rebias `subs ip,ip,#0x380` = 1023-127, overflow `cmp ip,#0xff` to 0x7F800000, NaN to 0x7FFFFFFF, denormal path with `lsr ip`, round-to-nearest-even on the 32 discarded bits): a binary64-to-binary32 conversion, the exact converse of the already recorded `_f2d` (0x0209BD38, `add ip,ip,#0x380`). It ends with `bx lr` at 0x0209B74C, 4 bytes before `_s32_to_double`.

## Evidence that it is `_d2f` (independent of the image bytes alone)

1. Vendor relocations: the overlay SDK objects for the three functions (libdwcgsserverbrowsing sb_serverlist.o for prevKeyCompare and FloatKeyCompare, gsxml for gsXmlReadChildAsFloat) call the undefined symbol `_d2f`; the same name appears in the gamespy archives under sdk/TwlDWC (libdwcgscommon, libdwcgsgp). `match.py one` resolves each such PC24 to 0x0209B64C in the original image (14 image call sites by label class, e.g. ov009 0x02183D58, 0x0219F360, 0x0219F378, 0x0219F3D0, 0x0219F3F0, 0x0218C088, 0x0218C0C0, plus blx from ov021 0x021C6BEE and 0x021C73F4 and ov123 0x021D66EC).
2. Semantics: each call site in the vendor objects sits where a `double` is narrowed to `float` (the double arithmetic result passed to `_fgr`/`_fls` compares, and the atof result stored to a float), and the routine body implements exactly IEEE binary64 to binary32 as listed above.
3. Reproduction: the 260 bytes are reproduced by mwccarm 1.1p1 (`-O4,p`, arm asm) with `python tools/match.py one` EXACT.
4. Limit: the vendor MSL runtime.a is not in sdk/, so there is no runtime object to locate against the image with 0 mismatches. The evidence is therefore (1) to (3), recorded through the same table path as `_ll_udiv`/`_u32_div_f` (a curated layout/runtime_arm9.txt row, attested as class `runtime`, ARM only). This is one unit of evidence weaker than a vendor-object match and is stated as such.

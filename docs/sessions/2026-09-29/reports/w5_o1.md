## Levers (idiom candidates)

- **An if-block that ends in `return` can still hold a later store (SBServerListConnectAndQuery).**
  The `bne` past the malloc showed that `slist->inbufferlen = 0` sits inside
  `if (slist->inbuffer == NULL) { ... }`, not after it. Read the branch target before
  reaching for register-allocation fixes.
- **A single strlen feeds two updates (ParseServer).** The object calls strlen once and adds
  the result to both buf and len. Writing `len -= strlen(buf) + 1; buf += strlen(buf) + 1;`
  calls strlen twice, because the compiler does not merge the calls. What matches is
  `#define ADVANCE(b, l) { int n = strlen(b) + 1; b += n; l -= n; }`. The DWARF lists no such
  local; it may have been a block-scoped temporary. The file header says so.
- **Case order in the source sets the layout of an if-chain switch (ParseServer).** The
  object compares against 0, 1, 2 but places the bodies in the order 1, 2, 0. Writing the
  cases in body order (byte, short, string) matches.
- **An explicit `case 4: case 7: break;` fixes a jump-table bound (ListCallback).** Without
  case 7, the table stops at 6. This is the same "jump-table empty cases" lever as in wave 4.
- **A store before the intrinsic clear survives (wsLoginRemoteAuthCallback).** The object
  stores 0 to `response.mCertificate.mIsValid` before the 0x5A4-byte `memset` loop. Writing
  `cert->mIsValid = 0;` before `memset(&response, 0, sizeof(response))` reproduces it. Put
  after the memset, the store is removed as dead.
- `state & 0xfc` gives `and`, while `state & ~3` gives `bic` (ParseServer).

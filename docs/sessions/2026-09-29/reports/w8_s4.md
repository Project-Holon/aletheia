## Near misses (src/pending/ov_sdk/, status MATCH in header, no shard)

- ov009 0x02165DCC WcmAllocApList (204 B): control flow, constants, magic-divide all match; residue is
  10 bytes of register naming only. Original: i=lr, maxBlock=ip (umull hi/lsrs), hoisted block base
  (pHeader+1)=r4. Ours: maxBlock=r4, base=ip. Return is `p` (not 0) after the search loop
  (`if (i < maxBlock) {...} return p;`). Tried: all 120 orderings of the five locals, while/for forms,
  literal 12/208, byte-offset pointer arithmetic, `(cond)?1:0`, unsigned i.
- ov172 0x021BF0B0 get_matrix_sub (172 B): 10 bytes, registers only. Original: i=r4, dx=r5, cx=r6
  (params s,p,ax,cx = r9..r6). Ours: cx=r4, i=r5, dx=r6. Tried decl orders, dx init placement,
  `--cx` / `cx - 1` loop bounds, scoped locals, `return 0` vs `return dx`.
- ov172 0x021C19E4 Yos_JPEGGetMemorySize (156 B): 12 bytes, registers only. Original keeps the x mask
  (samplingx*8-1) in r4 and reuses r2 in place for the y mask; ours holds the masks in r5/r4. The
  switch form (`case 1: break; case 2: y=2;x=y; case 3: x=2`) and `samplingy = samplingx = 1` are
  right (they fixed the control flow and init order). Callee is `_u32_div_f` (header symbol, no extern).
  Tried 24 orderings of the last four locals and dx/dy statement swaps.
- ov172 0x021C2050 SSP_YUV422ToYUV888 (96 B): 35 bytes. Semantics right (Y0|Y1<<8, U|U<<8, V|V<<8 into
  three ushort planes at dst, dst+y, dst+2y, y = w*h/2); original keeps yuyv in r1 and defers the
  stores (temps r5/r6/r8). Tried cb as a separate pointer vs `ybuf[y + x]`, all 6 statement orders.
- ov172 0x021C0370 GetWord (80 B): 27 bytes. Original does not if-convert the two arms and truncates
  the low byte through an `orr ..., lsr #16` on a shifted copy, which we never reproduced; every
  variant (word |= forms, casts, temps, early returns) predicates. The sibling GetLong matched with
  `word = b0; word |= (b1 << 8) & 0xff00; ...` inside if/else with one return.
- ov172 0x021C0C3C Yos_BitWrite (200 B): tool limit, not a codegen limit. gBitLen/gBitCode/gWriteLimit
  are three adjacent file statics (data local); modelling them as `static unsigned long` reproduces
  the loop promotion (ldm of len/code, stm of 8/0), but the ABS32 then targets `.data`, which the
  harness cannot resolve, and the object is 204 B. As extern scalars or an extern struct the
  promotion does not happen (224 B). The masks table is the C++-mangled static local
  `_ZZ12Yos_BitWritePhPmmmE5masks` at 0x021C7150 (type unsigned long[17]).
  Values of the type_size template for jpeg_exif_get_tag_size were read from the image.

## Levers found

- `word = b0; word |= (b1 << 8) & 0xff00; word |= ...` (statement form, not one OR chain) matches GetLong.
- Extra operand (`unsigned long c = *cur;`) hoisted before a run of global stores reproduces load
  order before the stores (SSP_ExifDecode).
- Loop counter init order `for (q = 0, p = 0, i = 0; ...)` fixed register assignment (decode_block);
  swapping the declaration order of two loop temps fixed getmatrix.
- `(con->server ^ flag) != 0` reproduces the vendor `teq` (finished_md5/sha1 share the template).
- Local `signed char t[11] = {...}` gives the template load; symbols entry `@12445 0x021C719C data`
  (jpeg_exif_get_tag_size).
- Duplicated pool word idea did NOT apply to SSP_ExifDecode: a single extern with one pool word is
  right, the second load is the compiler's own reload.

## Levers found (new)

- Inline "socket valid" predicate that must stay materialized (`mov r1,#0 / cmp sb,#0 / beq / ldrsh / tst #1 / movne r1,#1 / cmp r1,#0`, in SOCL_WriteTo, SOCL_ReadFrom, SOCLi_ReadUdpBuffer): write `static inline int f(struct SOCLSocket *s){ int r = 0; if (s != 0) r = (s->state & 1) ? 1 : 0; return r; }`. The `if (s != 0 && (s->state & 1)) r = 1;`, `return a && b` and early-return forms all get folded into branches by the optimizer (tried about 40 forms).
- Stream-mode predicate (`mode == 0 || mode == 4` materialized as `mov r1,#1 / cmpne / movne r1,#0 / cmp r1,#0`): `int r = 1; if (m != 0 && m != 4) r = 0; return r;` in a static inline. `return m == 0 || m == 4;` and `r = 0; if (...) r = 1;` produce the wrong predication.
- Image reloads `socket->state` between two bit tests joined by `||` (SOCL_WriteTo, SOCL_ReadFrom): the second operand is a volatile load (`*(volatile short *)&socket->state & 8`). Byte-exact, semantics-neutral; noted in both headers.
- SOCLi_WriteCallBack: a store followed by an unthreaded `b` shared error tail needs the error value assigned inside the loop arm (`copied = -0x4c; goto done;`) while the top-of-function failure keeps a separate `fail:` label.
- SOCLi_ExecWriteCommand: the cps_socket local_port copy belongs inside the `if (socket->local_port == 0)` arm; the `socket->remote_ip == 0 || remote_ip != 0` arm order gives the image layout.
- Declaration-order permutation search (random 60 to 120 permutations at about 1.5 s each) closed every register-allocation-only residue (WriteCallBack, WriteBuffer, ReadUdpBuffer, ReadCallBack).
- Structure facts recovered from offsets (no DWARF for nested types): SOCLiSocketRingBuffer is 0x14 bytes (size, area, in u16, out u16, waiting queue 8 B), so SOCLiSocketSendCommandPipe.exe_socket sits at 0x10c; send/recv pipe mutex at +0xE0; SOCLiCommandWrite fields +0x10..+0x28 as in sdkobj --types.

## Near miss

- 0x0219C3A4 qr_process_client_message: all bytes are equal, but two relocations are
  wildcarded.
  - @13818 at 0x021A1B64 is the initializer template for `natNegBytes[6]` (FD FC 1E 66 6A B2).
    The template class does not fire because the image holds the same six bytes at other
    addresses too: 0x021A1A64 (another object's @13818) and NNMagicData at 0x021A5A7C.
  - func_0219BA54 is NatNegProgressCallback, a 4-byte static in qr2.o. It has no label and
    no catalog row, and ov021 overlaps its address. This is the same kind of blocker as
    0x0218F880 in w3_o1.

  Carving 0x0219BA54 as its own function would clear the second blocker. The first needs a
  rule for templates that are not unique. The pending file includes string.h through
  `../../matched/arm9_sdk/libc/string.h`, and its header says to switch the path back to
  `../arm9_sdk/libc/string.h` when the file is promoted.

## Levers found (idiom candidates)

- **A const-attribute prototype keeps fields in registers across calls (DetermineNatType).**
  The object loads `nat->ipRestricted` and `nat->portRestricted` once and keeps them in
  r6/r7 across four calls to `abs` (0x02091588). A plain extern prototype makes the
  compiler reload them after every call. Declaring
  `extern int func_02091588(int) __attribute__((const));` reproduces the object exactly.
  mwccarm honours this attribute (`pure` works too). This is the same effect string.h gives
  strlen, but for a callee that string.h does not cover.
- **Swap macros evaluate their argument once per term (SendInitPackets).**
  `htonl(GetLocalIP())` calls GetLocalIP four times, and `htons(GetLocalPort(x ? a : b))`
  calls GetLocalPort twice with the ternary rebuilt each time. Write the macro over the
  call itself; do not use a temporary.
- **Some packet fields are written through the raw buffer (SendInitPackets).** The object
  writes localip, localport and gamename relative to sp (`buffer + 0x0F/0x13/0x15`), one
  byte at a time with the most significant byte first. It writes every other field through
  `p` in r6. `#pragma pack` and `__attribute__((packed))` do not change the layout under
  this compiler (localip still lands at +0x10). What matches is explicit
  `buffer[15..20] = ...` byte stores plus `strcpy(buffer + 21, ...)`.
- **The string.h memcpy intrinsic:**
  - NNProcessData: `memcpy(&p, data, 20/18/21)` becomes the 2-bytes-per-iteration inline
    loops.
  - qr_process_client_message: `memcpy(&cookie, buf + 6, 4)` becomes the 4-byte stack copy.
  - qr_build_partial_query_reply: `memcpy(buf->buffer + buf->len, &cttemp, 2)` becomes the
    2-byte copy.
- **Aggregate zero-init as a statement (gti2CreateSocket).**
  `address = (struct SOCSockAddrIn){0};` adds an 8-byte temporary, so the frame is 0x24
  where the object has 0x1c. `__builtin__clear(&address, sizeof(address))` gives the
  object's two word stores and the right frame.
- **Where the cast sits inside htons (qr_build_partial_query_reply).** Casting the operand
  inside the macro (`(unsigned short)x >> 8 ...`) matches. Assigning the cast to cttemp
  first and swapping afterwards gives a store-reload.

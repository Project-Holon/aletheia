## Near miss: ov114 0x021C26B8 (ghiPostGetHasFilesContentLength)

There are two blockers, and both are outside this lane's write set:

1. **strlen prototype.** The target keeps `data->name`, the report filename, the length and
   `post->useDIME` in callee-saved registers across `strlen` calls, but reloads them across
   `ArrayNth`. mwccarm treats `strlen` as not writing memory only when it is declared in a
   header named `string.h` (the same rule noted in src/matched/arm9_sdk/libc/string.h for
   strcpy/memcpy). If strlen is declared in the .c file, every mismatch is register
   allocation (DIFF). I copied the file into a scratch `inc/string.h` containing
   `typedef unsigned long size_t; size_t strlen(const char *s);` and it compiles
   byte-identical (MATCH, 22 of 24 relocations resolved). Fix: add
   `size_t strlen(const char *s);` to src/matched/arm9_sdk/libc/string.h and include that
   header. That header belongs to the integrator or the arm9_sdk lane, so I did not touch it.
2. **func_02181E20** (ov009, 8 bytes, `ldr r0,[r0,#4]; bx lr`, vendor gsXmlWriterGetDataLength)
   has no symbols_sdk.json row and no matched body. The layout also merges it into a 64-byte
   extent 0x02181E20..0x02181E60, which is missing the next function start at 0x02181E28. Its
   two call sites stay wildcarded, so the file caps at MATCH even after fix 1. This is the same
   blocker as the existing src/pending/ov_sdk/ov114_func_021C2620.c.

## Notes and idioms met

- Data externs: a `data ov114` token on the `symbols:` line made three string sites in
  0x021C4384 (0x021CF170, 0x021CF178, 0x021CF184) "hint contested". Removing the token fixed
  them (docs/idioms/an-overlay-token-on-a-contested-data-site-loses-the-attestation.md). All
  nine files now list data with no region token, which matches the wave-1 ov114 files.
- ghiDoConnecting zeroes its 8-byte SOCSockAddrIn with two word stores through a pointer to
  the local. A `memset` prototype in the .c file produces a call instead, so the file writes
  `u32 *p = (u32 *)&address; p[0] = 0; p[1] = 0;`. The same string.h rule probably makes a
  real `memset` inline. The final `state = engine ? 4 : 5` only matches as
  `if (engine == 0) state = 5; else state = 4;`.
- ghiPostDoPosting: the `first`/`last` arguments must be written as `(... ) ? 1 : 0` so that
  the ArrayLength call is evaluated before both comparisons.
- ghiProcessIncomingFileData: the chunked branch must be the `if` body with the plain delivery
  as the fall-through tail call, and the error path is written `completed = 1; result = 7;`.
  The compiler emits those two stores in the opposite order.
- gsDebugFormat (0x0217D254), GOAGetLastError (0x0217ED54), gsimalloc, current_time, socket and
  similar are ov009 addresses and carry the `ov009` token. OS_SPrintf (0x02084F40) and
  strlen/strstr/strchr/strcmp are ARM9 and carry no token.
- Name disagreements: none. The DWARF prototype for GOAGetLastError is `(void)`, but every call
  site passes the socket in r0, so the extern takes an int.
- No asm bodies.

## Levers found

- sdkobj.py crashes on Windows for members present in several archives (`tried` line splits on "/"); worked around with a wrapper that forward-slashes relpath (scratchpad only, tools untouched). Rows for rakuraku.o, sceneoptmovcomm.o etc. were affected.
- `mov r0,#0xc; sub r1,r0,#0x10` is DWCi_HEAPlAllocEx(12, -4).
- Second use of a global holder address as `&g` after reading g reuses r4; writing the free call as `(void *)0x021DE6A8` reproduces the separate pool literal (OBJlEnd, same form as MSGlEnd).
- `int lcd = 0; if (p >= base) lcd = 1;` gives `mov; cmp; movhs` (OBJlDelete); the ternary/compare-assign form does not.
- `cmp hi,#0; cmpeq lo,#0` with hi loaded before lo is an `unsigned long long == 0` test (button).
- Store to a byte global then reading it back for array indexing (`R[g.idx]` after `g.idx = i`) lets the compiler forward the (u8) value and orders the strb after the ldrh loads (input); explicit temps do not.
- if / else if / else chain with duplicated tails keeps the branchy shape; folding the store into a ternary or a common `snd` local makes the compiler predicate or hoist (cbMov).
- Thumb callees from ARM (ATERMi_ApConfig*) are declared normally and listed `thumb` in symbols; blx is a relocation-only difference.
- Struct layouts recovered: OVR info 0x1a0 with queue at +0x19c, list at +0x198, two size nodes at +0x180 and +0x18c; FocusPos = {u8 idx, u8 flag, pad, ptr}.

## Levers found

- Reverse-of-listing declaration order held for most (SocClose: error then elapsed, i.e. the reverse of
  the listing; ExecReqQueue, cancelAllRequests, SendData, GetPostContentlength).
- A struct field that must be re-read from memory every time: `volatile` on the field. `Req *volatile req_p` in
  cancelAllRequests (three loads of the same field, no CSE) and `volatile int headerLen` in GetResponseHeaderAll.
- Case fold: `((c >= 'A') & (c <= 'Z')) ? c + 0x20 : c` (bitwise AND), operand order `TOLOWER(c) == TOLOWER(*str)`
  matters (compareTokenN).
- `while (blockidx-- != 0)` for the block walk in loadFromHdrRecvBuf; `if (pos + len <= headerLen) { ... return 1; }
  return 0;` with the guard first-class reproduces the trailing `return 0` block.
- Local aggregate `unsigned int rdx[9] = {...}` reproduces the ldm/stm copy from template @12945; the header
  line is `@12945 0x021CDFA4 data` and statement order `p[len]=..; b=1; n-=..; len++` fixes the schedule.
- checkTagPost: block-local `char *tp = (char *)req_p + n; char t;` declared without initialiser, `c = tp[0x38]`
  before `t = g[n]`, gives the exact r6/r7 assignment.
- htons spelling for SocConnect: `(u16)((((u16)port) >> 8) & 0xff) | ... ((((u16)port) << 8) & 0xff00)`.
- SaveBuf/BufFull tails: see the parked notes above.

## Catalog / DWARF disagreements (arity)

Several image functions take extra leading register arguments that the DWARF prototype does not list:
NHTTPi_SocClose is `(unused, req, socket)`; NHTTPi_SocSSLConnect `(unused, unused, req, socket)` (SocConnect
passes its own r0, r1 through); NHTTPi_resolveHostname `(unused, hostname)`. NHTTPi_SocCancel is called with three
args (mutexInfo, req, arg) although DWARF lists two. Drafts use the arities the image shows.

## Levers found (idiom candidates)

- **md5.o is table-driven, not the RSA reference shape.** CPSi_md5_block runs four `for (j = 0;
  j < 4; j++)` loops. Each iteration does four steps that index `x[itab[i + k]]` and
  `ktab[i + k]`, with a running `i += 4` carried across all four loops. The step is written
  `a += f(b,c,d) + x[..] + k[..]; a = ROTL(a, s) + b`. It matched on the first compile.
- **An unsigned last operand keeps two subtracts separate (jpeg_encode_ifd).**
  `long_data - thumb_len - 2 - 6` folds into one `sub #8`. `- 2 - 6u` keeps `sub #2; sub #6`,
  which is what a trailing `sizeof` would give.
- **The for-increment order sets the instruction order.** `entry++, i++` puts `add entry`
  before the signed-char `i` update. `i++, entry++` reverses them.
- **A then-block placed first in the object is the `<=` test (jpeg_encode_ifd).**
  `if (size(entry) <= 4) set_value(); else { write offset }` matches. The `> 4` form swaps the
  blocks.
- **`while (A) { if (!B) break; ... }` versus `while (A && B)` (ProcessMainListData).** The
  object tests A before the loop, tests B at the top of the body, and branches back from the
  bottom A test to the B test. `while (A && B)` compiles to a jump to a bottom condition
  instead.
- **The `moveq r0, <zero reg>` loop condition is a conditional zeroing.** The object computes
  `r0 = inbuffer ? keyoffset : 0` and loops while `r0` is non-zero. That comes from
  `if (slist->inbuffer == NULL) keylen = 0; } while (keylen != 0);`. The `&&` forms in either
  order compile to two branches, and they lose the hoisted zero register (which also drops
  r3/fp from the push).
- **Split `*p++` to fix register allocation.**
  `expectedelements = (unsigned char)*inbuf; inbuf++;` swapped inbuf/inlen into the object's
  r5/r6. `*inbuf++` gives the same instructions but the opposite coloring. Neither the
  declaration order nor the initialisers moved it.
- **Merged guard (DWCi_CheckProfanityAsync).** The five argument checks form one `||` chain
  with a single return. Split into two `if`s, they give two epilogues. `if (timeout <= 0)
  10000; else timeout;` gives `ldrle/strle ... strgt`.

## Notes

- **Header parsing (tooling behaviour, not changed).** A `symbols:` line with the token `arm9`
  (for example `func_02092364 0x02092364 arm arm9`) silently ends the block. Every data line
  after it is then dropped, and a sole-ref data site shows as unresolved. Leave arm9 callees
  without a region token.
- **String access.** `#include <string.h>` does not resolve from src/pending/ov_sdk. The house
  header is `../arm9_sdk/libc/string.h` from src/matched/ov_sdk. From pending, it is reachable
  as `../../matched/arm9_sdk/libc/string.h`. Only through that header does memcpy become the
  inline byte copy that the object shows.
- **exifenc.o statics.** The file statics sit in one block based at dateTimeDataFlag
  (0x021CADF0): +0x04 is the write position and +0x14 is the output buffer. A struct overlay
  named by offset matches.
- **Names.** No disagreements. The DWARF names and the catalog names agree for all four rows.
- **No asm bodies.**

  0x02096594.

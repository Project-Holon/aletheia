## Near misses

- 0x021F3D04 MBi_MakeGameInfo (240 B): every instruction matches except one store placement (8 mismatching words, all from one shift). The original emits `mov r8,#1; ldr r0,[r5,#0xc]; mov r1,r6; mov r2,r8; strb r7,[r6,#0x4b2]; bl ReadIconInfo`; ours emits the `strb` before `mov r8,#1`. Tried about 14 variants: statement position (before/after the flag init, between the calls), comma expression in the call arguments, local declaration permutations. The or of the two failure flags needs `icon_disable = (call1 == 0) | (call2 == 0)` through two locals then `icon_disable = a | b; if (icon_disable)` to get `orrs r0,r8,r7`. Draft keeps that form.
- 0x021F2E58 MBi_calc_sendblock (124 B): 14 words differ. The original keeps the per-file base (`mla ip, ...`) live across the function and rebuilds `add r0, ip, #0x1d00` in an out-of-line tail (`strh r3,[r0,#0x48]` after a `bhi` for the b > a arm), with the second halfword in r3; ours predicates the store (`strhhi`) and uses r1. Tried about 9 shapes (per-access casts, halfword pointer, swapped if/else, goto tail, separately re-derived store address). The struct base is `mbc + file_id*0x5D4`, fields at +0x1D48 (a), +0x1D4A (b), +0x1D4C (u16 gate), +0x1D52 (byte gate); logic: if (b > a) a = b; else if (a <= b + 2) a = a + 1.

## Levers and notes

- mbss (0x021F6EF4) is the 0x2C-ish send-status struct addressed from a single literal-pool word; the catalog names its base `sUnlockFunc`. Raw byte offsets through one `unsigned char g_021F6EF4[]` extern match; fields used: +0x18 list head, +0x1C current, +0x20 data ptr, +0x24 state, +0x26 seq, +0x28 attr.
- ReadyBeaconSendStatus: the first `mbss.head == 0` test must read the head through `*(int *)`, the later reload through the pointer type; with matching types the compiler CSEs the load into `moveq r0,r1` (this is why it verifies EXACT*, no volatile is used).
- UpdateGameInfoMember: `unsigned char playerNum = 1;` initialised at the declaration (before the CpuCopy16 call) puts it in r4; assigning it after the call gives r3.
- ParentRecvData: the per-child callee takes the ReadMPData result in r0 (`func_021F2200(datap, i)`), not `arg`.
- ResponseRequest: locals declared req, state, enabled (reverse of the sdkobj listing) fix the register order; the `ack` param shares r4 with `req`.
- SendGameInfoBeacon: `while (1) switch (state)` with cases 0,1 sharing the Ready call, 2 and 4 init calls that loop, 3 and 5 send and return, empty case 6.
- mbc (0x021F6FA0) is a pointer variable (`char *`), state array at +0x14E8 stride 4, child names at +0x1340 stride 22, child slot 0x1772.
- Callees: ARM9 callees carry no region token; ov107 callees carry `ov107`.

## Levers found

- Locals: reverse of the sdkobj listing worked for ReloadCache, TaskThread and getHeaderValue slots, but
  it is not universal: in SendProcPostDataRaw the pointer locals had to be declared sysInfo, threadInfo,
  mutex, reqInfo, req, bgn (earlier-declared gets the lower callee-saved register).
- A callee that appears in the listing with `mov r0, <sysInfo reg>` before the bl takes that argument
  (GetBgnEndInfoP(sysInfo) in SendProcPostDataRaw); omitting it changes the sysInfo live range and every
  register after it. Without the mov (ProxyProc, ReqEnd) the no-argument form is right.
- Two same-named locals in nested scopes (TaskThread bak_cpsr in two blocks) are needed to get one
  register for both and a different one for callback.
- TaskThread: `Task *volatile list`, and `trg = p->list; p->list = p->list->next;` (second load kept)
  gives `ldr r0; mov r4,r0; ldr r1,[r0]`; `(trg = p->list)->next` does not.
- findNextLine: the whole body inside `if (pos < limit) { init; setup; for (...) }` with one shared
  `return -1` at the end reproduces the double guard; an early `return -1` compiles to conditional pops.
- HostAddrProc: `if (strlen == 0 || strcmp != 0) { resolve } else { hostaddr = pre }` puts the resolve
  block in line; the two error returns need `return 0` in each arm.
- ThreadProxyProc: swapping two adjacent constant stores (`result = 10` before `sendBufwp = 0`) fixes
  the temp register used for the reqCurrent load.
- CommThreadProcMain: a `while (!isThreadEnd)` with `continue` at every exit reproduces the shared ReqEnd
  tails. The jump table for `switch (SendProc)` starts one instruction after the `addls pc` (pc+8): the
  `b` right after the addls is the default arm, table[0] is the next word. Case arms must be written in
  image block order (case 2 before case 1 for ProxyProc; case 2 then `case 1: case 3:` for SendProc).
- ThreadReqEnd (near miss below): swapping the two stores in the doCancel block (`result = 8` first)
  fixed the store/constant order.

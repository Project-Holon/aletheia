## Findings worth an idiom

- Locals: the sdkobj `variable` list is in reverse declaration order (declare the last-listed first); this fixed register naming in CPSi_TcpConnectRaw and tcp_write_do.
- A `static inline` helper holding a `volatile` local reproduces the `str r1,[sp]; ldr r1,[sp]` thread-id spill (receive_packet).
- Typed structs instead of char-offset casts fixed the CPS_SocGetEport register residue the earlier draft blamed on allocation.
- tcp_write_do: the statement order `limit += ackno - save; r = limit; save = ackno; limit = r - 1; if (r == 0) thislen = 0` (RLSZ) puts `mov r6,r1` before the sub; other orders leave a 6-8 B swap.
- Byte swap of a u16: `(v >> 8) | (v << 8)` yields lsl first, orr with asr.
- 0x021A826C is one network struct (NetVars): +0x1c dhcp_server_ip, +0x50 myip, +0x04 send_win (u16), +0x08 ping_seq (u16); 0x02150FEC+4 is the current thread pointer, thread+0xa4 its socket.

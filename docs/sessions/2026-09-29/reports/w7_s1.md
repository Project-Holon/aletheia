## New levers

- Unrotated loop via `(i < size) ? 1 : 0` (docs/idioms "loop entered by a branch to its bottom test"): reproduced the
  `b test` entry of the IRCi_Send and IRCi_Write loops. Plain `for`/`while` variants give the guarded form, 4 B more per loop.
- `volatile` on a struct byte read in a wait loop (`while (m->st != 2);` in USBAPlEnd) stops the compiler folding the loop to
  a bare compare and puts the load in the loop.
- `volatile unsigned short tmp` reproduces the stack round trip `strh/ldrh [sp]` in CommWrite's `return (u8)tmp`.
- Post-increment through the struct field written as two statements, `*p->rp = reg; p->rp++;`, reproduces the second
  reload of `p->rp` (a single `*p->rp++ = ...` fuses the load).
- `(u32)f(...) >= 96` gives `movhs` where a plain long compare gives `movge` (GetSegmentLength).
- `ptr = sendbuf; *ptr++ = type;` gives `mov ip,r1; add ip,ip,#1; strb r2,[r1]` where `ptr = sendbuf + 1` does not; a
  `u8 type = hdr->type` local before the store stops the reload of hdr->type after the u8 store (MakeParentSendBuffer).
- Switch-shaped range checks: failure exits as `break` into one trailing `return 0` (IsAbleToRecv); `default: return 0;`
  after a `break`-ing last case, with the trailing `return 0` after the switch, gives the tail order of IsAbleToLoad.
- `irc_lock_id == -3` and `= -3` (a `u16` against -3 as int) reproduce `mvn r4,#2` and the later `add r0,r4,#0x10000`.
- `_ll_udiv` is emitted by `(t1 - t0) * 64000 / 0x82EA` over `unsigned long long`; list `_ll_udiv 0x0209C00C arm` in symbols.
- Pool-word aliases: `g_0217AC90_b` for the address-of use and `g_0217AC90` for field uses (IRCi_Write), `g_0217ABDC` for
  `sIrcBuf+4`. Statics that mwcc merged into one section base (`req_data_piece_idx`, `myUnitNumber`, `retry_count`,
  `sUnlockFunc`) must be typed as the struct or array the object really indexes.
- Locals in reverse of the sdkobj listing worked for taskEnd1, dispCell, MB_GetSegmentLength, ReadFromCache; dispCell needs
  `if (cy >= y && cy < 192) eff = NONE; else eff = HIDE;` (not the `||` form) for the cmp/movlt/blt layout.

## Near misses (about 12-15 attempts each)

- 0x021D0DE0 cbWm (4 B, size-exact after 4 B). Object: `cmp id,#2; popne; mov r0,#2; strb r0,[r1,#0xb94]; pop` (early return,
  then an unpredicated store); every spelling compiles `moveq r0,#2; strbeq; pop` (if/else, switch on id, early return,
  inline setter, local base). Register allocation, switch order (4 before 5) and the base in r1 through a padded struct are
  right; only the predication of the state store differs.
- 0x021D0CEC DWCi_USBAPlEnd (2 B). Everything matches except `ldr r1,[r0,#0xb90]; cmp r1,#0` (object) versus
  `ldr r0,...; cmp r0,#0` before the `DWCi_TSKlDeleteEx(0)` call; tried field types (int, void*, unsigned, volatile), a local
  copy, if/else and ternary forms. The `while (st != 2)` loop needed `volatile` and now matches.
- 0x021D15F0 taskMove (130 B). Object keeps constant 0 in r4 across calls (`mov r4,#0` early, used as the cell index, the
  TSKlForm kind and its work argument) and pushes {r4,r5,r6}; ours rematerialises 0 and pushes {r3,r4,r5}. A local
  `int k = 0` (also const, static const, register) is folded; if/else inversion did not change it. The rest (pool words,
  the `type == 5` ternary with `bne`/`b`, `g_021DAA00[type][0]`) is right. pushButton (same constant hoist) matched with
  plain literals, so probably the original has one more use of 0 that the DWARF does not show.
- 0x02179F74 IRC_Init (11 B). Object: `mov r3,#0xff; ldr r0; mov r2,#0; strb r3,[r1,#1]; str r2` (0 materialised before the
  byte store, base r1 kept live); ours: `mov r2,#0xff; ...; strb; mov r1,#0`. Store-order and typing variants (12 tried) only
  move the residue. The original probably has separate statics merged by mwcc into one section base.
- 0x0217A034 IRCi_Send (16 B, size-exact after the `? 1 : 0` lever). The counter is r5 in ours and r12 in the object (the
  object keeps the zero used by the header stores and the loops in ip), and the two checksum bytes are stored in the other
  order. Decl-order permutations of all four locals and int/unsigned/short counter types did not move it.
- 0x0217A8EC IRCi_Write (20 B). With `if (i + 1 == size)` the registers and layout equal the object except for the hoisted
  `sub sb,r6,#1` (object hoists `size - 1` into r9 after `mov r5,#0`; the `i + 1` form has `add r0,r5,#1; cmp r0,r6` in the
  loop). Writing `i == size - 1` hoists into r4 and shifts every allocation by one register (31 B). A local for `size - 1`
  did not help.
- 0x021F6890 MBi_MakeParentSendBuffer (7 B). Everything matches except r1/r2 swapped for `b` and `a >> 8` in case 4 (object:
  `ldrh r3; ldrh r1; and r2,r3; and r0,r1`). `u16 a, b` locals at function scope are needed (a reload otherwise);
  decl-order permutations and int/unsigned local types do not fix the swap.

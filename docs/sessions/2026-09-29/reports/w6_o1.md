## Levers

- **A `const` pointee lets loads hoist past stores (SOC_Startup).** The mangled static name
  `_ZZ11SOC_StartupPK9SOCConfig` shows the parameter is `const SOCConfig *`. With a plain
  pointer, every config load stays after the previous static store (306 B differ). With
  `const`, all loads are scheduled up front, as in the object. Read the `PK` in a mangled
  local-static name as a prototype hint.
- **Static blocks anchored on another function's local static.** soc.o, input.o and
  mb_wm_base.o reach their statics through one pool word named after an unrelated symbol
  (hostip_1 of SOC_GetHostByName, fold of DWCi_IPTlCheckFold, WM_DMA_NO). A struct overlay
  at the anchor address, named by offset, resolves as sole-ref. SOC_Startup also relocates a
  second word against soclConfig itself (anchor +0x50) for the call argument, so that word
  is written as its own extern.
- **Declare the vendor `@N` string templates in `symbols:` (initGraphics).** String literals
  resolve once the vendor names (`@20575 0x021DA4E8 data`, and so on) are in the header.
  A `char PLLT0[] = "..."` local compiles to the object's halfword copy loop.
- **Pointer-stepping loop (initGraphics).** `src = p + 0xc0; dst = p + 0x40;` before the
  loop and `+= 0x20` inside it matches. Index arithmetic inside the loop does not.
- **for-increment with a comma (readTouch).** `for (i = 0; i < 4; i++, idx = FX_ModS32(idx +
  4, 5))` puts `add i` before the call, as the object does.
- **Late `touch = FALSE` (readTouch).** Assigning the bool after `last = work->touch`, rather
  than initializing it at its declaration, keeps the zero out of `last`'s moveq, so `i`
  reuses the register instead.
- **Body inside the case (MovUserID).** A switch whose trailing work sits inside `case
  4: case 5: case 6:` gives direct `pop` table entries for the other cases. Putting the work
  after the switch gives `b` entries.
- **Two conditional returns (ThreadConnectProc).** `if (x) { r = 14; return 0; } else { r =
  5; return 0; }` gives the object's movne/moveq pair. A shared `return 0` after the if/else
  does not.
- **`0x8000u >> n` (big_power).** The unsigned constant gives `lsr`; plain `0x8000` gives
  `asr`.
- **Element-first indexing (MB_DisconnectChild).** The object adds `fid * 0x5d4` to mbc
  before the member offset. `mbc->fileinfo[fid].f` folds the constant first (48 B differ).
  Four other spellings failed: `(fileinfo + fid)->`, `(&fileinfo[fid])->`, an int index
  and a u32 index. Stepping mbc by whole slots (a `FILEINFO(id)` macro over
  `(u8 *)mbc + id * sizeof`) matches. The file comments on this. The integrator may want to
  look at the shape.
- **Hidden block locals (MB_DisconnectChild).** The `mov r6, r7` copy comes from a
  block-local `u16 child = aid;`. The DWARF lists only `aid`.
- Local statics as externs: prev_fid (`_ZZ28MBi_CommParentSendDLFileInfovE8prev_fid`)
  resolves as sole-ref when it is declared plainly as `g_021F6E48`. Adding an `ov107` token
  to its symbols line made the hint contested, so data lines carry no region token.
- The header parser (SYMBOL_RE) accepts only `ovNNN`/`twl`/`ov230d`/`aN` as a fourth token.
  An `arm9` token silently ends the symbols block, so arm9 callees carry no token.

## DWARF disagreements

- NHTTPi_ThreadConnectProc: the DWARF has NHTTPi_SocClose(req_p, socket) and
  NHTTPi_SocOpen(void). The call sites pass (mutexInfo_p, req_p, socket) and req_p. The
  file uses the call-site shapes, and its header says so.
- MBi_CommParentSendDLFileInfo: the DWARF hd type is 6 bytes (type, fid, and a u16 left
  unused here).
- The catalog names and the DWARF names agree for all ten rows.

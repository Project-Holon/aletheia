## The harness change (tools/match.py, one block, ~110 lines plus selftests)

Before: a relocation against `.data`/`.bss` (mwccarm's spelling for a file-scope or function-local static)
was resolvable only through the vendor-object `.bss` rule, which needs an ARM9 SDK function and the static
module's .bss range. Overlays and non-SDK files could not name it.

Now (section "section-relative relocations to the file's own data", before resolve_relocations()):

- extract_function() records, for each section symbol the function relocates against, that section's
  alignment, size, NOBITS-ness and the compiled object's own data objects with their offsets
  (`FuncBytes.secs`).
- Each static is written in `symbols:` as `name 0xADDR data` under its compiled-object name (for a
  function-local static the mangled `_ZZ...` name, for a file static its C name). A declared static at
  address A and offset O implies base A-O.
- Accepted only when: every declared static of the section implies ONE base (otherwise refused, reason
  lists the bases); the addend lands inside a declared static; the base meets the section alignment; a
  PROGBITS section (.data) lies wholly inside the image of the compare region (a NOBITS .bss has no such
  bound); and the ordinary attest() finds a witness at base+addend, called with the declared static's own
  region hint and alignment. No new evidence class: the class reported is whatever attest() gives
  (sole-ref in all three entries, subkind self).
- Precedence: an explicit `.bss 0xADDR data` line (vendor route) still wins, and a `.bss` reference with no
  declared static still takes the vendor route with its old message, so no existing entry can change.
  `.data` and other section symbols with nothing declared refuse with a message naming the missing
  `symbols:` lines.

Weakest point, stated plainly: the declaration of a static that no relocation of this function references
(e.g. gBitCode at +4, reached only as [r4,#4]) is checked for layout consistency only, not for evidence.
It cannot make a byte comparison pass that would otherwise fail, since the compared bytes come from our
compile; it only fixes the base that the referenced static's witness is tested at.

## Follow-up worth knowing

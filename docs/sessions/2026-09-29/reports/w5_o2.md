(libcrypto). All are ARM, dsi/1.1p1, -O4,p, c99, and the objects are stamped 4.0.0.1024.

object's size and stays in pending.

## Near miss

- **ov009 0x02159A80 dt_ack**: 1384 B compiled against 1384 B, with 820 concrete bytes
  different. The control flow, the 10-entry state switch, the block order and all 34
  relocations match. The residue is register allocation around the out-of-order chunk loop:
  - The object spills `enabled` to `[sp]`, which DWARF confirms (`[fb+0]`). It keeps `ci*12`
    in fp and `soc + ci*12` in sl across the retry that follows `push_rwin_chunks`, and that
    back edge lands at 0x118, after the address computation.
  - This build keeps `enabled` in fp. The retry loops back to the `mul` at 0x10C, so the
    address is never held, and sb/sl shift from there on.

  The object also reads the loop-top `start`/`len` through `[sl,#0x70]`. The branch bodies
  go through `soc->chunks[ci]` (`add r4,r6,#0x70; ldr [r4,fp]`), so branch 2 reloads
  `start`. That points to a pointer or macro at the loop top that DWARF does not list.
  DWARF omits locals elsewhere in this object too: scavenger's `now` is not listed.

  Tried without success:
  - goto retry, inner `for(;;)`, inner `while(1)`, `while`+`continue`, and a `ci--` retry;
  - a `CPSSocRcvBuf *` local;
  - a `CPSSoc *` offset pointer. This gets the sl base, but through `mla`, with no separate
    fp;
  - the window end as `dup`;
  - `volatile enabled` (experiment only: not even that makes the compiler hoist the address).

  Next try: the loop-top reads spelled through a pointer whose value is `soc + ci*12`, with
  `ci*12` also named, so that both fp and sl exist.

## Levers found (idiom candidates)

- **HTONS over a call result needs a local (_send_tcp).** The house `HTONS(x)` names its
  operand twice. `HTONS(invert(calc(data, len, calc(...))))` therefore compiles the whole
  checksum chain twice. The extra uses of `len` then give it the callee-saved register that
  `flag` has in the object, and 12 bytes shift. `u16 sum = ...; HTONS(sum)` gives exactly
  the object's code. DWARF has no `sum`; the local is the macro's single evaluation.
- **Two spellings of the same inline test compile differently (scavenger).** Case 0 of the
  DHCP switch sets a flag local (`denied = 0; if (cb) { if (cb() == 0) denied = 1; }`). Cases
  1 and 2 use a ternary helper (`cb ? cb() == 0 : 0`, giving moveq/movne). Each case matches
  only in its own spelling.
- **A failure-first `if` puts the failure block first (scavenger case 0).**
  `if (!discover() || !request(...)) { fixed; } else { ... }` puts the failure branch ahead of
  the success path, as in the object. The positive `&&` form puts the failure block after it.
- **A `case 3: break;` keeps a 4-entry jump table (scavenger).** Without it the switch
  lowers to a compare chain.
- **BN_div (SSLeay 0.9.x shape).** The BN_CTX is used as `&ctx->bn[ctx->tos + k]` with no
  start/end calls. The non-BN_LLONG path uses `mul64`, which recomputes `t2`/`t3` inside the
  `for (;;)`. `BN_sub`/`BN_add` results are not checked in the loop. `bn_fix_top(snum)` comes
  before the `rm` shift, and `neg = num->neg` is read before `BN_rshift`. It matched on the
  first compile.
- **Unsigned header-length shift.** `((p[12] & 0xF0u) >> 2)` gives `lsr`; a plain `0xF0`
  gives `asr`.

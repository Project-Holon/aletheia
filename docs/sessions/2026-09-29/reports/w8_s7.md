## Near miss: 0x02166600 WCMi_MergeToBuffer

Semantics are right; layout differs. Original: switch cmp 1 / cmp 2 with the shared `mov r6, r1` block emitted after the compares
(default and case 1 share it), case 2 out of line, totalLen in r4, headerLen r5, copyDest r6. Every form tried (case 1 + default
merged, separate arms, if chains, goto tail, copyDest pre-set, decl order swaps, swap-formula variants) makes mwcc hoist
`copyDest = sendBuf` above the compares (`mov r5, r1` before `cmp r0, #1`), shifting the registers and using `ip` for the
`headerLen + bodyLen` temp. A variant with no default arm (copyDest left unset on the default path, semantically wrong) gets the
register allocation right and differs in only 10 words, with the byte swap `((unsigned char)len << 8) | (len >> 8)` closest
to the original; the residue is which arm owns the `mov r6, r1`. Unresolved lever: something that keeps `copyDest = sendBuf` from
being hoisted while keeping both paths assigned (perhaps the vendor arms differ in type, e.g. a struct member address).

## Shape notes

- gpiConnect: the DWARF prototype lists 12 parameters, but the object reads
  newuser/blocking/callback/param one word higher (sp+0x44..0x50). An unused word
  parameter sits between cdkey and newuser (spelled `firewall`; the body forces
  `iconnection->firewall = 1`). This is a DWARF/object disagreement and is noted in the header.
- gpiDisconnect: gpiDestroyPeer's DWARF prototype has one parameter (peer), but the call
  passes (connection, peer). The file declares the two-argument form. The loop tail is
  `while (!gpiProfileMap(...)) {}`.
- gpiCallCallback: types 2 and 11 are separate `else if` branches with identical bodies.
  The compiler cross-jumps them, and does the same for 7/15, 8/13 and the tails of 9 and 14.
  One `||` branch compiles differently. In the type 3 block, `int i;` must come before `arg`
  so that i gets r5 and arg gets r6.
- gpiProcessRecvBuddyList: the 28-byte byte-store zero loop on the newly allocated
  GPIBuddyStatus is `__builtin__clear` (no memset call). Written as
  `for (j = 0; (j < sizeof(buffer)) && ((c = str[j+6]) != '\0') && (c != ','); j++)`, the copy
  loop keeps the object's jump-to-test entry. A loop with an inner `break` drops the first j test.
- gpiStartConnect: the port-retry `while` sits inside its own `if (anError != 0)`. The
  object tests the first init result once, and on success it skips both the loop and the
  failure test.
- gpiSaveKeysToBuffer: the Base64 length (`n%3 ? 4-n%3 + n*4/3 : n*4/3`, where n is strlen
  of the key) and the encode call are `static inline` helpers. That way the key pointer is
  loaded once per use, as in the object (a macro reloads it after every strlen call). In the
  second loop the advance helper takes `char **` so that `+=` lands in each branch.
  Candidate idiom: "a field loaded once across several calls is an inline parameter".
- gpiDeleteBuddy: gpiBuddyDeletedLocally runs outside the `sendServerRequest` if. The
  object frees buddyStatusInfo, clears it, and then reads extendedInfoKeys through it. The
  C keeps that order.

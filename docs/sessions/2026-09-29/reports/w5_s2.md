## Near misses (about 12 attempts each)

- 0x021D3638 DWCi_MOV_WH_Initialize (120 B, size equal): only register assignment differs. Object: `mov r5,#0` (shared zero) first and `mov r4,#1` later, returning `moveq r0,r5; movne r0,r4`. Compiler gives the zero r4 and the one r5, and the return as `moveq r5,r4; mov r0,r5` (or, with `int ret = 0`, right stores but the tail `movne r5,r4; mov r0,r5`). Tried if/return, ternary, `!= 0`, `!!`, local `ret` init 0/1, `f52 = 1` moved first, a `t = 1` local. State struct reached through the pair at g_021DE660 (trace pointer, then work pointer at +4); the literal is g_021DE660 with word offset 4 (I declared the pair as a struct, so the reloc resolves).
- 0x021D5904 DWCi_FNTlEnd (76 B original, compiled 72 B, 5 bytes differ): object reloads the MemFont literal after the loop (`ldr r0,[pc]; ldr r0,[r0]`) and uses a second literal-pool entry for the `&MemFont` argument to DWCi_HEAPlFree_ (`ldr r0,[pc,#8]`). Compiler keeps r4 = &MemFont across the whole function and emits `mov r0,r4`. Tried for/do-while/braces, a static inline loop body, a local `MemFont *m` for the loop, a byte-offset cast.
- 0x021D5950 DWCi_FNTlFormEx (220 B, size equal, about 20 bytes differ): all calls and stores match; residue is scheduling. Object: `mov ip,#0x6600000` before `cmp r7,#1`, and in the tail `ldr r2,[sp,#0x24]; ldr r0,[MemFont]; mov r1,#1; str r4,[r4,#0x18]; add r0,r0,r2,lsl #3`. Compiler swaps the mov/cmp pair and loads the global before the stack parameter. Best variant: `base = 0x6600000; if (lcd != 1) base = 0x6400000; base += name * 128;` after `*obj = ...`, then `pCanvas` before `pFont`. Ternary, `&base[name*128]`, `font + MemFont->font` operand swaps did not change it.

## Levers and notes

- `static inline` helper is the lever for the 6-byte MAC compare in DWCi_MOV_MBP_GetPlayerNo (plain `static` is not inlined; inline gives the exact hoisted `wb+0x24` base and single `mul`).
- MBP disconnect-all body (KickChild, StartDownload, StartDownloadAll, StartRebootAll): a block-scope `u16 mask = ~(1 << aid);` declared before OS_DisableInterrupts inside the failure branch reproduces the object (mask precomputed into a callee-saved register, wb reloaded per field). The success/ack branches use inline `(u16)~(1 << aid)`. Branch polarity: the ack==0 (disconnect) path is the fall-through, so test `!MB_CommResponseRequest(...)`.
- Struct passed by value on the stack (NNSi_G2dTextCanvasDrawText / DrawTextRect, 2-byte struct of two signed chars): `Pair p = {0, 0};` initializer, not two assignments, gives the address-taken zeroing through r4; jump-table `switch` cases ordered `0/7, 1/2, 3/4, 5/6`.
- MemFont layout: font[2] (8 B each), canvas[32] (48 B), bg[2], unused (queue) at +0x670, file[2] at +0x674, renew as `u8[2]` (sizeof 0x680, not 0x684; the alloc size is written as literal 0x680).
- moveid work struct (g_021DE668): sSendBuf 0, sRecvBuf 0x100, data_seq_num 0x200, send_data_kind 0x202, error_cnt 0x204, sRecvFlag 0x208, userinfo buf 0x248, tgid 0x648, sChannel 0x64a, dummy_userinfo 0x64c, dummy_gShareData 0xa4c, mov_stt 0xa90, mov_stt_old 0xa91, language 0xa92, language_send_f 0xa93, data_send_cnt 0xa94, start_wait_child_cnt 0xa98, cnt 0xa9c, sChildInfo 0xaa0, p_user_info 0xaa4, p_mov_data 0xaa8, reset_kind 0xaac, sShareDataPtr 0xab0, game_registry 0xab4 (ggid at +0x14).
- DWCi_MOVFinalize uses an if-chain on the byte state (`switch` builds a 30-entry jump table and does not match); the 4/5/6/13 group always calls MB_EndToIdle unless (state == 4 and start_wait_child_cnt < 6).
- _DWCi_MOVSearchChannel: `switch` with `break` (not `return`) in every case; case order 1, 7, 0, 9, 3, default.
- Callee naming: same-overlay callees carry the `ov016` token; ARM9 callees and MB_* game/unknown callees (0x021F....) carry none, matching the existing DWCi_MOV_MBP_Cancel file. DWCi_MOV_MBP_GetChildInfo (open row) attests as sdk.
- DWARF/catalog names: sdkobj reports the FNT/FOCUS "Ex" callees exactly as used; no disagreements found.

## Findings worth an idiom

- Callback wrappers: zero the (message,len) pair BEFORE the two level increments (`if (!len || !msg) {msg=0;len=0;}` then `x->level++; y->level++`); the other order gives a r1/ip register swap and a scheduling shift (ReceiveFilterCallback, ConnectAttemptCallback).
- Locals declared in reverse of the sdkobj list gave the right registers, but for gti2RemoveHoldMessage the correct order was moveAfter, shortenBy, num, i, moveEnd (dead `moveEnd` is kept by the compiler and must be declared last).
- Duplicated tails: a function returning `ret` in two branches needs `ret = 0` written inside each branch with a `return ret;` in each (a single merged tail changes the layout). A single shared `return 1` at the end needs an if/else-if structure (HandleAppReliable).
- `send = 1; if (!f(..., send)) send = 0; return send;` reproduces the reuse of a parameter register as constant 1 and result (HandleHostUnreachable).
- 4-byte memcpy of a local via `unsigned char *d = (unsigned char *)&x; d[0]=m[4]; ...` reproduces the 4 ldrb / 4 strb pattern (HandlePong).

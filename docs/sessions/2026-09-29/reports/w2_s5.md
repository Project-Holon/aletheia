New idioms worth noting:
- gsiLargeIntSub/Add: `u64 borrow/carry` declared first, `u32 i` declared without initializer, `i = 0` as a separate statement (Sub: after the min-length computation; Add: `i = 0; carry = 0;` before the first call), and the first loop written `for (; i < n; i++)`. This fixes the register colouring (i in r6, 64-bit accumulator in r4:r5) and the hoisted `mov r6,#0`. The `rsc r0, r1, #0` with r1 = i in Sub is the compiler reusing the known-zero i, not source.
- B64EncodeStream: encoding table chosen with `switch (mode) { case 1: g_021A1A02; case 2: g_021A19FF; default: g_021A19FC }` (pool order must be 1A02, 19FF, 19FC); data externs declared `char[3]` as in the sibling B64DecodeLen; per-branch `output[i] = ...` stores (no shared store) reproduce the `strble`/`strbeq` shape.
- gsUdpEngineAddMsgHandler: the two 16-byte name copies are `*(GSChar16 *)dst = *(GSChar16 *)src` with `typedef struct { char c[16]; } GSChar16;` (byte-pair unrolled loop of 8, no loop variable). Keep in mind this is a spelling for the codegen; the DWARF shows no local `i`.
- gsXmlReadChildAsDateTimeElement: struct tm as nine ints; the scanf argument order is year, mon, mday, hour, min, sec; year -= 1900, mon -= 1, isdst = -1, then gsiDateToSeconds.

Callee naming: ARM9 callees carry no region token; same-overlay callees carry `ov009`. Callees in the gsxml functions keep the ArrayLength/ArrayNth/gsiXmlUtilTagMatches spellings used by the matched siblings (02183A24 et al.).

## Near misses

- 0x02180A64 and 0x02180C94 share one residue: an 8-byte register swap in the 16-byte header copy into the stack GSUdpMsgHandler. The object keeps the destination in r4 and the source copy in r3. Every spelling I tried under 1.1p1 does the reverse. This happens only where the source pointer is still live after the copy (or is a stack parameter). In SendMessage and StartTalkingToPeer the same GSUdpHdr struct assignment is exact. What was tried is in each file header, including the permuter (a64: 2,000 anneal; c94: 400 anneal plus 2,000 random), and all of it stayed flat at 8 bytes.
- 0x0217D904 gsiLargeIntDiv: the earlier draft declared `len` as int, but the DWARF says unsigned int, so I rewrote it from the object. It went from 676 to 489 differing bytes (size 936 vs 928). What blocks it is stack order against init order. The object has scopy at sp+0x10, zeroed right after TimerEnter, and quotient at sp+0x210, zeroed after the memcpy. Under 1.1p1 the later-declared or inner-block aggregate always sits lower, so both cannot hold together. The permuter (1,500) stayed flat. The header has the details.

## Notes

- gsiSecondsToDate needed one extra local, `long alldays = *timp / 86400L`, computed before the tm_mon store. The permuter found it. There is no DWARF local for it, and the header says so.
- gsiDateToSeconds has a block-scoped `tbtemp` pointer that is not in the DWARF local list. Each error path uses its own `return -1` (a shared goto label gives a different layout).
- References to open SDK rows (0x02198620 gt2AddressToString, 0x02195AB4, 0x02195B44, 0x02180924, 0x02180A64, 0x02180C94) resolve as `sdk` evidence through their catalog rows.
- No name disagreements, no asm bodies, no new idioms.

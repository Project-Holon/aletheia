## Levers found

- Inline helper with parameters (DWCi_GXlSetWndPosition): four identical leaf arms with the loads before the
  wnd branch only appear when the body is a `static inline SetWin(u16 *reg, u16 x1, u16 y1, u16 x2, u16 y2)`
  called with `r->x1, r->y1, r->x2, r->y2` in each of the four arms. Macros or hand-loaded locals give the
  wrong load placement and registers. Body: `reg[0] = (u16)(((x1 << 8) & 0xff00) | (x2 & 0xff))`.
- Tail-merged call arms (taskFade): a ternary or `u32 addr = cond ? A : B` predicates (ldreq/ldrne); the
  branchy `bne; ldr; b; ldr; bl` shape needs `if (c) call(A, v); else call(B, v);` with the call in both
  arms (the compiler merges the common tail).
- Same for register-block ops (DWCi_FNTlFormBgEx): a full `*(vu16 *)A &= ...; *(vu16 *)A = ...` sequence in
  each arm of the `lcd == 1` if/else reproduces the shared-tail layout; a `vu16 *reg` select predicates.
- Int temporary for read-modify-write (GXlSetWndPlane): `int v = (*(vu16 *)a & ~0x3f) | plane;` then
  `if (effect) v |= 0x20; *(vu16 *)a = v;`; a `u16 v` adds lsl/lsr narrowing pairs.
- Switch arm order (Wait...Child): the arms must be written in image block order (case 1 text before
  case 0) to get the duplicated `state = 0x1f` blocks in the image order.
- Struct copy `work->pi = pi` is an ldrh/strh pair loop when the struct has alignment 2 (AOSSlInit); sizes
  must be exact (0x104; my first draft was 4 short and only the frame size differed).
- isCorrect: declaration order VAL, c, prm, i, j, buf, b (reverse of the sdkobj listing) fixed the stack
  slots (buf +0, prm +4, VAL +8); `u8 *c` avoids ldrsb; the `b != 0` arm must be written first in the
  bit loop to get the out-of-line `b == 0` arm.
- MBP_Init: the constant 0x02FFFC80 (owner info) is one `u8 *own`, used as `own[0x1a]` and `own + 6`
  (a single literal load); `MBUserInfo` bitfields `favoriteColor:4, playerNo:4` reproduce the two
  read-modify-write byte stores; the zeroed 14-byte header is `Hdr h = {0}; wb->hdr = h;`.
- ISA of a callee matters in the symbols block: AOSSi_InitLocal at 0x021B84E4 is thumb (blx from the ARM
  caller); declaring it arm gives "ISA conflict".

### 0x021D657C readKey (272 B), about 13 attempts

Best draft: src/pending/ov_sdk/ov016_func_021D657C.c. Instruction sequence, immediates and expression shapes

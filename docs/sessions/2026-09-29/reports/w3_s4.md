## Near misses and residue

- SetupListChallenge 0x0219FE44 (236 B, 4 B differ): the last two eors of the oddmode update have swapped operands (original `eor r0,r0,r2; eor r8,r0,r1`, mine `eor r0,r2,r0; eor r8,r1,r0`). Everything else is identical. About 400 term orders and nestings tried (five terms: c0&1, oddmode, (i^prev)&1, prev<c0, c0<79; left chains, right chains, compound `^=` sequences). Best committed form is D ^ (E ^ (A ^ (B ^ C))). Locals must be declared i then oddmode.
- ProcessIncomingData 0x021A153C (228 B, 104 B differ): the original keeps a real `beq` on state==2 around the decrypt and reloads inlen after the store; the compiler if-converts my version (ldrne/cmpne) and keeps the sum in a register. Right parts: oldlen local, `err = 0` carried live (`mov r4,#0` doubles as the recv flags arg), `if (state == 3) err = ProcessMainListData(); if (err) return err;`.
- ProcessDeleteServer 0x021A1254 (136 B, 21 B differ): register naming only. Original holds &port in ip and &ip in r7 and loads buf[4], buf[5] first into r3/r2; mine puts the pointer temps in r7/r6. Byte copies through block-scope pointers are closest; struct copies, static inline copy, declaration swaps did not help.
- SBSendNatNegotiateCookieToServer 0x021A174C (184 B, 112 B differ): swap-temporary allocation. Original keeps cookie in r5 and loads the six constants into r7/r6/r5/r4/lr/fp after the swap has started; mine has cookie in r4. Store orders, pointer-increment stores and an array initializer (becomes a ldr/str copy loop) tried.

## Notes

- BufferAddIntLE: the two byte swaps are different source shapes: SWAP32 as `((x>>24)&0xff)|((x>>8)&0xff00)|((x<<8)&0xff0000)|((x<<24)&0xff000000)`, then the second built by `ivalBE = 0; ivalBE |= x<<24; ivalBE |= (x&0xff00)<<8; ivalBE |= (x&0xff0000)>>8; ivalBE |= (x&0xff000000)>>24`.
- DWCi_GPProcess: OS_TicksToMilliseconds inlined as `(tick - last) * 64 / 33514` (u64 division through `_ll_udiv`, listed in the symbols block as emitted). g_021AA860 is a root struct whose +0xC member points to the DWC work struct (used by DWCi_CallBuddyFriendCallback too); the catalog name s_bNeedCloseStatsConnection is a misnomer for that address.
- 0x0219FAAC ErrorDisconnect uses g_021A821C (QUERY_ERROR, a char pointer) and g_021AEB00 (SBNullServer, a pointer); 0x0219F288/F40C/F48C use g_021AEB04 as a struct whose +4 member is the current server list. Catalog names for these data symbols (SBOverrideMasterServer at 0x021AEB04) disagree with the code, which dereferences +4 from that address.
- 0x021A1254 ProcessDeleteServer and 0x021A12DC ProcessPushServer: DWARF says SBAllocServer takes (ip, port) but the object passes slist in r0 (three arguments); declared with three.
- 0x0219F48C calls strcasecmp at 0x0209ABF8, which the catalog tags game/unknown; the shard still verified EXACT.

## Key finding: clz IS reachable
The SDK's `MATH_CountLeadingZerosInline` is `static inline u32 f(u32 x){ asm { clz x, x } return x; }`. Both front ends inline and **predicate** it (`cmp #8 / movge #3 / movlt / clzlt / rsblt #0x1f`). Write the `>= 8 ? 3 : ilog` arm first. This retires the "clz unreachable" wall in docs/notes/pkt_02068FF0.c.txt, so **func_02068FF0 (not this lane's) should now be re-attempted**. The same wall covered func_020681E4 and func_020691E0.

Permuter trick: the permuter can't parse asm, but it keeps `#` lines verbatim. Put the helper in a header and `#include "Z:\\...\\clzinc.h"` (a wine path). That made the AST permuter usable on both clz functions.

## DIFF details
- **0x020681E4**: the shift pair is a by-value `struct {int w; int h;}`, copied to locals and written back as `sw = (s.w = p[0])`. That is the only reading that reproduces the stores to the incoming stack slots and the loop target. Also needed: the inverse h-mask as a local in the `hh > y` arm, and the pair address as `tbl + (log2w<<1) + (log2h<<3)`. The residue is the entry load order plus register naming. Permuter best: `DIFF asm=95 bytes-out=18 size=248/248` (hill: no single mutation improves).
- **0x020691E0**: every instruction is in place; only numX and charPerOBJ swap sb/r8. Tried all 360 declaration orders, invariant inlining, loop-var scope and 2000 anneal steps. Permuter best: `DIFF asm=25 bytes-out=5 size=760/760`, `temp(tmp=x + (alignedW << 3))`.
